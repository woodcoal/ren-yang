# 数据模型与迁移策略

## 数据原则

- SQLite 是唯一业务事实源。
- OpenViking 是可重建的异步 Resource、Session、派生与语义检索处理器。
- FTS5 持续维护有效资料、成长和记忆索引，不是故障后临时创建的备用能力。
- 已发布灵魂版本、成长/记忆修订、分析批次输入、运行快照、反馈事件和块尝试只追加，不覆盖；用户明确删除人物反馈资料时，允许受审计地清除关联分析输入正文。
- 图片资产和导入原文件保存在本地数据目录，数据库只保存元数据和相对路径。
- 所有写入使用参数化查询和明确事务；外部网络调用不得持有数据库事务。

## 通用列约定

| 约定 | 说明 |
|---|---|
| 主键 | `TEXT` UUID，由应用生成 |
| 时间 | UTC Unix 毫秒 `INTEGER` |
| 布尔 | `INTEGER`，限定为 0/1 |
| 枚举 | `TEXT` 加共享 Schema 与数据库 `CHECK` |
| 结构化快照 | JSON 文本，写入前通过 Zod 校验 |
| 文件路径 | 相对数据目录的 POSIX 风格路径 |
| 哈希 | SHA-256 小写十六进制文本 |

查询频繁的状态、外键、时间和类型使用独立列，不把可查询业务字段全部塞入 JSON。

## 核心表

### 管理员与审计

| 表 | 关键字段 | 约束 |
|---|---|---|
| `administrators` | `id`、`username`、`password_hash`、`credential_version`、时间列 | 固定主键保证单管理员；用户名唯一 |
| `audit_events` | `actor`、`action`、`target_type`、`target_id?`、`details_json`、`created_at` | 关键动作只追加 |
| `api_keys` | 名称、前缀、SHA-256 摘要、权限 JSON、到期/最近使用/吊销/创建时间 | 摘要唯一；永不保存完整明文 |
| `public_api_idempotency_records` | Key、方法、路径、幂等键、请求摘要、首次成功响应、时间 | `(api_key_id, method, path, idempotency_key)` 唯一；成功结果永久保留 |
| `public_api_audit_events` | Key、请求 ID、方法、路径、目标、结果、状态码、错误码、时间 | 不保存认证头、请求正文或响应正文 |

公共审计在管理员审计页与 `audit_events` 形成统一只读投影，但两类记录保持独立表和写入规则。吊销 Key 不删除历史幂等结果或审计。

### 模拟对象

| 表 | 关键字段 | 约束 |
|---|---|---|
| `worlds` | `id`、`name`、`summary`、`active_soul_version_id?`、`is_enabled`、时间列 | `summary` 只用于后台辨认；禁用不删除关系或版本 |
| `personas` | `id`、`world_id`、`name`、`origin`、`active_soul_version_id?`、`is_enabled`、时间列 | 一个具体人物只属于一个世界范围；`origin` 仅为历史兼容列，新人物固定写入 `original`；禁用不删除心智或历史 |

世界与人物保留独立聚合根，不建立代码或数据库继承。人物来源模式已经退出公开输入、业务判断和界面展示，SQLite `origin` 列暂不执行破坏性迁移。没有显式业务世界的人物由应用创建隐藏独立世界范围，以满足 OpenViking User/Peer 隔离；界面不把隐藏范围显示成用户世界。

`personas.is_enabled` 控制人物能否创建后续新任务；禁用人物保留灵魂、成长、记忆、资料关系和历史运行。`worlds.is_enabled` 控制世界能否进入后续新任务；禁用世界后，已关联人物仍能按人物自身内容工作，但新任务不再带入该世界灵魂、成长和世界资料。两类状态都不追溯修改历史任务快照。

### 灵魂

| 表 | 关键字段 | 约束 |
|---|---|---|
| `soul_drafts` | 对象类型与对象外键、`base_version_id?`、`prompt_text`、变化摘要、时间列 | 每个对象最多一个主草稿；世界/人物外键恰好一个非空 |
| `soul_versions` | 对象类型与对象外键、`parent_version_id?`、`prompt_text`、Token 计数、状态、发布时间 | 发布后不可变；对象外键恰好一个非空 |

灵魂状态使用 `published`、`archived` 和 `rejected`。草稿不是不可变版本，单独保存在 `soul_drafts`。`prompt_text` 是管理、比较和运行共用的唯一灵魂内容；手动保存只去除首尾空白，AI 整理结果也只能先保存为草稿。发布事务插入版本、更新对象当前指针、删除草稿并写审计。

### 资料与成长原始数据

| 表 | 关键字段 | 约束 |
|---|---|---|
| `source_materials` | 名称、角色、输入类型、正文、哈希、原文件路径、可选来源地址/作者/时间/原始来源键、全局启用状态、时间列 | 输入为粘贴/TXT/Markdown；禁用不删除正文、切片或关系 |
| `source_chunks` | `source_id`、序号、标题、正文、哈希 | `(source_id, ordinal)` 唯一 |
| `persona_sources` | `persona_id`、`source_id`、优先级 | 人物任务参考资料关联 |
| `world_sources` | `world_id`、`source_id`、优先级、启用状态、时间列 | 世界资料及世界成长来源 |
| `persona_feedback_sources` | `persona_id`、标题、正文、来源、启用和删除状态、哈希、时间列 | 只用于人物成长分析 |

反馈事件和人物反馈资料分开保存。用户明确选择“作为人物学习资料”时才创建 `persona_feedback_sources`。

`source_materials.is_enabled` 是普通资料的全局状态。禁用后资料仍是 SQLite 业务事实，但不进入 FTS5 检索、人物任务上下文或 OpenViking 投影；重新启用后可从本地事实恢复投影。该字段不得与 `world_sources.is_enabled` 混淆：后者只控制某项资料是否参与指定世界的成长分析，不改变资料在其他人物或世界中的可用性。

### 成长

| 表 | 关键字段 | 约束 |
|---|---|---|
| `growth_records` | 对象类型与对象外键、当前修订、状态、取代关系、时间列 | 世界/人物外键恰好一个非空 |
| `growth_revisions` | `growth_id`、修订号、正文、范围、重要程度、冲突、分析批次、时间列 | `(growth_id, revision_no)` 唯一；不可变 |
| `growth_revision_evidence` | 修订、来源类型/标识/哈希/标题、支持或反对、来源可用状态 | 保留来源链 |

成长状态为 `candidate`、`active`、`superseded`、`archived`、`rejected`。只有当前 `active` 修订进入运行检索。

### 人物处理记录与记忆

| 表 | 关键字段 | 约束 |
|---|---|---|
| `persona_operation_records` | 人物、运行、操作类型、结果摘要、判断数据、启用状态、心智快照、Session 映射、时间列 | 每项运行按操作类型幂等创建 |
| `memory_records` | 人物、当前修订、类型、状态、取代关系、OpenViking 派生标识、时间列 | 只属于人物 |
| `memory_revisions` | 记忆、修订号、正文、范围、重要程度、发生时间、独立证据数、冲突和批次 | `(memory_id, revision_no)` 唯一；不可变 |
| `memory_revision_evidence` | 修订、处理记录、运行、关系和哈希 | 同一运行只计一个独立来源 |

记忆状态与成长一致。世界没有对应的处理记录或记忆表关系。

### 分析批次与提案

| 表 | 关键字段 | 约束 |
|---|---|---|
| `analysis_batches` | 类型、对象、增量/重建模式、基线、模型/参数/提示、原始结果、状态和错误 | 每次分析独立保存 |
| `analysis_batch_inputs` | 批次、来源类型/标识、内容哈希、必要快照、新增标记、可用状态 | 输入不可覆盖 |
| `iteration_proposals` | 批次、操作、目标、变更前、建议、用户修订、冲突、状态 | 接受后幂等应用 |

分析批次类型为 `world_growth`、`persona_growth`、`persona_memory`。提案操作为 `add`、`revise`、`merge`、`supersede`、`archive`、`no_change`。

### 人物蒸馏

| 表 | 关键字段 | 约束 |
|---|---|---|
| `persona_distillation_runs` | 重试来源、状态、创建要求、世界、提供器、算法/覆盖/提取/门禁快照、候选正文与评测哈希、人物结果和时间列 | 创建人物前独立存在；完成时必须关联人物；取消和失败保留历史 |
| `persona_distillation_inputs` | 运行、输入类型、可选资料、资料角色/来源关系/覆盖维度、独立来源键、正文与哈希、可用和确认状态 | 用户要求与资料分开；资料删除时清除历史正文并保留哈希和标题 |
| `persona_distillation_claims` | 分类、陈述、适用条件、局限、依据类型、置信度、独立来源数、跨场景数、状态与警告 | 只保存程序校验结果 |
| `persona_distillation_evidence` | 候选、输入、支持/反对关系、引文和哈希 | 候选与输入必须属于同一运行；同一引用唯一 |
| `persona_distillation_evaluations` | 运行、轮次、评测类型、候选哈希、输入/期望/输出、状态、评分与失败原因 | `(run_id, round_no, evaluation_type)` 唯一；只追加 |

人物蒸馏任务使用 `task_jobs.type=distill_persona`，业务运行标识保存在受数据库触发器校验的任务载荷中。候选编辑后清空 `evaluated_prompt_hash` 并创建新评测任务；最终确认必须在同一事务内创建人物、初始当前灵魂版本、资料关系并完成蒸馏运行。

### 检索与 OpenViking 投影

FTS5 索引：

- `source_chunks_fts`：资料切片；
- `subject_learning_fts`：只包含当前 `active` 世界成长、人物成长和人物记忆修订。

投影状态：

| 表 | 关键字段 | 约束 |
|---|---|---|
| `context_sync_records` | 实体类型/标识、范围、User、Peer、URI、目标哈希、操作、状态、错误、时间列 | `(entity_type, source_id, scope_type, scope_id, provider)` 唯一 |
| `openviking_session_records` | 本地来源、人物、User、Peer、远端 Session、状态、错误、时间列 | `(source_type, source_id)` 唯一 |
| `openviking_sync_outbox` | 未送达意图类型、最小载荷、租约、尝试次数、可用时间 | 只容许排队/运行；成功或终止后删除，不保存历史 |

待删除投影在远端清理成功前保留。关闭 OpenViking 不删除同步状态或远端资源；重新启用后从 SQLite 补偿。

普通资料被全局禁用时保存删除投影意图；删除成功前保留投影对应状态以支持重试。重新启用时保存恢复投影意图，正文、切片和人物/世界关系均直接取自 SQLite，不依赖远端残留数据。

### 历史模板与参数

| 表 | 关键字段 | 约束 |
|---|---|---|
| `format_templates` | 名称、版本、规格、是否有效、时间列 | `(name, version)` 唯一 |
| `parameter_profiles` | 名称、版本、作用域、参数 JSON、是否有效、时间列 | `(name, version)` 唯一 |

两张表只保留迁移前运行兼容读取和历史数据，不再提供后台入口或新增接口。新运行由代码固定安全预算，并把对应算法步骤参数与最终完整参数保存到运行快照，不依赖模板或参数方案。

### AI 接口、模型部署与算法配置

| 表 | 关键字段 | 约束 |
|---|---|---|
| `ai_connections` | 名称、协议、端点、API Key 密文、启用状态、时间列 | 名称唯一；当前协议固定为 OpenAI-compatible；只保存 AES-256-GCM 密文 |
| `ai_model_deployments` | 连接、管理名称、供应商模型标识、文本/图片类型、关闭思考请求格式、启用状态、时间列 | 名称唯一；一个连接可登记多个模型；图片部署格式固定为无 |
| `ai_algorithms` | 固定编码、名称、代码实现版本、当前配置版本指针、时间列 | 只允许代码已知的十四个算法 |
| `ai_algorithm_configuration_versions` | 算法、版本号、创建时间 | `(algorithm_code, version_no)` 唯一；只追加 |
| `ai_algorithm_step_configurations` | 配置版本、固定步骤、顺序、可空模型部署、提示词、参数 JSON | 同一配置内步骤和顺序唯一；模型为空表示使用同类型默认部署，非空模型与提示词使用限制删除外键 |
| `system_ai_settings` | 默认文本部署、默认图片部署、更新时间 | 单例；只保存两个后备模型选择，不保存算法参数 |

接口连接与模型部署分离，支持同一算法的不同步骤组合多个服务端点和模型。算法步骤、模型类型、顺序、输入预处理及输出 Schema 固定在代码中；数据库不能创建任意步骤，只能发布模型部署与调用参数的完整新版本。步骤模型为空时，新任务从 `system_ai_settings` 解析同类型默认部署并把实际部署写入运行快照；显式部署始终优先，历史快照不随默认设置变化。文本步骤使用温度、最大输出 Token、超时和关闭思考开关；开关启用时仅按模型部署声明的 `enable_thinking:false`、`reasoning_effort:"none"` 或 `reasoning:{ enabled:false }` 格式发送一个关闭字段，未声明格式的模型拒绝执行。最大输出 Token 不设本地上限，也不改变固定提示词预算；值为 `0` 时不发送该字段，由供应商决定默认长度。图片步骤使用最大宽度、最大高度和超时。图片任一维超过上限时居中裁剪，未超过时不重新编码；裁剪发生时同一资产记录保存裁剪结果与原图元数据。

十四个固定编码为 `persona_soul`、`world_soul`、`persona_growth`、`world_growth`、`persona_memory`、`persona_draft`、`world_draft`、`feedback_classification`、`persona_avatar`、`interest_assessment`、`article_generation`、`article_image_analysis`、`article_text_revision`、`article_image_generation`。新 AI 操作只从对应算法准备模型、提示词和参数；迁移前运行仍可读取旧设置行和旧模型快照继续执行。

`analysis_batches.algorithm_snapshot_json` 保存成长任务创建时的算法实现版本、配置版本、连接与模型部署、提示词版本和参数，不包含 API Key。迁移前批次与人物记忆批次允许为空。旧的模型、参数和提示字段继续保留，供历史页面和人物记忆单模型链路读取。

## 事务边界

以下操作必须原子完成：

- 发布灵魂版本并切换当前指针、删除草稿、写审计。
- 创建成长或记忆新修订并切换当前修订。
- 批量启用或禁用同一对象的原始记录。
- 创建分析批次、输入快照和任务。
- 创建人物蒸馏运行、输入快照和首个任务。
- 确认蒸馏候选并创建人物、初始当前灵魂版本、资料关系和完成状态。
- 审核提案并幂等应用成长或记忆变化。
- 创建运行、上下文预算快照和任务。
- 写入块尝试并切换当前选中尝试。
- 创建或吊销 API Key 并写管理员审计；永久删除已吊销 Key 时同步删除其公共调用审计与幂等记录，并保留管理员删除审计。

模型和 OpenViking 调用前保存输入事实，调用后使用短事务写结果。

## SQLite 运行设置

启动时设置并验证：

```text
PRAGMA foreign_keys = ON
PRAGMA journal_mode = WAL
PRAGMA busy_timeout = 5000
```

定期执行 `PRAGMA integrity_check`；只有明确维护操作才执行 `VACUUM`。

## 迁移规则

- 使用 Drizzle Kit 生成并人工审查 SQLite 迁移。
- 当前新安装依次执行 `drizzle/0000_schema.sql` 至 `drizzle/0018_persona_distillation.sql`，建立业务表、FTS5、触发器及内置 AI 配置种子。
- `0006` 扩展十四个固定算法，并把有效的迁移前默认文本、图片部署及草稿、反馈参数迁移到对应算法配置；旧设置行继续保留，只供历史运行兼容读取。
- 已完成 `0006` 的现有数据库不会重复执行迁移；业务数据和历史算法配置保持不变。
- `0007` 为兴趣批次增加附加提示词；`0008` 允许算法步骤模型为空，以便新任务解析同类型默认模型。两项迁移均保留既有数据并校验外键完整性。
- 未到达该最终版本的中间数据库和备份不支持原地升级或恢复，避免在已有表上重放完整基线。
- `0015` 新增 OpenViking 专属 outbox，把旧 `task_jobs` 中的排队或运行中同步项迁入 outbox，并移除全部 OpenViking 旧任务历史。
- `0016` 增加分析发布基线保护与提取校验快照；`0017` 固定提示词变量位置、信任、编码和缓存角色契约。
- `0018` 增加人物蒸馏运行、输入、候选、证据和评测结构，扩展资料来源元数据，并校验蒸馏任务和跨运行证据关系。
- 从当前基线开始，已发布迁移文件不可修改；修正使用新迁移。再次压缩必须确认所有需要保留的数据库都已到达当时最终版本。
- 本轮采用“新增结构 → 回填 → 兼容读取 → 切换新写入 → 独立清理”的顺序。
- 迁移前创建一致性备份；破坏性清理必须在新模型稳定后单独决策。
- 固定八字段、世界单正文和旧成长/记忆的具体映射见文档 15。
- 迁移后校验对象、版本、灵魂文本、成长、记忆、运行引用、内容哈希和外键完整性。
- PostgreSQL 仍是未来独立迁移项目，不建设双写或运行时数据库切换。

## 备份一致性

备份必须包含 SQLite 一致副本、被引用的资料原文件和图片资产，并生成 SHA-256 清单。OpenViking 数据不进入备份；恢复后从 SQLite 当前业务事实重建 Resource、有效成长/记忆投影和待送达同步意图。
