# 数据模型与迁移策略

## 数据原则

- SQLite 是 MVP 唯一业务事实源。
- OpenViking 是可重建的检索索引，不保存唯一业务事实。
- 图片、导出文件和原始文本文件保存到本地数据目录，数据库保存元数据和相对路径。
- 已发布人物版本、运行快照、反馈事件和块尝试只追加，不覆盖。
- 所有写入使用参数化查询和明确事务。

## 通用列约定

| 约定 | 说明 |
|---|---|
| 主键 | `TEXT` UUID，由应用生成 |
| 时间 | UTC Unix 毫秒 `INTEGER` |
| 布尔 | `INTEGER`，限定为 0/1 |
| 枚举 | `TEXT` 加应用 Schema 与数据库 `CHECK` |
| 结构化快照 | JSON 文本，写入前通过 Zod 校验 |
| 文件路径 | 相对数据目录的 POSIX 风格路径 |
| 哈希 | SHA-256 小写十六进制文本 |

查询频繁的状态、外键、时间和类型必须使用独立列，不把可查询业务字段全部塞入 JSON。

## 核心表

### 管理员与设置

| 表 | 关键字段 | 约束 |
|---|---|---|
| `administrators` | `id`、`username`、`password_hash`、`created_at`、`updated_at` | MVP 最多一行；用户名唯一 |
| `system_settings` | `key`、`value_json`、`updated_at` | 不保存模型密钥和会话密钥 |

会话由 nuxt-auth-utils 密封 Cookie 承担，不建立多用户权限表。

### 人物、世界和资料

| 表 | 关键字段 | 约束 |
|---|---|---|
| `worlds` | `id`、`name`、`summary`、时间列 | 名称非空 |
| `personas` | `id`、`world_id?`、`name`、`origin`、`active_version_id?`、时间列 | `world_id` 可空；名称非空 |
| `persona_versions` | `id`、`persona_id`、`parent_version_id?`、`status`、`snapshot_json`、`change_summary`、`published_at?`、时间列 | 创建后快照不可更新 |
| `source_materials` | `id`、`name`、`role`、`input_type`、`content_hash`、`content_text`、时间列 | MVP 输入类型仅 paste/txt/markdown |
| `persona_sources` | `persona_id`、`source_id`、`priority` | 联合主键 |
| `world_sources` | `world_id`、`source_id`、`priority` | 联合主键 |
| `source_chunks` | `id`、`source_id`、`ordinal`、`heading?`、`content`、`content_hash` | `(source_id, ordinal)` 唯一 |

`source_materials` 独立于人物和世界，允许同一资料被复用。删除资料前必须检查所有关联并显示影响范围。

### 检索

建立外部内容 FTS5 虚表 `source_chunks_fts`，索引 `heading` 和 `content`，以 `source_chunks` 为内容表。资料或块变更必须在同一应用事务中同步 FTS 索引。

OpenViking 同步状态保存在：

| 表 | 关键字段 | 约束 |
|---|---|---|
| `context_sync_records` | `id`、`source_id`、`provider`、`remote_uri?`、`content_hash`、`status`、`error?`、时间列 | `(source_id, provider)` 唯一 |

关闭 OpenViking 不删除同步记录或远端资源。

### 模板与参数

| 表 | 关键字段 | 约束 |
|---|---|---|
| `format_templates` | `id`、`name`、`version`、`spec_json`、`is_active`、时间列 | `(name, version)` 唯一 |
| `parameter_profiles` | `id`、`name`、`version`、`scope`、`values_json`、`is_active`、时间列 | `(name, version)` 唯一 |

参数解析顺序为系统默认、人物默认、格式模板、本次运行覆盖。运行只保存最终解析快照，不依赖后续参数方案变化。

### 运行、证据与任务

| 表 | 关键字段 | 约束 |
|---|---|---|
| `generation_runs` | `id`、`kind`、`persona_version_id`、`status`、`scene_json?`、`parameter_snapshot_json`、`model_snapshot_json`、`prompt_version`、`context_provider`、`usage_json?`、时间列 | 创建后的各快照不可替换 |
| `evidence_snapshots` | `id`、`run_id`、`source_id?`、`chunk_id?`、`content`、`content_hash`、`rank?`、`metadata_json` | 内容不可更新 |
| `task_jobs` | `id`、`run_id`、`type`、`status`、`attempt_count`、`max_attempts`、`lease_until?`、`heartbeat_at?`、`cancel_requested_at?`、`last_error?`、时间列 | 一个活动运行最多一个活动主任务 |

`generation_runs.kind` 至少包括 `interest_assessment` 和 `artifact_generation`。

### 图文文档

| 表 | 关键字段 | 约束 |
|---|---|---|
| `document_specs` | `id`、`run_id`、`revision`、`status`、`spec_json`、`confirmed_at?`、时间列 | `(run_id, revision)` 唯一 |
| `artifact_documents` | `id`、`run_id`、`selected_spec_id`、时间列 | 一个运行最多一个当前文档 |
| `artifact_blocks` | `id`、`document_id`、`ordinal`、`type`、`role`、`spec_json`、`status`、`selected_attempt_id?`、`is_locked`、时间列 | `(document_id, ordinal)` 唯一 |
| `block_attempts` | `id`、`block_id`、`attempt_no`、`status`、`input_snapshot_json`、`output_text?`、`file_id?`、`usage_json?`、`error?`、时间列 | `(block_id, attempt_no)` 唯一；不可覆盖 |
| `stored_files` | `id`、`kind`、`relative_path`、`media_type`、`byte_size`、`sha256`、时间列 | `relative_path` 唯一 |

### 反馈、修订与评测

| 表 | 关键字段 | 约束 |
|---|---|---|
| `feedback_events` | `id`、`run_id`、`block_id?`、`target_type`、`rating?`、`content`、`is_long_term`、`edited_output?`、时间列 | 原始内容不可更新 |
| `revision_proposals` | `id`、`persona_id`、`base_version_id`、`risk_level`、`status`、`patch_json`、`reason`、`evidence_json`、时间列 | 发布后不可变 |
| `evaluation_cases` | `id`、`persona_id`、`name`、`category`、`input_json`、`assertions_json`、`is_active`、时间列 | 人物内名称唯一 |
| `evaluation_runs` | `id`、`proposal_id`、`candidate_version_id`、`status`、`summary_json?`、时间列 | 每次执行独立保存 |
| `evaluation_results` | `id`、`evaluation_run_id`、`case_id`、`status`、`score?`、`details_json` | `(evaluation_run_id, case_id)` 唯一 |

## 关键索引

- `persona_versions(persona_id, created_at)`。
- `generation_runs(persona_version_id, created_at)`、`generation_runs(status, created_at)`。
- `task_jobs(status, created_at)`、`task_jobs(lease_until)`。
- `artifact_blocks(document_id, ordinal)`。
- `block_attempts(block_id, attempt_no)`。
- `feedback_events(run_id, created_at)`。
- `revision_proposals(persona_id, status, created_at)`。
- `evaluation_cases(persona_id, is_active)`。

只有查询计划证明必要时增加新索引；不预建推测性索引。

## 事务边界

以下操作必须原子完成：

- 创建人物版本并建立父版本关系。
- 发布版本并切换人物当前版本指针。
- 创建运行、参数快照和任务。
- 领取任务并写入租约。
- 写入块尝试并切换当前选中尝试。
- 创建反馈事件及其修订提案关联。
- 完成评测并更新提案发布判定。

模型和 OpenViking 网络调用不得持有数据库事务。调用前保存输入快照，调用后开启短事务写结果。

## SQLite 运行设置

启动时设置并验证：

```text
PRAGMA foreign_keys = ON
PRAGMA journal_mode = WAL
PRAGMA busy_timeout = 5000
```

定期执行 `PRAGMA integrity_check`；只有明确维护操作才执行 `VACUUM`。

## 迁移规则

- 使用 Drizzle Kit 生成并审查 SQLite 专属迁移。
- 迁移按版本顺序执行，应用启动前完成。
- 已发布迁移文件不可修改；修正使用新迁移。
- 破坏性迁移先备份，再复制数据并校验，最后删除旧结构。
- MVP 不包含 PostgreSQL Schema、驱动或运行时 Provider 开关。

## PostgreSQL 升级条件

出现任一情况时才启动独立迁移项目：

- Web 或 Worker 需要多实例。
- SQLite 持续出现写锁等待。
- 需要多 Worker 使用可靠行锁领取任务。
- 需要多用户、多租户、高可用、远程数据库或集中审计。

升级步骤是停写、SQLite 一致性备份、建立 PostgreSQL Schema、导入、校验行数与哈希、切换连接配置。SQLite 与 PostgreSQL 不长期双写。

## 备份一致性

备份服务必须：

1. 暂停领取新任务并等待写入安全点。
2. 使用 SQLite 在线备份能力生成一致性数据库副本。
3. 按 `stored_files` 清单复制资料与产物。
4. 为数据库和文件生成 SHA-256 清单。
5. 恢复演练时校验数据库完整性、外键和所有文件哈希。

OpenViking 索引不进入备份，恢复后按资料哈希重新同步。
