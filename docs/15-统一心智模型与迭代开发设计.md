# 统一心智模型与迭代开发设计

## 1. 目标与范围

本文把 [12-人物灵魂成长与记忆机制修改需求.md](./12-人物灵魂成长与记忆机制修改需求.md) 转成可实施设计，覆盖：

- 世界与人物的统一灵魂模型；
- 世界成长和人物成长；
- 人物处理记录与记忆；
- 分析批次和增量迭代；
- 提示词 Token 预算；
- SQLite、FTS5 与 OpenViking 协同；
- 旧数据迁移、接口、页面和测试顺序。

本轮不修改数据库技术选型，不引入 PostgreSQL，不建设世界记忆，不允许 OpenViking 成为事实源。

### 1.1 已确认迁移决策

2026-08-30 用户确认采用统一物理表方案，并允许清空现有业务数据后重建：

- 删除 `persona_versions` 和 `world_versions`，统一使用 `soul_drafts`、`soul_versions`；
- `worlds.active_soul_version_id`、`personas.active_soul_version_id` 只指向已发布灵魂；
- 生成运行中的 `persona_version_id` 保留业务字段名，但外键改为人物类型的 `soul_versions`，避免把一次运行错误关联到世界灵魂；
- 旧候选版本和直接移动当前版本指针的回滚接口退出；
- 后续确认取消后台草稿发布步骤，改为“编辑框暂存 → 用户保存 → 创建不可变版本并立即切换当前版本”；
- 恢复历史内容只回填编辑框，用户再次保存后创建以该历史版本为父版本的新版本；
- 迁移清空人物、世界、资料、运行、反馈、评测、同步和审计等业务数据，保留管理员凭据，避免远程管理入口失效。

## 2. 当前实现结论

| 区域 | 已采用实现 | 约束 |
|---|---|---|
| 人物灵魂 | `SoulSnapshot.promptText` 单文本 | 页面编辑状态、不可变保存版本和 Token 预算 |
| 世界灵魂 | 与人物共用 `SoulSnapshot.promptText` | 不再维护章节或第二份运行摘要 |
| 人物成长 | 只有基础表和有效状态检索 | 反馈原始资料、分析批次、修订、来源、冲突和批量审核 |
| 世界成长 | 无 | 从世界资料分析并审核生效 |
| 人物记忆 | Session 派生候选和简单状态 | 处理记录、累计分析、修订、独立证据和完整审核 |
| 提示词 | 固定人物/世界 JSON + 证据 | 按世界与人物心智层级组装并执行 Token 预算 |
| 输入限制 | `maxPromptCharacters` 字符硬限制 | 模型上下文、分类 Token 预算和保守估算 |
| 运行快照 | 人物版本、世界和证据分散保存 | 完整心智、预算、选入和跳过条目快照 |
| 管理界面 | 人物固定字段；世界单正文 | 人物六区、世界六区、原始数据与结论分栏 |

## 3. 架构边界

### 3.1 严格调用链

```text
页面
→ API 控制器
→ 应用服务
→ 领域规则
→ 仓储/模型/Token 计数/上下文端口
→ SQLite、模型或 OpenViking 适配器
```

- 控制器只负责认证、Zod 校验、调用一个应用服务方法和 HTTP 映射。
- 控制器不得访问仓储、Drizzle、模型或 OpenViking。
- Worker 只调用应用服务，不得访问仓储实现或 OpenViking 适配器。
- 应用服务定义事务边界；模型和 OpenViking 网络调用期间不持有 SQLite 事务。
- 领域层只处理单文本规范化、状态、修订、提案、冲突、预算分配和发布规则。

### 3.2 共享规则，不共享聚合根

“世界是特殊人物”是领域行为统一，不表示 `World` 继承 `Persona`。

保留 `worlds` 和 `personas` 两个聚合根，因为：

- 人物通过 `world_id` 明确属于一个世界；
- OpenViking 中世界映射 User，人物映射 Peer；
- 人物拥有处理记录和记忆，世界没有；
- 现有运行、资料和删除规则已经分别引用两者。

灵魂提示词、版本差异、成长修订、分析提案和预算规则使用共享领域函数与共享应用层组件，不复制两套状态机。

## 4. 目标领域模型

```text
World

├── WorldSource 0..N

Persona

```

## 5. 数据模型

### 5.1 灵魂

#### `soul_drafts`（兼容表）

| 字段 | 说明 |
|---|---|
| `id` | 草稿 UUID |
| `subject_type` | `world` 或 `persona` |
| `world_id?` / `persona_id?` | 恰好一个非空 |
| `base_version_id?` | 草稿基于的已发布版本 |
| `prompt_text` | 唯一可编辑灵魂提示词 |
| `change_summary` | 用户可见修改说明 |
| `created_at` / `updated_at` | 时间 |

该表只保留给旧接口兼容，不再是后台灵魂主流程的数据来源。`drizzle/0004_soul_save_immediately.sql` 已把现有草稿提升为当前历史版本并清空该表；新建对象和详情保存不再写入草稿。

#### `soul_versions`

| 字段 | 说明 |
|---|---|
| `id` | 版本 UUID |
| `subject_type` | `world` 或 `persona` |
| `world_id?` / `persona_id?` | 恰好一个非空 |
| `parent_version_id?` | 基础灵魂版本 |
| `prompt_text` | 保存时完整单文本提示词 |
| `runtime_token_count` | 保存时按指定计数器得到的数量 |
| `token_counter` | 计数器和模型标识 |
| `change_summary` | 变化摘要 |
| `status` | `published`、`archived` 或 `rejected` |
| `published_at` / `created_at` | 时间 |

`worlds.active_soul_version_id` 与 `personas.active_soul_version_id` 指向当前使用版本。数据库约束保证 `subject_type` 与两个外键只能匹配一个对象。

共享快照结构：

```json
{
  "promptText": "直接进入新任务的一段纯文本"
}
```

手动保存只执行整段 `trim()`，检查 Token 预算后原子插入不可变版本并切换当前指针。详情页 AI 整理由独立接口完成，只回填编辑框；模型不可用或输出无效时不覆盖用户文本，也不创建版本。模型调用在事务外完成，控制器仍只调用应用服务。

### 5.2 成长原始资料

世界继续使用 `source_materials` 和 `world_sources`；为 `world_sources` 增加：

- `is_enabled`；
- `enabled_at?`；
- `disabled_at?`；
- `updated_at`。

人物新增 `persona_feedback_sources`：

| 字段 | 说明 |
|---|---|
| `id` | 原始条目 UUID |
| `persona_id` | 所属人物 |
| `title` | 展示标题 |
| `content` | 反馈正文或稳定摘要 |
| `source_type` | `run_feedback`、`manual`、`imported`、`memory_conversion` |
| `source_id?` | 原反馈、任务或记忆标识 |
| `is_enabled` | 是否参加后续分析 |
| `content_hash` | 正文哈希 |
| `deletion_state` | `active`、`pending_remote_delete` |
| `created_at` / `updated_at` | 时间 |

远端删除成功后允许物理删除反馈资料。删除时同步清空分析批次输入中引用该资料的完整正文，只保留来源标识、哈希、标题摘要和“来源不可用”状态；历史仍能解释来源关系，但不能恢复用户明确删除的正文。

### 5.3 成长与修订

#### `growth_records`

保存逻辑成长的稳定标识和当前修订指针：

- `subject_type`；
- `world_id?` / `persona_id?`；
- `current_revision_id`；
- `status`：`candidate`、`active`、`superseded`、`archived`、`rejected`；
- `superseded_by_id?`；
- `created_at`、`updated_at`。

#### `growth_revisions`

保存不可变修订：

- `growth_id`、`revision_no`；
- `content`、`content_hash`；
- `scope`；
- `importance`；
- `conflict_summary?`；
- `analysis_batch_id?`；
- `created_by`：`user` 或 `analysis`；
- `created_at`。

#### `growth_revision_evidence`

保存成长修订与世界资料或人物反馈资料的多对多来源：

- `growth_revision_id`；
- `source_type`；
- `source_id`；
- `source_hash`；
- `source_title`；
- `relationship`：`supporting` 或 `opposing`；
- `source_available`。

修改有效成长时先创建新修订，再在同一事务更新当前修订指针和旧成长状态。合并多条成长时创建新成长并把被合并记录标记为 `superseded`。

### 5.4 人物处理记录

新增 `persona_operation_records`：

| 字段 | 说明 |
|---|---|
| `id` | 记录 UUID |
| `persona_id` | 所属人物 |
| `run_id` | 对应运行 |
| `operation_type` | `interest_assessment`、`artifact_generation`、`content_analysis` |
| `result_summary` | 可检索摘要 |
| `decision_json?` | 选择、评分、兴趣结论和任务效果 |
| `is_enabled` | 是否参加记忆分析 |
| `context_snapshot_json` | 当时使用的心智标识和摘要哈希 |
| `session_record_id?` | OpenViking Session 同步记录 |
| `created_at` / `updated_at` | 时间 |

输入和输出全文通过 `generation_runs`、`evidence_snapshots` 和产物表引用，不重复写入。

### 5.5 记忆与修订

`memory_records` 只属于人物，结构与成长相近：

- `persona_id`；
- `current_revision_id`；
- `memory_type`；
- `status`；
- `superseded_by_id?`；
- OpenViking 派生标识；
- 时间。

`memory_revisions` 保存：

- 正文和哈希；
- 适用范围；
- 重要程度；
- 发生时间范围；
- 独立证据数；
- 冲突说明；
- 分析批次；
- 修订号和时间。

`memory_revision_evidence` 保存处理记录来源。相同 `run_id` 的来源只计为一个独立证据。

### 5.6 分析批次和提案

#### `analysis_batches`

| 字段 | 说明 |
|---|---|
| `id` | 批次 UUID |
| `analysis_type` | `world_growth`、`persona_growth`、`persona_memory` |
| `world_id?` / `persona_id?` | 分析对象 |
| `mode` | `incremental` 或 `full_rebuild` |
| `baseline_soul_version_id` | 分析基线 |
| `baseline_json` | 当时有效成长或记忆快照 |
| `model_snapshot_json` | 模型快照 |
| `parameter_snapshot_json` | 参数快照 |
| `prompt_version` | 分析提示版本 |
| `raw_result_json?` | 通过 Schema 的模型原始结果 |
| `status` | `queued`、`running`、`awaiting_review`、`completed`、`failed` |
| 错误和时间字段 | 审计和恢复 |

#### `analysis_batch_inputs`

保存每项输入的类型、标识、哈希、必要内容快照、是否新增输入以及来源可用状态。人物反馈资料删除时允许对关联输入执行受审计的正文清除，这是不可变分析输入的明确例外。

#### `iteration_proposals`

| 字段 | 说明 |
|---|---|
| `analysis_batch_id` | 所属批次 |
| `operation` | `add`、`revise`、`merge`、`supersede`、`archive`、`no_change` |
| `target_type` | `growth` 或 `memory` |
| `target_ids_json` | 被修改或合并的记录 |
| `before_json` | 变更前快照 |
| `proposed_json` | AI 建议内容 |
| `reviewed_json?` | 用户最终修改内容 |
| `conflicts_json` | 冲突列表 |
| `status` | `pending`、`accepted`、`rejected`、`applied` |
| 审核人和时间 | 单用户仍保留审计 |

接受提案和应用变更必须在一个应用服务事务内完成。重复提交通过当前状态和幂等键返回已有结果，不能重复创建成长或记忆。

### 5.7 提示词预算与运行快照

现有 `parameter_profiles.values_json` 增加：

```json
{
  "contextWindowTokens": 32768,
  "reservedOutputTokens": 4096,
  "safetyMarginTokens": 2048,
  "worldBudgetTokens": 5000,
  "worldSoulBudgetTokens": 2500,
  "worldGrowthBudgetTokens": 2500,
  "personaBudgetTokens": 9000,
  "personaSoulBudgetTokens": 3500,
  "personaGrowthBudgetTokens": 2500,
  "personaMemoryBudgetTokens": 3000,
  "sourceBudgetTokens": 5000
}
```

数值只是迁移和测试夹具示例，不作为生产默认值。创建参数方案时校验：

- 预留输出与安全余量小于上下文长度；
- 世界子预算之和不超过世界总预算；
- 人物子预算之和不超过人物总预算；
- 世界、人物、资料与固定内容的预计总量不超过可用输入预算；
- `maxPromptCharacters` 在兼容期继续作为请求体和异常保护，不再代表心智预算。

`generation_runs` 增加 `prompt_context_snapshot_json`，保存：

- 预算配置和 Token 计数器；
- 世界和人物当前灵魂版本及单文本提示词；
- 选入的世界成长、人物成长、人物记忆和资料；
- 每项预计 Token；
- 被跳过条目及原因；
- 最终系统提示和用户提示哈希。

完整提示正文继续按现有安全和审计策略保存，不在普通列表接口返回。

## 6. 状态与事务

### 6.1 灵魂保存即生效

单个事务内：

1. 校验世界或人物存在，且可选基础版本属于该对象；
2. 规范化单文本提示词并检查 Token 预算；
3. 插入新的不可变灵魂版本；
4. 更新世界或人物当前灵魂版本指针和修改时间；
5. 写入 `soul_version_saved` 审计事件。

### 6.2 原始资料批量状态

批量启用或禁用使用一个应用服务调用和一个短事务。返回逐条结果；任一标识不属于当前对象时整批拒绝，避免越权或串台。

人物反馈资料删除分两阶段：

```text
active
→ pending_remote_delete
→ 远端删除成功
→ 清除关联分析输入正文
→ 物理删除正文和业务行
```

OpenViking 未启用或从未同步的条目可以在事务提交后直接清理；已同步条目必须等待远端删除完成。

### 6.3 分析执行

1. 应用服务读取当前启用原始数据和有效基线。
2. 事务创建分析批次、输入快照和持久任务。
3. Worker 通过分析应用服务领取任务。
4. 应用服务调用模型或 OpenViking 端口，不持有事务。
5. 结构化结果通过 Zod 校验；最多一次修复重试。
6. 短事务保存提案并把批次改为 `awaiting_review`。
7. 用户审核后，应用服务原子应用提案。

## 7. 应用服务

目标应用服务职责：

| 应用服务 | 用例 |
|---|---|
| `SoulApplicationService` | 读取当前灵魂和历史、独立整理提示词、保存并立即启用新版本；旧草稿方法仅供兼容接口 |
| `GrowthSourceApplicationService` | 世界资料和人物反馈资料的批量状态、删除和分析准备 |
| `GrowthApplicationService` | 查询成长、手工创建、修订、归档、恢复和批量审核 |
| `OperationRecordApplicationService` | 记录任务行为、批量启用/禁用和查询来源 |
| `MemoryApplicationService` | 查询记忆、修订、归档、恢复、批量审核和转为反馈资料 |
| `AnalysisApplicationService` | 创建增量/完整批次、执行分析、保存提案和应用审核 |
| `PromptContextApplicationService` | 选择有效内容、执行预算、固定运行上下文快照 |
| `ContextSynchronizationApplicationService` | Resource、Session、成长和记忆投影同步、删除补偿和重建 |

可以按现有模块规模合并相邻服务文件，但控制器只能与应用服务交互，应用服务只能通过端口与数据层和外部能力交互。

## 8. 接口设计

### 8.1 灵魂

世界和人物分别暴露清晰业务路径，内部共用服务：

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/soul/analyze` | 独立整理人物或世界灵魂提示词，只返回文本 |
| `GET /api/v1/worlds/{id}/soul` | 世界当前灵魂和全部保存历史 |
| `PUT /api/v1/worlds/{id}/soul` | 保存世界灵魂并立即启用新版本 |
| `GET /api/v1/personas/{id}/soul` | 人物当前灵魂和全部保存历史 |
| `PUT /api/v1/personas/{id}/soul` | 保存人物灵魂并立即启用新版本 |
| 旧 `/soul/draft`、`/soul/publish`、`/soul/draft-from-version` | 兼容旧客户端，不再进入后台主流程 |

### 8.2 原始数据、成长和记忆

| 方法与路径 | 用途 |
|---|---|
| `PATCH /api/v1/worlds/{id}/sources/status` | 批量启用或禁用世界资料 |
| `GET/POST /api/v1/worlds/{id}/growth` | 查询或手工创建世界成长 |
| `PATCH /api/v1/worlds/{id}/growth/status` | 批量确认、归档、恢复或拒绝 |
| `POST /api/v1/worlds/{id}/growth/analyze` | 创建增量或完整分析批次 |
| `GET/POST /api/v1/personas/{id}/feedback-sources` | 查询或创建人物反馈资料 |
| `PATCH /api/v1/personas/{id}/feedback-sources/status` | 批量启用或禁用 |
| `DELETE /api/v1/personas/{id}/feedback-sources` | 批量安全删除 |
| `GET/PATCH /api/v1/personas/{id}/operation-records` | 查询及批量启用/禁用处理记录 |
| `GET /api/v1/personas/{id}/growth` | 查询人物成长 |
| `PATCH /api/v1/personas/{id}/growth/status` | 批量审核和状态变更 |
| `POST /api/v1/personas/{id}/growth/analyze` | 人物成长分析 |
| `GET /api/v1/personas/{id}/memories` | 查询人物记忆 |
| `PATCH /api/v1/personas/{id}/memories/status` | 批量审核和状态变更 |
| `POST /api/v1/personas/{id}/memories/analyze` | 人物记忆分析 |
| `POST /api/v1/personas/{id}/memories/{memoryId}/to-feedback-source` | 转为人物反馈资料 |
| `GET /api/v1/analysis-batches/{id}` | 查看输入、提案和状态 |
| `POST /api/v1/analysis-batches/{id}/review` | 逐条或批量审核提案 |

状态变更统一使用对象标识数组、目标状态和可选原因，不设计一个标识一次请求的重复接口。

## 9. 提示词预算执行

### 9.1 Token 计数端口

新增 `TokenCounterPort`：

```text
count(model, text) → { tokens, mode }
```

`mode` 为 `exact` 或 `estimated`。生产适配器优先使用模型对应分词器；无法识别模型时使用保守估算器并应用安全余量。测试适配器按固定规则计数，保证边界测试可重复。

### 9.2 上下文选择算法

1. 读取世界和人物当前灵魂版本。
2. 计算固定系统规则、任务、场景和两个灵魂提示词占用。
3. 固定 SQLite 当前允许的成长、记忆和资料标识集合。
4. 使用本次选定的 OpenViking 或 FTS5 对允许集合排序。
5. 服务层再次检查对象、状态、内容哈希和删除状态。
6. 按重要程度、相关性和必要的时间因素逐条加入分类预算。
7. 完整记录跳过条目和原因。
8. 计算最终提示；若仍超总预算则按需求顺序收缩。
9. 核心内容仍超限时返回 `PROMPT_BUDGET_EXCEEDED`，不调用模型。
10. 保存运行上下文快照后才创建模型任务。

不同分类记录不得拆成半条加入。相同内容哈希在同一分类中只加入一次。

## 10. OpenViking 投影

| SQLite 业务对象 | OpenViking 范围 | 用途 |
|---|---|---|
| 世界资料 | 世界 User Resource | 世界成长分析和世界证据检索 |
| 人物参考资料 | 人物 Peer Resource | 人物任务证据检索 |
| 人物反馈资料 | 人物 Peer Resource | 人物成长分析 |
| 人物处理过程 | 人物 Peer Session | 记忆派生素材 |
| 有效成长/记忆 | 精确可过滤投影 | 语义排序，不决定有效性 |

投影记录需要从仅支持 `source_id` 扩展为：

- `entity_type`；
- `entity_id`；
- `scope_type`；
- `scope_id`；
- `user_id`、`peer_id?`；
- `remote_uri?`；
- `desired_hash`；
- `status`；
- `operation`：`upsert` 或 `delete`；
- 重试和错误字段。

任何检索都必须由 SQLite 提供允许标识或精确 URI。OpenViking 返回未在允许集合中的内容时丢弃并写诊断记录。

## 11. FTS5

持续维护以下索引：

- 世界资料切片；
- 人物参考资料切片；
- `active` 世界成长当前修订；
- `active` 人物成长当前修订；
- `active` 人物记忆当前修订。

候选、已归档、已取代、已拒绝、待删除和来源原始记录不得作为运行心智内容被召回。分析原始数据使用独立查询，不复用运行检索索引。

## 13. 迁移策略

### 13.1 迁移原则

- 先新增结构和回填，后切换读取，最后在独立迁移中清理旧结构。
- 当前开发期迁移已在全量清空业务数据后压缩为 `drizzle/0000_baseline.sql`；该文件是后续迁移的固定起点。
- 基线发布后不再修改；后续结构变化新增迁移。
- 迁移前自动创建一致性备份。
- 历史运行继续支持旧快照读取，不批量重写不可变运行。
- 回填过程必须幂等或由迁移事务保证只执行一次。

### 13.2 回填映射

单文本迁移由 `drizzle/0003_soul_prompt_text.sql` 完成：

| 旧字段 | 新字段 | 规则 |
|---|---|---|
| `soul_drafts.runtime_summary` | `soul_drafts.prompt_text` | 原文复制，保持草稿标识和基础版本 |
| `soul_versions.runtime_summary` | `soul_versions.prompt_text` | 原文复制，保持版本状态、时间和 Token 计数 |

迁移通过重建两张灵魂表删除 `chapters_json` 和 `runtime_summary`。迁移后必须确认 `prompt_text` 内容一致、旧列不存在且 `PRAGMA foreign_key_check` 为空。世界后台 `summary` 继续只作管理简介，不能自动写入灵魂提示词。

保存即生效迁移由 `drizzle/0004_soul_save_immediately.sql` 完成：现有每条草稿沿用自身 UUID 写入 `soul_versions`，`base_version_id` 保留为父版本，世界或人物当前指针切换到迁移版本，最后清空兼容草稿表。迁移不得覆盖既有历史版本。

### 13.3 兼容期

1. 数据库迁移完成后，读写统一使用 `prompt_text`，不保留双写路径。
2. 运行快照继续兼容已经存在的历史格式；新运行只写 `promptText`。
3. 反馈旧候选和现有成长/记忆迁移后保留原标识映射。
4. 所有现有运行详情继续解析旧人物和世界快照。
5. 自动化迁移验收通过后，才删除旧写路径；旧表清理单独决策。

## 15. 测试设计

### 15.1 领域测试

- 灵魂手动保存只去除首尾空白，单文本差异稳定。
- AI 整理不得增加事实，失败时不得覆盖编辑框或创建版本。
- 已保存版本不可变，历史回溯再次保存时创建新版本。
- 世界不允许创建记忆。
- 成长和记忆所有状态转换及非法转换。
- 修订、合并和取代不覆盖历史。
- 删除或禁用来源不自动改变有效结论。
- 同一运行的重复处理记录只计一个独立证据。
- 记忆转反馈资料和成长吸收灵魂必须显式执行。
- 父子提示词预算、去重、排序、整条跳过和核心超限失败。

### 15.2 应用与数据库测试

- 批量操作拒绝混入其他对象标识。
- 分析批次输入、模型调用和提案保存不持有长事务。
- 重复审核请求不会重复应用提案。
- FTS5 只包含当前 `active` 修订。
- OpenViking 返回范围外、旧哈希或待删除记录时被过滤。
- 远端删除失败后任务可重试，本地来源状态可解释。
- 旧 `runtime_summary` 迁移为 `prompt_text` 无损，历史运行仍能读取。
- 运行上下文快照保存实际选入和跳过记录。

### 15.3 组件与端到端测试

- 列表创建未选择 AI 时不得调用模型，选择 AI 时必须先整理提示词再创建且保留用户名称。
- 人物和世界单文本直接编辑、AI 回填、历史回填、提示词预算和保存即生效。
- 灵魂保存失败保持输入；AI 处理中显示全屏模糊加载层和旋转图标。
- 成长原始资料与成长结果不混淆。
- 处理记录与记忆结果不混淆。
- 批量启用、禁用、删除、审核及影响确认。
- OpenViking 故障时 FTS5 完成新任务，分析入口显示暂停原因。
- 预算不足时界面显示具体分类和处理建议。
- 历史任务仍显示原心智和预算快照。
