# 管理界面与交互

## 设计目标

管理界面采用专业创作工作台形态，以桌面端为主、中等信息密度，支持浅色与深色主题。界面优先保证世界与人物的灵魂、成长、记忆、原始数据、证据来源、提示词预算和待确认变更可见，不以聊天窗口代替完整业务流程。

面向普通使用者的标题、按钮和说明优先使用业务词语：界面显示“基本信息”而不是“元数据”、“修改稿”而不是“候选版本”、“修改记录”而不是“版本时间线”、“任务记录”而不是“运行历史”。Token、OpenViking 等无法替换的技术词必须紧邻说明其用途和影响。接口、数据库和开发文档继续使用精确领域术语，避免为了界面通俗化而改变数据语义。

## 主导航

| 导航 | 主要职责 |
|---|---|
| 仪表盘 | 显示最近人物、进行中任务、待处理反馈和能力状态 |
| 人物 | 创建人物，管理人物灵魂、成长、记忆和资料 |
| 世界与资料 | 管理世界灵魂、世界成长、资料及使用人物 |
| 创作工作台 | 判断兴趣、生成规格、确认块、执行生成和预览 |
| 内容格式与生成设置 | 管理输出结构、长度、随机程度、超时和重试限制 |
| 任务记录 | 查询判断或创作任务、内容块尝试和错误，并进入详情即时导出 |
| 学习中心 | 处理反馈资料、成长/记忆候选、灵魂修改提案和评测 |
| 系统设置 | 查看能力、账户和默认限制，检测提供器、重建索引、创建备份和查看审计 |

全局导航还应显示当前登录状态、后台任务数量和外部能力是否可用。能力不可用时显示具体影响，不只显示红点。

| 路由 | 页面职责 |

| `/` | 仪表盘与最近工作入口 |

| `/personas/[id]` | 人物概览、灵魂、成长、记忆、世界与资料、版本六区工作台 |
| `/worlds` | 世界列表、当前灵魂和成长待办摘要 |
| `/worlds/[id]` | 世界概览、灵魂、成长、世界资料、使用人物、版本六区工作台 |
| `/sources` | 资料列表、导入、处理状态和删除影响 |
| `/sources/[id]` | 原文、系统整理的内容段落，以及人物和世界使用关系 |
| `/workbench` | 新建兴趣判断或图文生成运行 |
| `/runs/[id]` | 规格确认、块执行、重试、锁定、预览、导出、反馈提交和分类确认 |

| `/evaluations/[id]` | 评测进度、用例结果和发布判定 |
| `/history` | 任务记录筛选与详情入口 |

页面只负责组合数据和特性组件。创建、发布、回滚、删除等在线动作必须通过应用接口完成。能力和数据目录由进程环境配置；密码重置与恢复只能在本机通过停机 CLI 执行。

## 核心交互流程

### 管理世界

1. 基本信息明确说明名称和简介只用于后台辨认，不进入提示词。
2. 灵魂页使用自由章节和独立运行摘要；修改保存为草稿，发布后成为不可变版本。
3. 成长页显示从世界资料形成的候选和有效结论，原始资料与分析结果不能混成一个列表。
4. 世界资料页支持查找、新建、加入、启用、禁用、解除和同步状态；解除关联不删除共享资料。
5. 使用人物按名称筛选并在限高区域滚动，人物再多也不拉长整页。
6. 版本页显示灵魂差异和历史引用；回滚根据历史创建新草稿。

### 创建人物

1. 可直接手工编辑，也可输入自然语言并选择原创、资料型或混合型。
2. AI 整理时可选已发布世界灵魂和已导入资料；该动作只返回自由章节和运行摘要建议，不创建或发布人物。
3. 用户检查章节、来源、未知边界和运行摘要 Token 预算。
4. 可继续编辑世界和资料关联；资料型人物至少保留一项资料。
5. 保存灵魂草稿，确认后发布。

发布前必须展示章节差异、来源、冲突和预算。系统不自动发布长期变化。

### 人物成长与记忆

1. 成长页分为“反馈资料”和“成长结果”；反馈资料按条展示，支持批量启用、禁用、删除和分析。
2. 记忆页分为“处理记录”和“记忆结果”；处理记录按条展示，支持批量启用、禁用和分析。
3. 候选结果显示新增、修订、合并、取代或停用影响，支持逐条和批量审核。
4. 成长与记忆都显示来源、适用范围、冲突和修订历史。
5. 记忆转成长必须先执行“转为反馈资料”；成长进入灵魂必须执行“吸收到灵魂”。

### 图文创作

1. 选择人物、任务类型、内容要求、格式模板和参数方案。
2. 可选填写临时场景上下文，并预览世界、人物和提示词分类预算。
3. 先固定实际选入与跳过的上下文，再生成 `DocumentSpec` 并在结构编辑器中确认。
4. 使用上移、下移按钮调整块顺序；MVP 不实现拖放。
5. 执行后按块显示状态、尝试记录、锁定和重试操作。
6. 预览统一产物，并导出 HTML、Markdown 或 Txt。

图片模型未配置时，图片块入口必须禁用，并明确告知文本生成仍可使用。

### 反馈迭代

1. 从运行详情选择具体产物、块或人物提交反馈。
2. 显示系统分类：当前产物、参数、人物学习、灵魂修改或资料事实。
3. 人物学习只有在用户确认后才转为人物反馈资料。
4. 灵魂修改展示章节差异、依据、风险和评测状态，接受后只进入草稿。
5. 所有成长、记忆和灵魂变化由用户确认；历史修订和版本不覆盖。

## 数据获取与状态

- 页面读取使用 Nuxt `useFetch` 或 `useAsyncData`，写操作使用明确的服务端接口调用。
- MVP 不引入 Pinia；跨页面事实由服务端和 URL 标识维护，局部编辑状态留在页面或组合式函数。
- 只实现当前页面实际需要的筛选；运行历史把人物、类型和状态筛选写入查询参数，刷新后可恢复。MVP 不承诺所有列表都支持分页和排序。
- 运行详情在任务未终止时进行有限频率轮询；离开页面时停止轮询。
- 提交动作使用页面提交锁，避免重复创建运行或重复提交关键动作。
- 接口错误统一映射为可操作消息，同时保留稳定错误码供诊断。

## 表单

- 使用 Nuxt UI 表单组件和共享 Zod Schema。
- 客户端校验只用于及时反馈；服务端必须重复校验。
- 必填项、格式错误和业务冲突分别呈现，不用一条通用错误覆盖。
- 删除、发布、归档、恢复、批量审核和基于历史创建草稿使用明确确认区，展示对象与影响范围。
- 长文本编辑器保留未提交草稿至当前页面会话；MVP 不实现跨设备草稿同步。

## 响应式范围

| 设备 | 支持范围 |
|---|---|
| 桌面 | 完整创建、编辑、比较、生成、评测和系统管理 |
| 平板 | 完整主流程；复杂差异和规格编辑可以改为纵向布局 |
| 移动端 | 查看人物、运行状态、预览结果和处理简单确认 |

移动端不承诺完成复杂规格编辑、版本对比、资料管理或恢复操作。窄屏不隐藏关键风险信息，只调整布局或引导到桌面端。

## 可访问性与状态反馈

- 所有表单控件有可见标签，图标按钮有可访问名称。
- 键盘可以完成导航、提交、取消和块顺序调整。
- 焦点状态清晰；主题颜色满足正文和关键状态的对比要求。
- 任务状态不能仅用颜色区分，必须包含文字和必要图标。
- 异步操作显示进行中、成功、失败和可重试状态。
- 图片预览必须使用替代文本；缺失时阻止最终导出。
- 尊重用户的减少动态效果设置，避免不必要动画。

## 内容安全

- 不可信内容不得直接传给 Vue `v-html`。
- HTML 预览只渲染服务端受控渲染器的结果，并在展示前净化。
- Markdown 先解析为受控节点或净化后的 HTML，不允许脚本、事件属性和危险 URL。
- 文件下载名称、图片路径和外部链接必须使用服务端校验结果。

## 界面验收

- 用户能从人物创建进入生成，再进入反馈资料、成长/记忆审核和灵魂发布，不依赖隐藏入口。
- 用户能明确区分原始资料、成长结果、处理记录和记忆结果。
- 世界工作区不存在记忆入口，人物工作区具备完整三层心智入口。
- 创建任务和运行详情可以解释每类 Token 预算、实际使用和跳过内容。
- 所有后台操作都能查看当前状态和失败原因。
- OpenViking 或图片模型关闭后，相关入口正确降级，其他主流程保持可用。
- 刷新运行详情不会丢失服务端状态或重复提交任务。
- 桌面主流程可用键盘完成；移动端能查看关键结果与风险提示。
