# 管理界面与交互

## 设计目标

管理界面采用专业创作工作台形态，以桌面端为主、中等信息密度，支持浅色与深色主题。界面优先保证人物版本、证据来源、任务状态和待确认变更可见，不以聊天窗口代替完整业务流程。

## 主导航

| 导航 | 主要职责 |
|---|---|
| 仪表盘 | 显示最近人物、进行中任务、待处理反馈和能力状态 |
| 人物 | 创建人物、编辑候选版本、比较版本、发布与回滚 |
| 世界与资料 | 管理共享世界设定、资料及其处理状态 |
| 创作工作台 | 判断兴趣、生成规格、确认块、执行生成和预览 |
| 模板与参数 | 管理格式模板、模型参数方案及其版本 |
| 运行历史 | 查询运行、任务、块尝试、错误和导出记录 |
| 反馈与版本 | 提交反馈、审查修订提案、运行评测和发布版本 |
| 系统设置 | 配置能力、数据目录、备份恢复和账户安全 |

全局导航还应显示当前登录状态、后台任务数量和外部能力是否可用。能力不可用时显示具体影响，不只显示红点。

## 路由与页面职责

| 路由 | 页面职责 |
|---|---|
| `/login` | 登录；首次启动时进入管理员初始化 |
| `/` | 仪表盘与最近工作入口 |
| `/personas` | 人物列表、来源模式和当前版本摘要 |
| `/personas/new` | 创建原创、资料型或混合型人物 |
| `/personas/[id]` | 人物概览、当前版本、关联世界和资料 |
| `/personas/[id]/versions` | 版本时间线、差异、发布和回滚 |
| `/worlds` | 世界设定列表和版本状态 |
| `/worlds/[id]` | 世界设定内容、人物关联和版本历史 |
| `/sources` | 资料列表、导入、处理状态和删除影响 |
| `/sources/[id]` | 原文、切片、证据引用和处理错误 |
| `/workbench` | 新建兴趣判断或图文生成运行 |
| `/runs/[id]` | 规格确认、块执行、重试、锁定、预览和导出 |
| `/templates` | 格式模板及版本管理 |
| `/parameter-profiles` | 模型参数方案及版本管理 |
| `/feedback` | 反馈队列、分类结果、提案和候选记忆 |
| `/evaluations/[id]` | 评测进度、用例结果和发布判定 |
| `/history` | 运行历史筛选与详情入口 |
| `/settings` | 能力、存储、备份、账户和运行限制 |

页面只负责组合数据和特性组件。创建、发布、回滚、删除、恢复等动作必须通过应用接口完成。

## 核心交互流程

### 创建人物

1. 选择原创、资料型或混合型。
2. 填写名称、描述、初始设定；资料不是必填项。
3. 可选关联世界设定和已导入资料。
4. 预览证据与推断标记。
5. 保存为候选版本，确认后发布。

发布前必须展示变化摘要。事实没有证据、资料冲突或包含高风险字段时，阻止自动发布并指出原因。

### 图文创作

1. 选择人物、任务类型、内容要求、格式模板和参数方案。
2. 可选填写临时场景上下文。
3. 先生成 `DocumentSpec`，在结构编辑器中确认。
4. 使用上移、下移按钮调整块顺序；MVP 不实现拖放。
5. 执行后按块显示状态、尝试记录、锁定和重试操作。
6. 预览统一产物，并导出 HTML、Markdown 或 Txt。

图片模型未配置时，图片块入口必须禁用，并明确告知文本生成仍可使用。

### 反馈迭代

1. 从运行详情选择具体产物、块或人物提交反馈。
2. 显示系统分类：当前产物、参数、长期人物或资料事实。
3. 对长期变更展示字段级差异、依据、风险和评测状态。
4. 低风险变更评测通过后可按设置自动发布；高风险变更只允许人工确认。
5. 发布或回滚后保留完整版本时间线，不覆盖旧版本。

## 组件边界

| 组件 | 单一职责 |
|---|---|
| `PersonaSummaryCard` | 展示人物摘要和当前版本 |
| `PersonaVersionDiff` | 展示两个不可变版本的字段差异 |
| `EvidenceList` | 展示证据、来源、优先级和快照 |
| `SourceImportForm` | 校验并提交粘贴文本、TXT、Markdown |
| `CapabilityStatus` | 展示文本、图片、OpenViking 的可用性和影响 |
| `DocumentSpecEditor` | 编辑并校验文档规格 |
| `BlockEditor` | 编辑单个块要求和验收条件 |
| `BlockAttemptList` | 展示尝试并选择成功结果 |
| `ArtifactPreview` | 安全预览统一产物文档 |
| `RunStatusPanel` | 展示任务状态、进度、取消和恢复信息 |
| `FeedbackForm` | 收集反馈目标、内容和用户意图 |
| `RevisionProposalReview` | 展示修订提案、风险和发布动作 |
| `EvaluationResultTable` | 展示用例级评测结果 |

父组件通过 Props 传入数据，子组件通过事件表达用户意图。特性组件不能自行访问数据库、文件系统或外部模型，也不能隐式修改父级对象。

## 数据获取与状态

- 页面读取使用 Nuxt `useFetch` 或 `useAsyncData`，写操作使用明确的服务端接口调用。
- MVP 不引入 Pinia；跨页面事实由服务端和 URL 标识维护，局部编辑状态留在页面或组合式函数。
- 列表的筛选、分页和排序写入查询参数，刷新后可恢复。
- 运行详情在任务未终止时进行有限频率轮询；离开页面时停止轮询。
- 提交动作使用幂等键或提交锁，避免重复创建运行、发布版本或恢复备份。
- 接口错误统一映射为可操作消息，同时保留稳定错误码供诊断。

## 表单

- 使用 Nuxt UI 表单组件和共享 Zod Schema。
- 客户端校验只用于及时反馈；服务端必须重复校验。
- 必填项、格式错误和业务冲突分别呈现，不用一条通用错误覆盖。
- 删除、发布、回滚、恢复等关键动作使用确认对话框，并明确对象与影响范围。
- 长文本编辑器保留未提交草稿至当前页面会话；MVP 不实现跨设备草稿同步。

## 响应式范围

| 设备 | 支持范围 |
|---|---|
| 桌面 | 完整创建、编辑、比较、生成、评测和系统管理 |
| 平板 | 完整主流程；复杂差异和规格编辑可以改为纵向布局 |
| 移动端 | 查看人物、运行状态、预览结果和处理简单确认 |

移动端不承诺完成复杂规格编辑、版本对比、资料管理或恢复操作。窄屏不隐藏关键风险信息，只调整布局或引导到桌面端。

## 可访问性与状态反馈

- 所有表单控件有可见标签，图标按钮有可访问名称。
- 键盘可以完成导航、提交、取消和块顺序调整。
- 焦点状态清晰；主题颜色满足正文和关键状态的对比要求。
- 任务状态不能仅用颜色区分，必须包含文字和必要图标。
- 异步操作显示进行中、成功、失败和可重试状态。
- 图片预览必须使用替代文本；缺失时阻止最终导出。
- 尊重用户的减少动态效果设置，避免不必要动画。

## 内容安全

- 不可信内容不得直接传给 Vue `v-html`。
- HTML 预览只渲染服务端受控渲染器的结果，并在展示前净化。
- Markdown 先解析为受控节点或净化后的 HTML，不允许脚本、事件属性和危险 URL。
- 文件下载名称、图片路径和外部链接必须使用服务端校验结果。

## 界面验收

- 用户能从人物创建进入生成，再进入反馈和版本发布，不依赖隐藏入口。
- 所有后台操作都能查看当前状态和失败原因。
- OpenViking 或图片模型关闭后，相关入口正确降级，其他主流程保持可用。
- 刷新运行详情不会丢失服务端状态或重复提交任务。
- 桌面主流程可用键盘完成；移动端能查看关键结果与风险提示。
