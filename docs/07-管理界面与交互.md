# 管理界面与交互

## 设计目标

管理界面采用专业创作工作台形态，以桌面端为主、中等信息密度，支持雾白、暖砂、海盐和松岚四套低饱和浅色主题。界面优先保证世界与人物的灵魂、成长、记忆、原始数据、证据来源、提示词预算和待确认变更可见，不以聊天窗口代替完整业务流程。

面向普通使用者的标题、按钮和说明优先使用业务词语：界面显示“基本信息”而不是“元数据”、“修改稿”而不是“候选版本”、“修改记录”而不是“版本时间线”、“任务记录”而不是“运行历史”。Token、OpenViking 等无法替换的技术词必须紧邻说明其用途和影响。接口、数据库和开发文档继续使用精确领域术语，避免为了界面通俗化而改变数据语义。

## 主导航

| 导航 | 主要职责 |
|---|---|
| 仪表盘 | 显示最近人物、进行中任务、待处理反馈和能力状态 |
| 人物 | 创建人物，管理人物灵魂、成长、记忆和资料 |
| 世界与资料 | 管理世界灵魂、世界成长、资料及使用人物 |
| 创作工作台 | 判断兴趣、生成规格、确认块、执行生成和预览 |
| 内容格式与生成设置 | 管理输出结构、长度、随机程度、超时和重试限制 |
| AI 模型与算法 | 管理加密接口、具体模型部署，以及灵魂和成长固定步骤的模型与参数版本 |
| 任务记录 | 查询判断或创作任务、内容块尝试和错误，并进入详情即时导出 |
| 系统设置 | 查看能力、账户和默认限制，检测提供器、重建索引、创建备份和查看审计 |

全局导航还应显示当前登录状态、后台任务数量和外部能力是否可用。能力不可用时显示具体影响，不只显示红点。

## 路由与页面职责

| 路由 | 页面职责 |
|---|---|
| `/login` | 登录；首次启动时进入管理员初始化 |
| `/` | 仪表盘与最近工作入口 |
| `/personas` | 人物列表、当前灵魂和学习待办摘要 |
| `/personas/new` | 创建人物并按需选择世界与参考资料 |
| `/personas/[id]` | 人物概览、灵魂、成长、记忆、世界与资料、版本六区工作台 |
| `/worlds` | 世界列表、当前灵魂和成长待办摘要 |
| `/worlds/[id]` | 世界概览、灵魂、成长、世界资料、使用人物、版本六区工作台 |
| `/sources` | 资料列表、导入、处理状态和删除影响 |
| `/sources/[id]` | 原文、系统整理的内容段落，以及人物和世界使用关系 |
| `/workbench` | 新建兴趣判断或图文生成运行 |
| `/runs/[id]` | 规格确认、块执行、重试、锁定、预览、导出、反馈提交和分类确认 |
| `/templates` | 格式模板及版本管理 |
| `/parameter-profiles` | 模型参数、提示词父子预算及版本管理 |
| `/ai-models` | 管理多个 AI 接口端点、加密凭据和具体文本/图片模型部署；只显示密钥已配置状态 |
| `/ai-algorithms` | 为四个代码固定算法的每个步骤选择文本模型并发布参数配置版本 |
| `/prompts` | 管理算法和生成链路使用的提示词草稿、发布版本与历史 |
| `/system-ai-settings` | 管理尚未迁移到固定算法的兴趣、人物记忆、草稿生成和反馈分类参数 |
| `/history` | 任务记录筛选与详情入口 |
| `/settings` | 能力状态、OpenViking 检测与重建、备份创建、审计、账户边界和默认运行限制 |

页面只负责组合数据和特性组件。创建、发布、回滚、删除等在线动作必须通过应用接口完成。能力和数据目录由进程环境配置；密码重置与恢复只能在本机通过停机 CLI 执行。

AI 模型页面编辑连接时不得回填 API Key；密钥输入留空表示保留原密文。在线检测只对文本模型显示，并明确会产生一次最小真实调用。AI 算法页面按代码固定顺序展示步骤、固定提示词编码和三个可调参数，不提供新增、删除或拖动步骤的入口；保存按钮使用“发布算法配置”表达不可变版本语义。

## 核心交互流程

### 管理世界

1. 列表页点击“创建世界”直接打开单一自然语言编辑框；AI 生成名称、摘要和灵魂草稿后立即创建并进入详情。
2. 基本信息明确说明名称和简介只用于后台辨认，不进入提示词。
3. 灵魂页使用自由章节和独立运行摘要；修改保存为草稿，发布后成为不可变版本。
4. 成长页显示从世界资料形成的候选和有效结论，原始资料与分析结果不能混成一个列表。
5. 世界资料页支持查找、新建、加入、启用、禁用、解除和同步状态；解除关联不删除共享资料。
6. 人物与管理支持按部分名称搜索未归属世界的人物并添加，也可移除已有关系；移除不删除人物，已归属其他世界的人物不能直接迁移。
7. 版本页显示灵魂差异和历史引用；回滚根据历史创建新草稿。

### 创建人物

1. 列表页点击“创建人物”直接打开单一自然语言编辑框。
2. AI 自动生成人物名称、自由灵魂章节和运行摘要；校验通过后创建人物和待确认草稿。
3. 初始化时不关联世界或资料，创建成功后自动进入人物详情。
4. 提交后弹窗整体切换为等待页，明确告知正在生成、请保持页面开启且完成后会自动进入详情；处理期间禁止关闭和重复提交。
5. 模型未配置或生成失败时不创建人物，弹窗恢复编辑、保留输入并展示错误。
6. 用户在详情中继续调整名称、世界、资料、灵魂、成长和记忆，确认后发布灵魂草稿。

发布前必须展示章节差异、来源、冲突和预算。系统不自动发布长期变化。

### 人物与世界列表状态

1. 人物和世界列表均使用服务端分页，默认每页 10 项，可切换为 5、10、20、50 或 100；页码和每页数量写入 URL。
2. 列表支持勾选当前页任意对象并全选当前页；切换页码或每页数量后清空选择，不保留跨页选择。
3. 批量启用直接执行；单项和批量禁用都必须二次确认，并明确说明只影响后续新任务。
4. 批量按钮使用小号无边框样式；操作行无背景、圆角和边框，未选择时隐藏数量提示。
5. 列表行右侧只保留带可访问名称的进入详情图标；单项启停入口集中在详情页。
6. 禁用人物保留灵魂、成长、记忆、资料关系和历史任务，但不能创建新任务。禁用世界保留版本和所有关系，关联人物仍可工作，但新任务不带入该世界。

### 导入资料

1. 两个导入表单上方共用一个对象选择区，可同时选择多个人物与多个世界；粘贴文本和文件导入使用同一选择，不选对象时只保存到资料库。
2. 文件输入支持一次选择多个 TXT 或 Markdown 文件；整批共用资料用途和关联对象。
3. 每个文件的资料名称默认取去掉扩展名后的文件名，并允许在提交前单独修改。
4. 前端按选择顺序逐个上传，每个文件保持独立的 2 MB 限制；单项失败不回滚已成功资料。
5. 全部成功后收起导入区；部分失败时保留导入区并按文件名汇总成功数、失败数和原因。
6. 世界详情中的“新建资料并自动加入”不显示通用对象选择，创建时直接原子关联当前世界。

### 资料列表与关系

1. 资料列表使用服务端分页，默认每页 10 项，可切换为 5、10、20、50 或 100；页码和每页数量写入 URL，刷新后保持。
2. 列表允许勾选当前页任意资料进行批量启用或批量禁用；切换页码或每页数量后清空选择，不跨页保留。
3. 批量启用直接执行，批量禁用必须二次确认并说明资料将退出检索和 OpenViking 投影；两个按钮使用小号无边框样式，列表行右侧只保留进入详情的图标按钮。
4. 批量操作行不使用背景、圆角或边框；未选择资料时隐藏数量提示，选择后显示当前页已选数量。
5. 资料详情允许启用或禁用单项资料。禁用必须二次确认，重新启用无需确认；两种操作都保留正文、切片和使用关系。
6. 导入和详情页使用同一个人物/世界模糊搜索选择器，允许多选，并把已选对象显示为可移除标签；标签必须标明对象类型。
7. 详情页添加或移除关系后立即保存；失败时恢复操作前选择并显示错误。

### 人物成长与记忆

1. 成长页分为“反馈资料”和“成长结果”；反馈资料按条分页展示，支持批量启用、禁用、删除和分析，人工添加使用弹窗。
2. 记忆页分为“处理记录”和“记忆结果”；处理记录按条展示，支持批量启用、禁用和分析。
3. 人物反馈资料和世界资料都可通过弹窗批量导入成长；每份资料独立设置 1–5 分，分别形成一条待确认成长，正文由服务端按来源读取。
4. 成长结果默认每页 10 项，可切换每页数量并跨页选择；支持批量启用、禁用、拒绝和永久删除。
5. 人工添加和修改成长使用弹窗；修改建立新不可变修订、继承证据并恢复为待确认状态，不覆盖旧修订。
6. 候选结果显示新增、修订、合并、取代或停用影响，支持逐条和批量审核。
7. 成长与记忆都显示来源、适用范围、冲突和修订历史。
8. 记忆转成长必须先执行“转为反馈资料”；成长进入灵魂必须执行“吸收到灵魂”。

### 图文创作

1. 选择人物、任务类型、内容要求、格式模板和参数方案。
2. 可选填写临时场景上下文，并预览世界、人物和提示词分类预算。
3. 先固定实际选入与跳过的上下文，再生成 `DocumentSpec` 并在结构编辑器中确认。
4. 使用上移、下移按钮调整块顺序；MVP 不实现拖放。
5. 执行后按块显示状态、尝试记录、锁定和重试操作。
6. 预览统一产物，并导出 HTML、Markdown 或 Txt。

图片模型未配置时，图片块入口必须禁用，并明确告知文本生成仍可使用。

### 反馈迭代

1. 从运行详情选择具体产物、块或人物提交反馈。
2. 显示系统分类：当前产物、参数、人物学习、灵魂修改或资料事实。
3. 人物学习只有在用户确认后才转为人物反馈资料。
4. 人物学习反馈只创建成长素材，经过成长分析并由用户发布成长提示词后才影响后续新任务。
5. 所有成长、记忆和灵魂变化由用户确认；历史修订和版本不覆盖。

## 数据获取与状态

- 页面读取使用 Nuxt `useFetch` 或 `useAsyncData`，写操作使用明确的服务端接口调用。
- MVP 不引入 Pinia；跨页面事实由服务端和 URL 标识维护，局部编辑状态留在页面或组合式函数。
- 只实现当前页面实际需要的筛选；运行历史把人物、类型和状态筛选写入查询参数，人物、世界和资料列表把页码及每页数量写入查询参数，刷新后可恢复。MVP 不承诺其他列表都支持分页和排序。
- 运行详情在任务未终止时进行有限频率轮询；离开页面时停止轮询。
- 提交动作使用页面提交锁，避免重复创建运行或重复提交关键动作。
- 接口错误统一映射为可操作消息，同时保留稳定错误码供诊断。

## 表单

- 使用 Nuxt UI 表单组件和共享 Zod Schema。
- 客户端校验只用于及时反馈；服务端必须重复校验。
- 必填项、格式错误和业务冲突分别呈现，不用一条通用错误覆盖。
- 删除、发布、归档、人物/世界/资料禁用、恢复、批量审核和基于历史创建草稿使用明确确认区，展示对象与影响范围。重新启用不要求二次确认。
- 长文本编辑器保留未提交草稿至当前页面会话；MVP 不实现跨设备草稿同步。

## 响应式范围

| 设备 | 支持范围 |
|---|---|
| 桌面 | 完整创建、编辑、比较、生成、反馈处理和系统管理 |
| 平板 | 完整主流程；复杂差异和规格编辑可以改为纵向布局 |
| 移动端 | 查看人物、运行状态、预览结果和处理简单确认 |

移动端不承诺完成复杂规格编辑、版本对比、资料管理或恢复操作。窄屏不隐藏关键风险信息，只调整布局或引导到桌面端。

## 可访问性与状态反馈

- 所有表单控件有可见标签，图标按钮有可访问名称。
- 键盘可以完成导航、提交、取消和块顺序调整。
- 焦点状态清晰；主题颜色满足正文和关键状态的对比要求。
- 任务状态不能仅用颜色区分，必须包含文字和必要图标。
- 异步操作显示进行中、成功、失败和可重试状态。
- 图片预览必须使用替代文本；缺失时阻止最终导出。
- 尊重用户的减少动态效果设置，避免不必要动画。

## 内容安全

- 不可信内容不得直接传给 Vue `v-html`。
- HTML 预览只渲染服务端受控渲染器的结果，并在展示前净化。
- Markdown 先解析为受控节点或净化后的 HTML，不允许脚本、事件属性和危险 URL。
- 文件下载名称、图片路径和外部链接必须使用服务端校验结果。

## 界面验收

- 用户能从人物创建进入生成，再进入反馈资料、成长/记忆审核和灵魂发布，不依赖隐藏入口。
- 用户能明确区分原始资料、成长结果、处理记录和记忆结果。
- 世界工作区不存在记忆入口，人物工作区具备完整三层心智入口。
- 创建任务和运行详情可以解释每类 Token 预算、实际使用和跳过内容。
- 所有后台操作都能查看当前状态和失败原因。
- OpenViking 或图片模型关闭后，相关入口正确降级，其他主流程保持可用。
- 刷新运行详情不会丢失服务端状态或重复提交任务。
- 桌面主流程可用键盘完成；移动端能查看关键结果与风险提示。
