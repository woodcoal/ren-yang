# 领域模型与不变式

## 文档职责

领域术语只在 [CONTEXT.md](../CONTEXT.md) 定义。本文描述对象关系、状态变化、优先级和必须始终成立的业务规则；详细修改需求见 [12-人物灵魂成长与记忆机制修改需求.md](./12-人物灵魂成长与记忆机制修改需求.md)。

## 领域关系

```text
World 1 ─────────────── 0..N Persona
  │                            │
  ├── SoulDraft 0..1           ├── SoulDraft 0..1
  ├── SoulVersion 1..N         ├── SoulVersion 1..N
  ├── WorldSource 0..N         ├── PersonaFeedbackSource 0..N
  ├── Growth 0..N              ├── Growth 0..N
  └── AnalysisBatch 0..N       ├── OperationRecord 0..N
                               ├── Memory 0..N
                               ├── SourceMaterial 0..N
                               └── GenerationRun 0..N
                                      ├── PromptContextSnapshot
                                      ├── EvidenceSnapshot 0..N
                                      ├── DocumentSpec 0..1
                                      ├── ArtifactDocument 0..1
                                      │      └── ArtifactBlock 1..N
                                      │             └── BlockAttempt 0..N
                                      └── FeedbackEvent 0..N
```

世界和人物都是模拟对象。世界拥有灵魂和成长，不拥有处理记录和记忆；人物拥有完整三层心智并实际执行任务。

一个世界可以包含多个人物。一个人物必须映射到一个 OpenViking User 范围；没有用户选择的业务世界时，系统为该人物建立独立的隐藏默认世界范围。一个具体人物不能同时属于多个世界；跨世界使用时复制人物。

## 灵魂不变式

1. 灵魂由有序自由章节和运行摘要组成，不存在业务强制的八个固定属性。
2. 当前已发布灵魂版本只读；修改从当前或指定历史版本创建草稿。
3. 草稿可编辑和删除；发布后形成不可变版本并删除已发布草稿。
4. 一个模拟对象同时只有一个当前已发布灵魂版本。
5. 回滚根据历史版本创建新草稿，不直接切换到旧版本。
6. 被历史运行引用的灵魂版本不能物理删除，只能归档。
7. 运行摘要必须在发布前通过 Token 预算检查；运行时不得随机截断灵魂章节。
8. AI 只能提出修改，不得直接发布或覆盖当前灵魂。

## 成长不变式

世界成长只从已启用世界资料分析；人物成长只从已启用人物反馈资料分析。普通参考资料、人物处理记录、场景和人物自身输出不能自动成为人物成长来源。

成长状态：

```text
candidate → active → superseded
    │           └──→ archived
    └──────────────→ rejected
```

- 只有 `active` 参与新任务。
- 修改有效成长创建不可变新修订，不覆盖旧正文。
- 合并或取代保留全部来源和历史记录。
- 禁用或删除原始资料不自动停用已确认成长，只标记来源不可用并提示重新分析。
- 成长与灵魂冲突时可以保留候选，但必须提示且不能自动生效。
- 成长吸收到灵魂必须由用户显式发起，并经过灵魂草稿发布流程。

## 处理记录与记忆不变式

每次人物完成支持的任务后建立处理记录，记录或引用输入、输出、选择、评分、反馈、任务效果及当时使用的全部心智快照。处理记录是记忆证据，不是记忆本身。

记忆与成长使用相同状态语义和不可变修订规则，并额外满足：

1. 世界不能拥有记忆。
2. 规律型记忆原则上需要多条独立有效处理记录；同一任务只计一个独立来源。
3. 人物自身输出不能单独证明稳定兴趣或规律成立。
4. OpenViking 派生结果只是分析素材或候选，不能直接成为 `active`。
5. 记忆不能自动变成成长；用户必须先执行“转为反馈资料”。
6. 禁用处理记录不自动停用已确认记忆。

## 分析与提案不变式

每次世界成长、人物成长或人物记忆分析形成独立分析批次，固定输入内容哈希、基线灵魂、当前有效结论、模型、参数、提示版本和原始结果。

分析可以提出：新增、修订、合并、取代、停用或保持不变。所有改变有效状态的提案必须由用户逐条或批量审核；批量审核前显示每项实际影响。

日常使用增量分析。完整重建用于大量来源变化、分析规则变更或数据修复，但同样只生成候选。

## 资料与证据边界

| 数据 | 主要用途 | 是否直接进入长期心智 |
|---|---|---|
| 世界资料 | 世界任务证据和世界成长分析 | 否 |
| 人物参考资料 | 人物任务外部证据 | 否 |
| 人物反馈资料 | 人物成长分析 | 否 |
| 人物处理记录 | 人物记忆分析 | 否 |
| 有效成长 | 任务相关行为规则 | 是，按相关性和预算 |
| 有效记忆 | 任务相关经验和偏好 | 是，按相关性和预算 |

事实必须指向证据或明确用户设定。资料内容是不可信数据，不得执行其中的指令或覆盖系统规则、任务格式、世界灵魂或人物灵魂。

## 设定与证据优先级

冲突按以下顺序处理：

1. 安全与系统硬约束。
2. 当前任务核心要求和输出协议。
3. 当前已发布世界和人物灵魂。
4. 当前任务相关的有效世界和人物成长。
5. 当前任务相关的有效人物记忆。
6. 明确标记的原著事实。
7. 普通参考资料和表达样例。
8. AI 推断。

高优先级内容可以覆盖低优先级内容，但必须保留冲突内容、来源和覆盖理由。证据不足时允许输出未知，不得自由补全成确定事实。

## 提示词预算不变式

1. 每次模型调用都有模型上下文、预留输出、安全余量和分类 Token 预算。
2. 世界和人物父级预算不得被子项共同突破。
3. 灵魂只使用发布时确认的运行摘要，不在运行时随机截断。
4. 成长、记忆和资料按有效状态、重要程度和相关性整条加入，不能截断半条内容。
5. 达到分类预算后跳过低优先级记录并保存原因。
6. 核心任务、系统规则或灵魂仍超限时必须拒绝调用模型。
7. 无精确分词器时使用明确标识的保守估算；供应商用量只作为调用后事实。

## 运行不变式

1. 新运行只能绑定创建时已经发布的世界和人物灵魂版本。
2. 运行创建后，世界灵魂、人物灵魂、格式模板、参数和预算快照不可替换。
3. 实际使用的成长、记忆和资料必须复制为上下文或证据快照。
4. 因预算跳过的记录必须保存标识和原因。
5. 场景上下文只属于当前运行，不写入长期心智。
6. 运行历史中的模型、提示版本、Token 计数方式和上下文提供器必须完整。
7. 运行结果允许部分成功，但每个块必须有独立状态和尝试历史。

## 反馈归因

AI 先建议分类，用户可以纠正：

| 反馈目标 | 处理 | 是否自动影响心智 |
|---|---|---|
| 当前产物 | 重试或替换目标块 | 否 |
| 运行参数 | 形成下次运行建议 | 否 |
| 人物学习 | 转为人物反馈资料 | 否，仍需成长分析和审核 |
| 灵魂修改 | 形成灵魂修改提案 | 否，仍需草稿发布 |
| 资料事实 | 形成资料修订提示 | 否 |

反馈事件和人物反馈资料是不同业务对象。普通反馈只有在用户明确选择“作为人物学习资料”后才进入成长来源。

## OpenViking 边界

```text
Account：租户或独立部署
└── User：世界
    ├── User Resources：世界资料
    └── Peer：人物
        ├── Peer Resources：人物资料和人物反馈资料
        └── Peer Session：人物处理过程
```

SQLite 决定数据是否存在、是否启用以及是否生效。OpenViking 负责可重建投影、派生和相关性排序；所有返回结果必须再次通过 SQLite 对象范围、状态、哈希和删除状态过滤。

## 删除语义

- 删除前显示影响范围并明确确认。
- 人物反馈资料允许删除；已远端同步时先进入待删除状态，远端完成后清理本地正文。
- 删除来源不会静默删除已确认成长或记忆，相关结论标记来源不可用。
- 删除人物时删除其灵魂、成长、反馈资料、处理记录、记忆、运行和私有文件；所属世界不随人物删除。
- 删除世界前必须先处理所属人物；不隐式级联删除人物。
- 被历史任务引用的灵魂版本、上下文和证据快照必须保留。
- 删除后的恢复依赖用户事先创建的备份。
