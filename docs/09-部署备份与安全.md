# 部署、备份与安全

## 部署边界

MVP 直接以 Node.js 长期运行进程部署，不提供 Docker、Electron 或 Tauri。Nuxt/Nitro Web 服务与内部 Worker 位于同一进程，SQLite 和文件资产位于同一受控数据目录。

推荐环境：

- Node.js 当前 LTS。
- pnpm，依赖由锁文件固定。
- 单实例运行；MVP 不支持多个应用进程共享 SQLite。
- 本机访问可使用回环地址 HTTP；开放到局域网时必须置于 HTTPS 反向代理后。

## 命令契约

工程实现后至少提供以下脚本，具体参数由命令帮助说明：

| 命令 | 职责 |
|---|---|
| `pnpm dev` | 启动开发环境 |
| `pnpm build` | 只读取无密钥 `.env.build`，生成生产构建并执行构建期校验 |
| `pnpm start` | 启动生产 Node.js 服务和内部 Worker |
| `pnpm test` | 执行默认自动化测试 |
| `pnpm migrate` | 显式执行待应用的 SQLite 迁移 |
| `pnpm admin:reset-password` | 在本机交互式重置唯一管理员密码 |
| `pnpm backup` | 创建一致性手工备份 |
| `pnpm restore:validate` | 验证备份，不改动当前数据 |
| `pnpm restore -- <备份目录>` | 在应用停止后执行已验证备份恢复 |

MVP 不实现自动定时备份。命令失败必须返回非零退出码，并输出可操作但不泄露密钥的信息。

## 数据目录

```text
data/
├── app.sqlite             # 业务事实和任务状态
├── sources/               # 导入资料原文
├── artifacts/             # 运行生成的块资源
├── exports/               # 预留目录；当前导出包即时生成，不持久化
├── backups/               # 手工备份，建议也复制到其他设备
└── logs/                  # 本地结构化日志
```

- 数据目录位置由非敏感配置指定，默认目录加入 `.gitignore`。
- 数据库只保存受控相对路径，不保存可逃逸数据目录的任意路径。
- 进程启动时验证目录可写、权限和可用空间；不自动切换到未知目录。
- 资料原文件和图片资产采用稳定标识命名；即时导出文件使用安全化标题和运行标识命名。

## 配置与密钥

非敏感配置可以来自仓库外环境文件或环境变量；密钥只能从仓库外只读配置源加载。生产构建显式读取仓库内的空 `.env.build`，不会自动读取本地 `.env`；所有运行配置均在启动进程时注入。

密钥包括：

- 会话密封密钥。
- 由会话密封密钥进行用途隔离派生的数据库凭据加密密钥；该密钥同时保护人物账号密码和 AI 接口 API Key。
- 旧图文生成链路由环境注入的文本与图片模型访问凭据。
- 管理员在 AI 模型页面录入、经 AES-256-GCM 加密后保存到 SQLite 的算法接口凭据。
- OpenViking 认证信息。
- 反向代理或其他外部服务凭据。

主密钥和明文凭据不得写入 SQLite、资料、产物、导出、错误响应或日志。SQLite 和备份允许包含使用随机 IV、认证标签及连接 UUID 附加认证数据保护的版本化 AES-256-GCM 密文。管理页面只显示“已配置”，创建响应、编辑响应、审计和算法快照均不返回密文或明文。

启动时必须校验会话密钥；文本、图片和 OpenViking 能力分别报告配置状态。OpenViking 缺失、故障、未采用 API Key 认证或配置密钥没有当前 Account 的 ADMIN 权限时，必须明确进入 FTS5 降级，不得伪装成语义检索可用。启动补偿扫描从 SQLite 补回缺失的 User、资料和 Session 持久任务。

## 登录与网络

- 即使只在本机运行，也始终要求登录。
- 首次启动只允许在本机安全上下文初始化管理员。
- 管理员登录密码使用安全哈希函数保存，不保存明文或可逆密文。
- 人物第三方账号密码因业务要求允许主动取回，使用 AES-256-GCM 认证加密保存；普通人物详情不返回密文或原文，只有管理员主动查看时才解密，响应禁止缓存。
- AI 接口 API Key 使用相同加密端口但绑定独立连接 UUID 上下文；只有服务端执行连接检测或算法步骤时临时解密到内存，不提供取回接口。
- 会话 Cookie 使用 `HttpOnly`、合适的 `SameSite` 和生产环境 `Secure` 属性。
- 修改密码、恢复数据后使旧会话失效。
- 不提供公开注册、多用户和第三方登录。
- 局域网访问必须使用 HTTPS 反向代理，并限制可信网络；应用不自行申请证书。

## 单进程生命周期

1. 启动时校验配置、数据目录、迁移状态和数据库完整性。
2. 完成必要迁移后启动 Web 服务与 Worker。
3. Worker 恢复过期租约，再领取新任务。
4. 收到退出信号后停止领取任务。
5. 当前模型调用无法安全中断时，等待至配置的优雅退出上限。
6. 在安全点写入状态并关闭 SQLite、日志和外部连接。

超过退出上限的任务依赖租约在下次启动恢复。不得仅以内存变量表示任务成功。

## 手工备份

备份流程：

1. 使用 SQLite 在线备份能力创建一致性数据库副本，不能直接复制活动中的 WAL 数据库主文件。
2. 规范化副本日志模式，并从副本读取资料原文件与图片资产引用。
3. 只复制这些白名单引用文件；导出包即时生成，不进入备份。
4. 生成清单，记录相对路径、媒体类型、大小和 SHA-256。
5. 校验数据库完整性、外键、迁移数量、引用集合和所有清单项。
6. 原子完成备份目录；若并发变化导致引用文件缺失，则备份失败并清理临时目录。

备份不包含主密钥、明文凭据、日志或 OpenViking 数据，但 SQLite 副本会包含 AI 接口和人物账号的加密密文。恢复后必须提供与备份时相同的本地主密钥，否则密文不可解密；不能用新密钥静默覆盖。备份必须包含 SQLite 中的投影状态、Session 状态、候选记忆、有效成长和记忆；OpenViking 可由这些事实重建。

## 恢复与验证

恢复分为只读验证和实际恢复：

- `restore:validate` 检查清单版本、哈希、路径、SQLite 完整性、迁移兼容性和必需文件，不修改当前数据。
- 实际恢复只能在应用停止后通过本机 CLI 执行。
- 恢复前再次展示目标备份、创建时间、数据规模和将被替换的当前目录。
- 当前数据先移动到带时间标识的回退目录，再将已验证备份原子切换为活动目录。
- 启动后重建 FTS5；OpenViking 按 SQLite 当前关联和状态重建世界 User / 人物 Peer 投影，并执行引用一致性检查。
- 恢复失败时保留原数据和失败诊断，不留下半恢复状态。

是否永久删除回退目录必须由用户单独确认。

## 删除与数据生命周期

- 删除前计算人物、版本、资料、运行、产物、反馈和文件之间的引用影响。
- 默认先展示影响范围，再要求输入明确确认。
- 删除应用服务在事务中删除业务记录并建立文件删除清单；文件操作失败必须可重试和审计。
- 路径规范化后必须仍位于配置的数据目录内，禁止符号链接或 `..` 穿越边界。
- 已进入独立备份的历史数据不会被在线删除自动改写；用户需要按备份保留策略单独删除。

## 安全控制

### 提示注入与模型输出

- 导入资料和用户内容均视为不可信数据，不得作为系统指令执行。
- 提示中明确分隔系统规则、人物设定、证据、场景和用户任务。
- 资料内要求泄露提示、密钥或改变优先级的文字一律视为资料内容。
- 模型结构化输出必须通过 Schema 和业务规则校验；不直接执行模型返回的命令、路径、HTML 或 URL。

### 文件输入

- MVP 只接受粘贴文本、TXT 和 Markdown。
- 同时校验声明类型、扩展名、内容特征、UTF-8 解码和大小上限。
- 拒绝二进制伪装、压缩包、路径控制字符和超限文件。
- 上传名称不作为磁盘真实路径，原始名称只以清理后的元数据保存。

### Web 输出

- 所有可变文本默认转义。
- 禁止直接渲染不可信 `v-html`。
- HTML 与 Markdown 预览经过允许列表净化，拒绝脚本、事件属性、危险协议和远程追踪资源。
- 下载接口通过记录标识解析文件，不接受任意磁盘路径。
- 修改型接口要求有效会话并执行来源与 CSRF 防护策略。

### 资源限制

- 对资料大小、请求体、块数量、单次输出、图片大小、任务重试和并发设置明确上限。
- 单 Worker 串行执行模型任务，避免本地资源和外部额度失控。
- 外部请求设置连接、响应和总时限；限流和永久失败使用不同错误码。
- 磁盘空间不足时停止创建新资产，不删除旧数据自救。

### 日志与审计

- 日志记录请求标识、运行标识、状态变化、耗时和稳定错误码。
- 默认不记录完整提示、资料正文、模型原始输出、Cookie、认证头或密钥。
- 必要诊断内容按字段脱敏，并由用户显式开启。
- 本地日志按大小和保留天数轮转，防止无界增长。
- 发布、回滚、删除、提案拒绝、恢复、账户重置、AI 接口与模型编辑、算法配置发布写入审计记录。旧图文生成能力仍由环境配置并在重启时读取；算法使用的接口与模型由管理员页面版本化配置。

## 运维验收

- 干净机器可按文档完成安装、迁移、首次登录和启动。
- 进程异常退出后能恢复过期任务且不重复生成已提交结果。
- 备份清单、哈希和 SQLite 完整性校验通过，恢复演练可回退。
- OpenViking 故障后从 SQLite/FTS5 完成核心流程；Session 和 Memory 任务保留待重试，恢复后可重建并补偿。

生产隔离要求：OpenViking 使用专用 Account；配置密钥必须是该 Account 的 ADMIN User Key，仅供后端管理 User。每个世界和独立人物空间必须创建自己的普通 User，业务资料、检索和 Session 只能使用目标 User Key；ADMIN Key 不得用于常规数据请求。User Key 只保存在应用进程内，进程重启时由 ADMIN Key 刷新，不写入 SQLite、备份或日志。
- 密钥扫描确认数据库、备份、导出和日志中没有凭据。
- 路径穿越、危险 HTML、伪装文件和超限请求被拒绝并留下安全日志。
