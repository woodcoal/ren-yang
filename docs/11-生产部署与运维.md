# 生产部署与运维

## 部署边界

- 仅支持单台主机、单个 Node.js 进程和本地 SQLite。
- 应用必须监听 `127.0.0.1`，不得把 Nitro 端口直接暴露到公网或局域网。
- 局域网或公网访问必须经过同机 HTTPS 反向代理。
- OpenViking、文本模型和图片模型是外部能力；SQLite 与数据目录始终是唯一业务事实源。
- 不支持 Serverless、Edge、多实例共享数据目录或 SQLite 网络文件系统。

## 目录与账户

建议建立独立、不可登录的系统账户：

```bash
sudo useradd --system --home /var/lib/ren-yang --shell /usr/sbin/nologin ren-yang
sudo install -d -o ren-yang -g ren-yang -m 0700 /var/lib/ren-yang
sudo install -d -o root -g ren-yang -m 0750 /etc/ren-yang
```

代码目录可以是 `/opt/ren-yang/current`，运行数据固定使用 `/var/lib/ren-yang`。数据目录不能位于 NFS、SMB 或其他网络文件系统。

## 安装与构建

```bash
corepack enable
corepack prepare pnpm@11.20.0 --activate
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

生产主机必须使用 Node.js 24 和 pnpm 11。依赖只从锁文件安装，不能在生产主机执行无锁升级。

## 环境配置

将 `.env.example` 复制到仓库外，例如 `/etc/ren-yang/ren-yang.env`，权限设为 `0640 root:ren-yang`。至少配置：

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3001
NUXT_DATA_DIRECTORY=/var/lib/ren-yang
NUXT_SESSION_PASSWORD=<至少 32 个字符的独立随机值>
```

会话密钥可以用 `openssl rand -base64 48` 生成。文本、图片和 OpenViking 密钥只能保存在该仓库外文件或等价的只读密钥源中。

资源限制默认值：

| 配置 | 默认值 | 作用 |
|---|---:|---|
| `NUXT_LIMITS_REQUEST_BODY_BYTES` | `2200000` | 所有 API 修改请求的实际正文上限，分块传输同样受限 |
| `NUXT_LIMITS_MINIMUM_FREE_DISK_BYTES` | `104857600` | 新资料或图片写入后必须保留的空间 |
| `NUXT_LOGGING_MAXIMUM_FILE_BYTES` | `5242880` | 单个活动 JSON Lines 日志大小 |
| `NUXT_LOGGING_RETENTION_DAYS` | `14` | 轮转日志保留天数 |

资料仍有 2 MB 原始文件限制，图片仍有 10 MiB 限制。反向代理的请求体上限应设置为 3 MB，不能高于应用上限过多。

## 数据库初始化

首次启动前执行：

```bash
set -a
. /etc/ren-yang/ren-yang.env
set +a
pnpm migrate
```

该命令应用全部 Drizzle 迁移，并检查 SQLite 完整性、外键和 WAL 配置。不得手工复制活动中的 `app.sqlite` 作为备份。

## systemd

`/etc/systemd/system/ren-yang.service`：

```ini
[Unit]
Description=人样 AI 人物模拟与图文创作系统
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ren-yang
Group=ren-yang
WorkingDirectory=/opt/ren-yang/current
EnvironmentFile=/etc/ren-yang/ren-yang.env
ExecStart=/usr/bin/node .output/server/index.mjs
Restart=on-failure
RestartSec=5
TimeoutStopSec=180
UMask=0077
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/ren-yang

[Install]
WantedBy=multi-user.target
```

启用并检查：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ren-yang
sudo systemctl status ren-yang
```

应用通过数据目录中的 `.application.lock` 阻止两个进程共享同一 SQLite。进程异常退出后的失效锁会在确认 PID 不存在后清理。

## 首次管理员初始化

必须在开放反向代理前完成。远程服务器使用 SSH 隧道：

```bash
ssh -L 3001:127.0.0.1:3001 user@server
```

然后在本机浏览器访问 `http://127.0.0.1:3001/setup`。应用会同时检查直接套接字地址和代理转发地址；远端代理请求不能创建首个管理员。

## HTTPS 反向代理

Caddy 最小配置：

```caddyfile
ren-yang.example.com {
    request_body {
        max_size 3MB
    }
    reverse_proxy 127.0.0.1:3001
}
```

Nginx 最小配置：

```nginx
server {
    listen 443 ssl http2;
    server_name ren-yang.example.com;
    client_max_body_size 3m;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

代理必须设置真实 `Host`、`X-Forwarded-For` 和 `X-Forwarded-Proto`。只允许可信网络访问时，应在反向代理或主机防火墙实施来源限制。

## 备份

管理面板可以在线创建备份；本机命令等价：

```bash
set -a
. /etc/ren-yang/ren-yang.env
set +a
pnpm backup
```

备份目录包含 `manifest.json`、SQLite 在线副本和数据库实际引用的资料/图片文件。清单记录媒体类型、字节数和 SHA-256。密钥、日志、缓存、未引用文件和 OpenViking 数据不会进入备份。

`data/backups/` 不能视为异地备份。每次关键变更后，应把已完成备份目录复制到另一设备，并在复制后执行只读验证：

```bash
pnpm restore:validate -- /mnt/offsite/backup-2026-...
```

## 停机恢复

```bash
sudo systemctl stop ren-yang
set -a
. /etc/ren-yang/ren-yang.env
set +a
pnpm restore:validate -- /mnt/offsite/backup-2026-...
pnpm restore -- /mnt/offsite/backup-2026-...
sudo systemctl start ren-yang
```

恢复命令会：

1. 再次验证清单、哈希、SQLite、迁移和文件引用。
2. 在同一文件系统准备完整 staging 目录。
3. 把当前数据目录改名为带时间的 `rollback` 目录。
4. 原子启用恢复目录；切换失败会立即恢复原目录。
5. 重建 FTS5、撤销旧会话，并把 OpenViking 同步状态改为待重建。

命令输出恢复前数据的绝对回退路径。确认登录、资料检索、历史和产物正常前，禁止删除该目录。恢复来源如果原先位于活动数据目录，其备份副本会随旧数据保留在回退目录。

## 升级与回退

1. 在线创建并异机复制备份。
2. 停止服务。
3. 部署新代码并执行 `pnpm install --frozen-lockfile`、`pnpm build`。
4. 执行 `pnpm migrate`。
5. 启动服务并检查登录、系统设置、任务和日志。

迁移不支持自动降级。升级失败时切回旧代码，并使用升级前备份执行停机恢复。

## 日志与审计

- 本地请求日志位于 `data/logs/application.log`，使用 JSON Lines。
- 日志只记录请求标识、方法、路径、状态和耗时；不记录请求正文、Cookie、认证头、提示或模型输出。
- 日志按大小轮转并按天数清理，备份不包含日志。
- 发布、回滚、删除、密码重置和数据恢复保存到 SQLite `audit_events`，可在系统设置页查看。
- HTTP 响应包含 `X-Request-Id`，可用于关联本地日志。

## 故障检查

```bash
sudo systemctl status ren-yang
sudo journalctl -u ren-yang --since today
pnpm migrate
pnpm restore:validate -- <最近备份目录>
```

磁盘余量不足时，系统停止创建新资料和图片，不会删除旧数据自救。OpenViking 不可用时可在部署环境关闭该能力，后续运行使用 SQLite FTS5；既有业务事实不受影响。
