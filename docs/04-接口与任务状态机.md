# 接口与任务状态机

## 接口原则

- 网页内部接口使用 `/api/v1` 前缀和管理员会话；公共接口使用 `/api/v2` 前缀和 API Key，二者不得混用凭据。
- 控制器只处理会话校验、Zod 请求解析、应用服务调用和 HTTP 映射。
- 同步 CRUD 成功返回 `200` 或 `201`；异步运行创建返回 `202` 和任务标识。
- 删除成功返回 `204`，删除前的影响分析使用独立只读接口。
- 时间使用 UTC Unix 毫秒，标识使用字符串 UUID。
- 外部接口只暴露业务对象，不暴露 Drizzle 行、模型 SDK 响应或 OpenViking 原始响应。

## 公共 API v2

- OpenAPI 3.1 契约：`GET /api/v2/openapi.json`。
- 可交互文档：`GET /api/v2/docs`；文档与契约无需登录，实际业务试调必须输入 API Key。
- 业务凭据只接受 `Authorization: Bearer <api_key>`，不接受 URL 查询参数。
- 公共时间字段使用 ISO 8601 UTC；成功和失败响应都包含请求追踪 ID。
- 所有写接口必须提供 `Idempotency-Key`。同一 Key、方法、路径和幂等键永久复用首次成功结果；请求内容变化返回 `409 IDEMPOTENCY_CONFLICT`。
- `401` 表示 Key 无效、过期或吊销，`403` 表示权限不足，`404` 表示资源不存在，`409` 表示幂等、版本或业务状态冲突，`413` 表示请求字节超限，`422` 表示参数或业务校验失败；`429` 为后续频率控制保留。

权限范围固定为 `persona:read/write`、`world:read/write`、`library:read/write`、`generation:read/write`。其中 `generation:read/write` 同时覆盖兴趣与图文接口。API Key 管理只存在于管理员会话接口 `/api/v1/api-keys`，公共 Key 无权创建、查看、吊销或删除 Key；管理员只可永久删除已吊销 Key，删除时同步清理该 Key 的公共调用审计和幂等记录。

公共资源覆盖人物、世界、资料的分页、详情、创建、修改、启停、删除影响和受控删除；同时覆盖人物与世界、资料与人物/世界/全局范围的关系，以及人物/世界灵魂草稿与发布。TXT、Markdown 上传使用 `multipart/form-data`。直接图文运行开放创建、查询、取消、整体重试、即时渲染、图片读取和结果下载；兴趣判定开放批量创建、查询和单项重试，其他 AI 任务仍只提供内部接口。

## 响应格式

成功响应：

```json
{
  "data": {}
}
```

失败响应：

```json
{
  "error": {
    "code": "PERSONA_VERSION_NOT_ACTIVE",
    "message": "所选人物灵魂版本不可用于新运行",
    "details": {}
  }
}
```

`message` 面向用户，`code` 供界面稳定判断；内部堆栈、模型密钥和原始外部响应不得返回浏览器。

人物与世界列表快速创建统一采集名称和一段灵魂提示词。未选择 AI 时，列表页直接调用对应创建接口，按原文创建默认启用的对象及其初始当前版本；选择 AI 时，先调用 `POST /api/v1/soul/analyze`，只有整理成功后才创建对象。独立整理接口不创建人物、世界或版本，整理失败不得留下半创建对象；对象名称始终使用用户输入，模型只整理 `snapshot.promptText`。创建成功后进入详情，初始提示词已经生效。

`POST /personas/draft` 和 `POST /worlds/draft` 保留给需要模型同时建议名称、摘要或结合资料生成候选的流程，只返回结构化建议，不创建对象。模型返回的名称、摘要和 `snapshot.promptText` 只能描述业务对象，候选、确认、发布或 AI 生成等流程元话术视为模型输出无效并自动重试。人物草稿不接收来源模式，参考资料可为空，一次最多向模型提供 8 项资料。

世界详情的人物管理复用 `GET /api/v1/personas` 和 `PATCH /api/v1/personas/{personaId}`：按名称在未归属世界的人物中模糊搜索，添加时写入当前 `worldId`，移除时写入 `worldId: null`。移除仅解除关系，不删除人物；已归属其他世界的人物不作为添加候选。

人物和世界灵魂保存接口统一接收 `{ baseVersionId, snapshot: { promptText } }`。应用服务校验版本归属、规范化文本并检查 Token 预算，在一个 SQLite 事务内插入不可变历史、切换当前版本并写入审计。详情页魔法棒先独立调用 AI 整理接口，结果只回填编辑框；历史选择同样只回填，只有用户点击保存才会生成并启用新版本。保存失败不得覆盖编辑框内容。

资料创建请求可携带 `targets: [{ targetType: "persona" | "world", targetId: UUID }]`，也可传空数组只保存到资料库。应用服务先验证并去重目标，仓储再把资料正文、FTS5 切片和优先级为 `100` 的初始关系放入同一 SQLite 事务；任一目标无效时不得留下资料、切片、关系或原始文件。浏览器多文件导入仍逐个调用单文件接口，每个文件独立提交名称，共用资料用途和目标；部分文件失败时保留成功项并汇总结果，不执行整批回滚。OpenViking 同步只在单项 SQLite 事务成功后异步排队。

资料状态接口只修改 `source_materials.is_enabled`，不删除正文、切片和人物/世界关系。批量接口先验证全部资料存在，再用单条 SQLite 更新提交，避免无效标识造成部分成功；本地提交后按资料分别创建可重试的 OpenViking 删除或恢复投影任务。资料被全局禁用后，管理端 FTS5 检索、人物任务 SQLite 检索和 OpenViking 检索均必须排除该资料。

人物与世界状态接口分别只修改 `personas.is_enabled` 和 `worlds.is_enabled`。批量接口先验证全部对象存在，再用单条 SQLite 更新，任一 UUID 无效时整批不修改。禁用人物会阻止创建新的兴趣判断或图文任务；禁用世界不阻断其关联人物工作，但后续新任务必须排除该世界灵魂、成长、资料和 OpenViking 世界范围检索。禁用不删除对象、版本、资料关系、心智记录或历史运行；历史运行继续使用创建时已固定的快照。

## AI 接口、模型与算法配置接口

| 方法与路径 | 用途 |
|---|---|
| `GET/POST /api/v1/ai/connections` | 查询脱敏接口连接或创建带加密 API Key 的连接 |
| `PUT /api/v1/ai/connections/{connectionId}` | 替换非敏感连接参数；省略 `apiKey` 时保留原密文 |
| `GET/POST /api/v1/ai/model-deployments` | 查询或创建连接上的具体文本/图片模型部署，并为文本模型声明关闭思考请求格式 |
| `PUT /api/v1/ai/model-deployments/{deploymentId}` | 替换模型部署名称、模型标识、类型、连接、关闭思考格式和启用状态 |
| `POST /api/v1/ai/model-deployments/{deploymentId}/check` | 对文本部署发送最小真实请求，验证端点、密钥和模型，不返回供应商正文 |
| `GET/PUT /api/v1/system/ai-settings` | 查询或完整替换默认文本与图片模型部署 |
| `GET /api/v1/ai/algorithms` | 查询十四个固定算法、步骤定义、当前配置和版本数量 |
| `PUT /api/v1/ai/algorithms/{code}` | 校验固定步骤集合并发布一版完整模型与参数配置 |

连接接口从不返回密文或明文，只返回 `hasApiKey`。算法配置接口不能提交任意步骤或步骤顺序；固定提示词与步骤配置在统一 AI 管理中共同维护。当前算法编码为 `persona_soul`、`world_soul`、`persona_growth`、`world_growth`、`persona_memory`、`persona_draft`、`world_draft`、`feedback_classification`、`persona_avatar`、`interest_assessment`、`article_generation`、`article_image_analysis`、`article_text_revision`、`article_image_generation`。算法步骤可显式选择部署或留空；留空时新任务使用同类型默认模型，显式部署始终优先。文本步骤可选择关闭思考，系统仅按模型部署声明的 `enable_thinking:false`、`reasoning_effort:"none"` 或 `reasoning:{ enabled:false }` 格式发送一个字段；未声明格式时拒绝执行。最大输出 Token 不设本地上限；为 `0` 时请求省略 `max_tokens`，由供应商采用默认长度，且不改变固定提示词预算。图片步骤可配置二次居中裁剪的最大宽高；文章图片资产接口与人物头像接口均使用 `variant=result|original` 读取裁剪结果或原图。默认设置不包含提示词或调用参数，也不改变已创建任务的模型快照。

兴趣判断、文章生成和正文修订的系统消息由算法固定规则以及任务创建时锁定的已发布人物、世界、成长和记忆组成；用户消息只包含附加提示词、检索证据、本次待处理内容和输出要求。同一心智快照下只改变本次内容时，系统消息必须逐字一致。进程内缓存亲和键只由实际系统消息的 SHA-256、算法编码、提示词版本、模型部署和固定参数生成，不包含 API Key、系统消息原文、本次变化文本、运行 ID、时间戳或旧模型回答；同键调用按提交顺序串行，异键并行，前序失败仍会释放后续调用。该队列不缓存模型结果，不承诺跨进程顺序，也不改变持久任务状态、租约、幂等和重试语义。图片调用、文章配图分析、后台算法诊断及其他尚未建立稳定系统消息契约的文本算法不进入队列。

| `GET /api/v1/runs/{runId}` | 获取运行快照、任务和结果 |
| `POST /api/v1/runs/{runId}/cancel` | 请求协作式取消 |
| `POST /api/v1/runs/{runId}/retry` | 对可重试失败创建新任务 |
| `POST /api/v1/runs/{runId}/render` | 渲染指定格式 |
| `GET /api/v1/runs/{runId}/assets/{assetId}` | 读取该运行引用的受控图片资产 |
| `GET /api/v1/runs/{runId}/exports/{format}` | 下载文件或资源包 |

图文创建输入只包含 `personaId`、`requirement`、`outputFormat` 和 `imageCount`。系统先生成完整文章；`imageCount` 大于零时，再基于最终文章分析图片内容与位置并生成严格相同数量的图片。`outputFormat=html` 时按位置混排，`outputFormat=text` 时正文和 `assets` 图片数据分离返回。前端通过 `GET /runs/{runId}` 轮询状态，活动运行默认每两秒一次；MVP 不实现 WebSocket 或 SSE。

兴趣批次输入包含一个 `personaId`、可选 `additionalPrompt` 和一至二十个 `{ itemId, text }`。附加提示词对整批文本生效，不提供年龄、地点、目标、情绪或事件等结构化场景字段。主任务固定人物、算法、提示词、附加提示词、证据和模型快照后只调用一次模型；固定人物心智位于系统消息，附加提示词、证据和整批文本位于用户消息。响应按 `itemId` 逐项校验结构、证据和三态结论，缺项、重复项或单项格式错误只使对应运行失败。单项重试保持系统消息不变，只发送同一附加提示词、证据和目标文本，不携带旧模型回答；批次累计记录输入、输出、总 Token 和供应商返回的缓存命中 Token。

## 运行状态机

图文运行状态：

```text
planning
  ├──失败──> failed
  └──文章与内部顺序快照完成──> queued
                                  ↓
                               running
                    ┌─────────────┼─────────────┐
                    v             v             v
                succeeded      partial        failed
                    └────取消请求安全点──────> canceled
```

内部保存文档快照时可短暂使用 `awaiting_confirmation` 作为原子确认过渡状态，但应用服务会在同一次 Worker 执行中自动确认并入队，不接受用户确认或编辑。兴趣运行创建后直接进入 `queued`。

任务状态：

```text
queued → running → succeeded
   │         ├────→ failed
   │         └────→ cancel_requested → canceled
   └──────────────→ canceled
```

`partial` 表示至少一个块成功且至少一个块失败；成功块和尝试必须保留。

## Worker 规则

1. 单进程内只启动一个 Worker 循环。
2. 领取任务时以短事务把 `queued` 更新为 `running`，增加尝试次数并写入租约。
3. 外部调用期间不保持数据库事务；任务依赖领取时写入的租约和重启恢复处理异常退出。
4. 生成、分析和评测任务最多两次自动尝试；Resource、Session 与删除同步任务最多三次，耗尽后进入 `failed` 并保留同步错误。
5. 手工重试创建新的任务记录或新的块尝试，不重置旧历史。
6. 取消是协作式的：在模型调用前后、块之间和文件写入前检查取消标志。
7. 进程重启时，租约过期且仍可尝试的任务重新进入 `queued`；超过上限的任务进入 `failed` 并记录恢复原因。

## 限制与超时

每次运行解析并保存以下上限：

- 最大文字块数。
- 最大图片块数。
- 模型上下文 Token。
- 预留输出与安全余量 Token。
- 世界、人物、灵魂、成长、记忆和资料分类 Token 预算。
- 单次模型提示最大字符数，仅作为异常输入保护。
- 单次模型最大输出 Token。
- 整次运行最大已报告 Token。
- 模型请求超时。
- 单块最大尝试数。

提示输入优先使用模型对应分词器；没有精确分词器时使用明确标记的保守估算和安全余量。调用前按父子预算筛选上下文并执行总预算硬检查，不能用调用后的供应商用量替代。供应商未返回实际用量时显示未知，不把估算伪装成实际用量。

内部执行单元的尝试数跨自动执行、整体重试和反馈修正累计，不能通过新建任务绕过。达到硬上限时停止创建新调用，保留已有结果和已产生用量并返回 `TASK_LIMIT_EXCEEDED`。这些内部执行单元不向用户提供单独操作入口。MVP 不自动计算货币费用；保存供应商返回的用量，允许后续配置单价计算。

## 稳定错误码

至少包含：

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `AUTH_REQUIRED` | 401 | 会话不存在或无效 |
| `SETUP_ALREADY_COMPLETED` | 409 | 唯一管理员已创建 |
| `VALIDATION_FAILED` | 400 | 请求不符合共享 Schema |
| `RESOURCE_NOT_FOUND` | 404 | 业务对象不存在 |
| `VERSION_CONFLICT` | 409 | 基于过期版本执行修改 |
| `CAPABILITY_DISABLED` | 422 | 请求依赖未配置能力 |
| `DOCUMENT_SPEC_NOT_CONFIRMED` | 409 | 规格尚未确认 |
| `BLOCK_LOCKED` | 409 | 目标块已锁定 |
| `RUN_NOT_CANCELABLE` | 409 | 当前状态不能取消 |
| `TASK_LIMIT_EXCEEDED` | 422 | 超过配置上限 |
| `PROMPT_BUDGET_EXCEEDED` | 422 | 核心提示在分类收缩后仍超过模型输入预算 |
| `PROVIDER_UNAVAILABLE` | 503 | 外部模型或 OpenViking 不可用 |
| `BACKUP_VALIDATION_FAILED` | 422 | 备份清单或哈希不一致 |

外部供应商错误映射为稳定错误码，同时把脱敏后的原始原因保存在运行历史中。
