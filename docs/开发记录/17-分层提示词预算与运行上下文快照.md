# 分层提示词预算与运行上下文快照开发记录

## 阶段目标

限制世界、人物、成长、记忆和参考资料进入模型提示词的长度，并为每次运行保存不可变上下文快照，避免内容持续积累后超过模型上下文窗口，也使历史结果可追溯。

## 完成内容

### 1. 分层 Token 预算

文本模型参数新增：

- `contextWindowTokens`：模型上下文总长度；
- `reservedOutputTokens`：回答预留长度；
- `safetyMarginTokens`：协议、模板和估算误差的安全余量；
- `worldBudgetTokens`：世界总预算；
- `worldSoulBudgetTokens`：世界灵魂预算；
- `worldGrowthBudgetTokens`：世界成长预算；
- `personaBudgetTokens`：人物总预算；
- `personaSoulBudgetTokens`：人物灵魂预算；
- `personaGrowthBudgetTokens`：人物成长预算；
- `personaMemoryBudgetTokens`：人物记忆预算；
- `sourceBudgetTokens`：参考资料预算。

可用输入按“模型上下文总长度 - 回答预留 - 安全余量”计算。参数校验保证：

- 单次回答上限不超过回答预留；
- 世界子预算之和不超过世界总预算；
- 人物子预算之和不超过人物总预算；
- 世界、人物和参考资料总预算不超过可用输入。

### 2. 上下文选择规则

- 人物灵魂是运行必需内容，超过预算时直接拒绝运行，不静默截断；
- 世界灵魂仅在本次任务绑定世界时参与预算，超过预算时直接拒绝运行；
- 成长、记忆和参考资料保持完整条目，不截断半条内容；
- 父级预算、分类预算和总输入预算均为硬上限；
- 总预算不足时依次保留世界成长、人物成长、人物记忆和参考资料；
- 重复候选只选择一次；
- 未选入条目保存稳定原因：`category_budget`、`parent_budget`、`total_budget`、`scope_or_state_invalid`。

### 3. SQLite 二次校验

上下文提供器返回候选后，生成应用服务再次根据 SQLite 事实校验：

- 资料仍属于当前人物或世界，处于可用状态且正文有效；
- 世界成长、人物成长和人物记忆仍为 `active`；
- 当前正文哈希与候选哈希一致；
- 同一业务实体不会重复进入提示词。

OpenViking 只负责候选召回，不能绕过 SQLite 的归属、状态和正文校验。SQLite 仍是唯一业务事实源。

### 4. 运行上下文快照

`generation_runs` 新增 `prompt_context_snapshot_json`，创建运行时固定保存：

- Token 计数器名称及是否精确；
- 可用输入与预计输入；
- 世界、人物、资料父子预算及实际用量；
- 世界与人物灵魂发布版本；
- 实际选入条目、未选入条目及原因；
- 初始系统提示和用户提示的 SHA-256。

迁移前历史运行该字段为 `null`，历史详情读取保持兼容。

### 5. 提示词与后台

- 提示版本升级为 `artifact-v5`；
- 文本提示词明确分为人物灵魂、世界灵魂、世界成长、人物成长、人物记忆、不可信参考资料、临时场景和当前任务；
- 图片提示词使用相同预算选择结果；
- `user_setting` 证据保留在历史快照中，不再重复注入运行提示词；
- 生成设置页增加完整预算参数和可用输入计算；
- 运行详情页增加预计输入、可用输入、分类预算用量、计数方式、选入条目和跳过原因；
- 运行详情的人物快照改为展示实际灵魂摘要与自由章节，不再读取已删除的固定八字段。

## 分层约束

- API 控制器未直接访问数据库；
- 生成应用服务只通过仓储、上下文提供器和模型端口访问数据层及外部系统；
- 上下文预算计算保持为纯领域逻辑；
- 运行快照随运行事实一起由运行仓储持久化。
