# AI 成长记忆分析与人工审核

## 1. 完成范围

- 新增世界成长、人物成长和人物记忆三种分析批次。
- 支持“分析新增资料”和“完整重新分析”两种模式；增量模式没有新输入时明确拒绝重复分析。
- 每个批次固定灵魂版本、当前有效长期内容、原始输入正文与哈希、模型、参数和提示词版本。
- AI 仅生成 `add`、`revise`、`merge`、`supersede`、`archive`、`no_change` 提案，不直接修改长期内容。
- 管理员可以逐条修改提案正文、适用范围和重要程度，然后接受或拒绝。
- 接受提案时在同一 SQLite 事务中创建不可变修订、更新当前记录和证据链；拒绝不改变成长或记忆。
- 人物记忆新增或修订提案至少需要两个批次输入，避免把单次输出误判为稳定记忆。
- 页面只组合分析组件；控制器只调用 `AnalysisApplicationService`；应用服务只通过仓储端口访问 SQLite。

## 2. 数据迁移

迁移文件：`drizzle/0009_analysis-proposals.sql`。

新增业务表：

- `analysis_batches`：保存分析类型、对象、基线、固定模型参数、状态和安全错误。
- `analysis_batch_inputs`：保存分析实际使用的不可变输入快照及来源可用状态。
- `iteration_proposals`：保存 AI 原始提案、管理员最终内容、审核结果和冲突说明。

资料被删除时不删除历史批次，改为清空输入正文并标记来源不可用，保留哈希、标题和证据关系。

## 3. Worker 与失败处理

- `analyze_learning` 进入持久任务队列，由内部 Worker 路由到分析应用服务。
- 模型结果经过 Zod 结构校验和目标、基线、证据范围业务校验后才写入提案。
- 参数快照受生成参数统一上限约束，分析最多使用 50 个证据块。
- 批次参数反序列化、模型配置变化、输出不合规或保存冲突均会把批次标为失败，避免停留在“分析中”。

## 4. 后台交互

新增组件：

- `app/components/analysis/AnalysisPanel.vue`
- `app/components/analysis/IterationProposalCard.vue`

人物成长、人物记忆和世界成长页均显示最新批次、状态、输入数量、提案数量、冲突、可编辑最终内容和人工审核入口。公共样式继续位于独立文件 `app/assets/css/theme/mind.css`。

## 5. 验证

已通过：

```text
pnpm exec vitest run tests/components/analysis-components.test.ts tests/integration/analysis-iteration.test.ts tests/architecture/layering.test.ts
pnpm exec tsc -p .nuxt/tsconfig.json --noEmit
pnpm build
```

覆盖内容：

- 增量批次只接受新输入，完整重建可重复分析全部启用输入；
- 模型不合规输出形成失败批次且不产生长期内容；
- 接受成长提案后原子创建有效记录和证据，拒绝不产生变化；
- 管理员编辑提案后提交最终内容；
- 已审核提案不能在界面重复操作；
- 新增控制器保持“控制器 → 应用服务 → 仓储”边界。

全量测试当前为 137 项通过、20 项失败。失败集中在旧反馈、备份和 OpenViking 测试仍引用方案 A 已移除的 `active_version_id`、`persona_versions`、`persona_memories` 等旧模型；将在旧反馈路径和 OpenViking 新模型投影阶段一并迁移，当前分析功能相关测试全部通过。
