# 列表原文创建与灵魂 AI 加载反馈

## 调整范围

- 人物和世界列表创建弹窗统一为“名称 + 灵魂提示词 + AI 整理开关”。
- 未选择 AI 时，按原始提示词直接创建待确认灵魂草稿，不调用模型。
- 选择 AI 时，先独立整理灵魂提示词，整理成功后再创建对象；名称始终使用用户输入。
- 新增 `POST /api/v1/soul/analyze`，只调用 `SoulApplicationService`，不直接访问仓储，也不写入人物、世界或灵魂草稿。
- 创建失败时保留弹窗输入；关闭后重新打开才清空。
- 人物和世界详情的灵魂修改保存成功后关闭弹窗，保存失败时保持弹窗和输入。
- 灵魂 AI 整理期间增加最高层级全屏模糊加载层。
- 新增独立公共旋转动画样式，人物、世界创建和灵魂整理加载图标统一使用明确 CSS 关键帧。

## 失败与一致性边界

- AI 创建路径严格执行“整理 → 创建”，整理失败时不会产生半创建对象。
- 独立整理接口只返回通过共享 Schema 校验的 `{ promptText }`，SQLite 不发生写入。
- 灵魂编辑仅在父页面刷新到服务端新草稿后关闭；请求失败未更新草稿时保持当前编辑状态。
- 手动和 AI 两种创建结果仍是未发布草稿，不改变现有发布规则。

## 测试质量审查

- 静态配对扫描识别 234 个 TypeScript 源文件和 40 个测试文件；`SoulApplicationService.ts` 与共享 Schema 均有测试引用。Vue 单文件组件不在该扫描器的 TypeScript 源文件结论内，因此使用组件测试补充验证。
- 测试缺口审查补充“AI 整理失败时不创建对象并保留输入”，覆盖半创建风险。
- 断言直接核对模型请求、创建请求、用户名称、整理结果、SQLite 表计数、弹窗状态、加载层层级、模糊背景和 CSS 动画声明。
- 聚焦测试中没有 `.only`、`.skip`、固定延时或无断言测试；CSS 文件读取用于验证 JSDOM 无法执行的动画静态契约。

## 验证结果

- 定向测试：4 个文件、38 项测试通过。
- 全量测试：37 个文件、201 项测试通过。
- `pnpm exec tsc -p .nuxt/tsconfig.json --noEmit` 通过。
- `pnpm build` 生产构建通过，并生成 `soul/analyze` 服务端路由。
- `pnpm typecheck` 仍被既有 TypeScript 7.0.2 与 vue-tsc 3.3.11 包导出兼容问题阻断：`ERR_PACKAGE_PATH_NOT_EXPORTED: ./lib/tsc`；该命令未进入源码诊断，源码已由直接 `tsc` 完成类型检查。

## 回归测试证据

- `列表创建未选择 AI 时按原始提示词直接创建人物和世界`：验证手动路径不调用模型并保存原文。
- `列表创建选择 AI 时先整理提示词再创建且保留用户名称`：验证调用顺序、整理结果和名称归属。
- `列表创建 AI 整理失败时不创建对象并保留输入`：验证失败原子性和重试体验。
- `灵魂修改成功后关闭弹窗，AI 处理期间显示可旋转的全屏加载层`：验证成功关闭、失败保持、模糊加载层和旋转动画。
- `创建前独立整理灵魂不写入人物、世界或草稿`：验证应用服务没有隐藏持久化副作用。
- 分层架构测试：验证新增控制器仍只与应用服务交互。
