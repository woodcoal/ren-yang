# 学习提示词素材进度与双模式生成

## 目标

人物成长、世界成长和人物记忆提示词统一展示当前启用素材数量及未处理数量，并显式提供增量生成与全量生成入口。

## 处理口径

- 已启用数量只统计会参加下一次提炼的当前素材。
- 未处理数量按输入类型、业务标识、正文哈希和人工重要度组成的稳定键判断。
- 只有进入 `awaiting_review` 或 `completed` 批次的素材版本视为已处理；失败批次不改变统计。
- 修改正文或重要度后稳定键变化，素材重新计为未处理。
- 禁用素材不参加统计，也不会自动改写已经发布的提示词。

## 界面调整

- 提示词编辑框上方展示“已启用多少条素材、其中多少条未处理”。
- “增量生成”只在存在未处理素材时可用。
- “全量生成”在存在启用素材时可用。
- 移除编辑框左下角原有的无模式 AI 生成图标，保留历史、刷新、Token 估算和保存发布操作。
- 人物成长、世界成长和人物记忆使用同一组件与交互契约。

## 算法边界

- 人物成长和世界成长继续使用 `extract → synthesize` 两阶段固定算法。
- 人物记忆使用独立的 `persona_memory` 固定算法：`extract（证据提取）→ 程序校验与门槛 → synthesize（完整纯文本编译）→ 人工审核发布`。
- `experience` 至少需要一条有效外部经历或任务结果；`interest` 与 `preference` 至少需要两条独立非自我输出证据；`judgment` 至少需要三条。
- 任意记忆类型如有明确 `user_feedback`，单条即可成立；`self_output` 永远不计入证据，避免人物把自己的模型输出循环强化为长期事实。
- 第三方经历只能使用 `external_record` 信号，人物任务记录禁止冒充外部经历；引用不存在的输入或信号与来源不匹配会使整个批次失败。
- 所有候选均未达到门槛时返回 `MEMORY_EVIDENCE_INSUFFICIENT`，不生成空洞草稿。
- 三类提炼都支持 `incremental` 与 `full_rebuild` 批次模式：增量模式保留当前已发布提示词作为基线并纳入新素材，全量模式基于当前全部启用素材重新编译。
- 算法生成的最终结果仍是纯文本草稿，只有管理员人工审核并发布后才进入后续人物任务。

## 验证范围

- 组件测试覆盖素材统计、增量/全量事件、无未处理素材时禁用增量，以及运行中禁止重复提交。
- 单元测试覆盖人物记忆来源校验、自我输出排除、独立证据门槛、明确反馈例外和相同事实合并。
- 集成测试覆盖世界成长和人物记忆素材从未处理到成功处理的统计变化，以及人物记忆专用算法的提取、校验、编译和草稿保存。
- 类型检查、全量测试和生产构建作为发布门禁。
