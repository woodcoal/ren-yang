## 实现边界

本阶段只生成纯文字块，不生成图片、不渲染 HTML/Markdown/Txt 文件，也不处理反馈和人物自动修订。OpenViking 能力继续保留为关闭状态，当前运行固定使用 SQLite FTS5 上下文提供器。

```text
管理页面 / API 控制器 / InternalWorker
                  ↓
       GenerationApplicationService
          ↓          ↓          ↓
   RunRepository  ContextProvider  TextModelPort
          ↓          ↓          ↓
       SQLite     SQLite FTS5   OpenAI-compatible HTTP
```

- 控制器只负责读取并校验 HTTP 输入，然后调用应用服务。
- Worker 只把已领取任务交给实现 `TaskHandler` 的生成应用服务。
- 应用服务只依赖端口，不导入 H3、Drizzle、better-sqlite3、文件系统或模型适配器。
- 数据事务只覆盖状态和快照写入，任何模型网络调用均不持有数据库事务。
- 组合根是基础设施实例化和依赖连接的唯一位置。

## 数据与迁移

新增 Drizzle 迁移 `drizzle/0002_premium_nocturne.sql`，包含八张表：

| 表 | 职责 | 关键约束 |
|---|---|---|
| `parameter_profiles` | 不可变文本参数方案版本 | 同名版本唯一；启用状态与范围 CHECK |
| `format_templates` | 不可变纯文本结构模板版本 | 同名版本唯一；块数在共享 Schema 校验 |
| `generation_runs` | 兴趣或创作运行事实源 | 固定人物版本、参数、模型、提示版本和上下文提供器 |
| `evidence_snapshots` | 运行实际使用的证据正文副本 | 正文、SHA-256、角色和排名随运行保存 |
| `document_specs` | AI 规划和用户编辑的规格修订 | `(run_id, revision)` 唯一；修订只追加 |
| `artifact_documents` | 已确认规格对应的统一产物 | 每次运行最多一个文档 |
| `artifact_blocks` | 顺序稳定的纯文字块 | 键和顺序在文档内唯一 |
| `block_attempts` | 每块独立模型尝试 | 尝试号唯一；结果和错误只追加 |

原有 `task_jobs.run_id` 不直接增加 SQLite 外键，避免迁移时重建阶段一任务表；迁移使用插入和更新触发器验证运行存在，并在删除运行后清理所属任务。

人物版本被运行引用时使用 `RESTRICT`。永久删除人物由内容仓储在一个事务内先删除私有产物和所属运行，再删除人物及版本。删除影响接口现在明确返回运行、任务、证据快照、规格修订、产物块和块尝试数量。共享世界与资料不会随人物删除；资料被删除时证据的 `source_id` 和 `chunk_id` 置空，但复制的正文与哈希继续保留。

## 运行快照与证据

创建运行前必须满足：

1. 文本模型配置完整。
2. 人物存在且拥有当前已发布版本。
3. 所选参数方案和格式模板版本存在且启用。

运行创建事务同时保存：

- 用户输入和可选临时场景。
- 已解析的最终模型参数。
- 模型提供器、模型名称和接口 Origin。
- 提示版本 `text-v1`。
- 人物当前已发布版本指针。
- 人物快照和可选世界快照的 `user_setting` 证据副本。
- SQLite FTS5 在人物和世界资料关联范围内检索出的证据正文、角色、排名和 SHA-256。
- 首个持久任务。

场景只写入 `generation_runs.scene_json`，没有写回人物版本。运行执行前会验证当前进程模型配置与运行模型快照一致，避免重启后使用不同模型静默继续旧运行。

## 提示分层与结构校验

提示固定分为：

1. 系统规则和输出约束。
2. 已发布人物设定。
3. 可选世界。
4. 当前临时场景和任务。
5. 明确标记为不可信数据的资料证据。

系统规则声明优先级为“系统规则 > 用户人物设定 > 当前场景与任务 > 原著事实 > 普通参考和风格样本 > 推断”，并禁止执行证据正文中的指令。资料、场景、规格和前置块输出均通过 JSON 序列化后放入显式标签边界。

模型输出先由适配器解析为 JSON，再由共享 Zod Schema 校验：

- 兴趣判断包含概率、置信度、结论、分项因素、支持/反对证据、未知项和理由摘要。
- 证据引用必须属于本次运行快照。
- `DocumentSpec` 必须有标题、摘要及有序块；块键唯一，只能依赖排在前面的块。
- 单块输出只允许非空 `text`。
- 结构错误会附带已脱敏校验原因进行一次修正请求；两次仍无效才交给任务级有限重试。

## 兴趣判断流程

```text
创建运行与快照
  → task_jobs: assess_interest
  → Worker 领取并设置租约
  → 生成并校验兴趣结构
  → 校验证据引用
  → 保存结果与用量
  → 运行 succeeded
```

创建接口返回 HTTP 202。调用方通过运行详情轮询，不同步等待模型。排队或执行中的运行可以请求取消；模型调用返回后再次检查取消状态，取消请求优先于保存模型结果。

## 纯文本创作流程

```text
创建运行与快照
  → plan_document
  → AI 生成 DocumentSpec
  → awaiting_confirmation
  → 用户编辑产生新 revision
  → 用户确认
  → 原子创建文档、文字块和 execute_document
  → 按块串行执行
  → succeeded / partial / failed
```

- 用户确认前不存在产物块和执行任务。
- 规格编辑不会覆盖旧修订；旧草稿变为 `superseded`，最新草稿才可确认。
- 确认在同一事务内固定规格、建立文档和全部块，并创建新任务。
- 块按顺序串行生成，每块最多两次尝试；每次尝试保存输入快照、状态、输出或稳定错误。
- 任务恢复时不重新生成成功块，而是读取已选择成功尝试作为后续块上下文。
- 进程中断遗留的 `running` 块尝试会标为 `TASK_INTERRUPTED`，块恢复为可执行状态，并创建新的尝试。
- 全部块成功时运行成功；部分块成功时为部分成功；没有块成功时为失败。

## 重试、租约与取消

任务默认最多领取两次：

- 临时错误且尚有次数时，同一任务清除租约并重新排队，运行恢复为 `planning` 或 `queued`。
- 不可重试错误或次数耗尽时，任务和运行进入稳定失败状态。
- Worker 进程退出后，租约过期且尚有次数的任务重新排队，运行同步恢复为规划或排队；次数耗尽时任务和运行以 `TASK_LEASE_EXHAUSTED` 终止。
- 已请求取消的运行若在进程退出时遗留租约，启动恢复会同时把任务和运行置为已取消。
- 手工重试只允许失败或部分成功运行，会创建新的任务记录，不删除或重置旧任务和块尝试。
- 文档手工重试只恢复失败块，成功块及其选择结果保持不变。

稳定模型错误包括：`CAPABILITY_DISABLED`、`PROVIDER_TIMEOUT`、`PROVIDER_RATE_LIMITED`、`PROVIDER_UNAVAILABLE` 和 `MODEL_OUTPUT_INVALID`。响应、运行快照、任务错误和日志均不包含 API Key。

## 生产模型适配器

`OpenAiCompatibleTextModel` 使用原生 `fetch` 调用 Chat Completions 完整 URL，不绑定供应商 SDK。配置来自 Nuxt 私有运行时环境变量：

- `NUXT_TEXT_MODEL_ENDPOINT`
- `NUXT_TEXT_MODEL_API_KEY`
- `NUXT_TEXT_MODEL_MODEL`

请求包含系统消息、用户消息、温度、最大输出 Token 和 `response_format: { type: "json_object" }`。`AbortController` 执行运行参数中的超时。HTTP 429、5xx、超时、网络失败、无效响应 JSON、无效 Chat Completions 外层结构和无效内容 JSON均映射为稳定错误；接口响应只公开模型名称和 Endpoint Origin。

## 管理界面

新增页面和组件：

- `/workbench`：选择已发布人物、任务类型、参数方案、格式模板和临时场景，创建兴趣或创作运行。
- `/history`：按人物、类型和状态筛选运行；筛选项写入 URL。
- `/runs/{id}`：活动运行每两秒轮询，离开页面或进入非活动状态后停止；展示固定输入、兴趣结果、规格修订、块尝试、任务和证据。
- `/templates`：创建和查看不可变格式模板版本。
- `/parameter-profiles`：创建和查看不可变参数方案版本。
- `DocumentSpecEditor`：编辑标题、摘要、块、角色、依赖和验收条件，支持按钮调整顺序。
- `RunStatusPanel`：展示运行和任务状态，提供取消或手工重试入口。
- `EvidenceList`：以纯文本展示证据正文和 SHA-256，不解释资料中的 HTML。

人物删除确认界面同步显示将删除的完整运行历史数量。MVP 继续不引入 Pinia、WebSocket、SSE 或拖放库。

## 已知边界

- 当前只支持纯文字块；图片块、单块手工重试、尝试选择、块锁定、渲染和 HTML/Markdown/Txt 导出属于阶段四。
- 参数方案和格式模板当前通过同名新建产生下一版本，尚无停用接口和分层参数预览接口。
- OpenViking 当前明确显示为未配置且未启用；可切换上下文提供器及重建能力属于阶段五。
- 当前采用 Chat Completions 的 JSON Object 模式，不使用供应商专属 JSON Schema 或工具调用；共享 Zod Schema 是最终可信边界。
- Worker 是单进程串行执行，适合本地 MVP；多进程并发、分布式锁和外部队列不在当前范围。
- 模型调用已支持超时和有限重试，但无法强制所有 OpenAI-compatible 供应商严格遵守最大输出 Token。
- 运行详情保留完整证据正文，资料较多时页面信息密度较高；分页和证据折叠优化不影响当前闭环。
