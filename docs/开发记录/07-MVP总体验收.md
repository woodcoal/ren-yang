## 完成度审计修复一：自然语言人物草稿

对照产品范围唯一事实源后确认，原实现只能手工提交完整结构化人物快照，没有实现“从自然语言创建结构化人物候选档案”。本次补齐独立编辑闭环：

1. 新增 `POST /api/v1/personas/draft`，控制器只解析共享 Schema 并调用生成应用服务。
2. 应用服务读取可选已发布世界与最多 8 项选定资料，通过文本模型生成 `name` 和完整人物快照。
3. 用户明确人设高于参考资料；只有 `canon_fact` 可作为原著事实，证据不足字段保持未知。
4. 草稿不写数据库、不创建版本、不自动发布；页面只把结果填入结构化表单，必须由用户检查并保存。
5. 单项资料和世界正文分别限制为前 5000 字和前 10000 字，发生截断时返回并展示明确提示。
6. 文本模型未配置时 AI 按钮禁用，原手工创建路径保持完整。

组件按职责拆分：创建页只编排请求，`PersonaDraftAssistant` 采集自然语言与参考上下文，`PersonaForm` 只编辑和校验结构化候选。分层测试继续保证控制器不访问模型实现，应用服务只依赖端口。

验证结果：

- 类型检查通过。
- 23 个测试文件、113 项测试全部通过。
- 新测试覆盖资料去重、事实角色提示、生成不落库、模型关闭、草稿助手事件和人工提交门禁。
- Nuxt/Nitro 生产构建通过，并生成静态优先的 `personas/draft.post` 服务端路由。

本项只证明软件契约；自然语言草稿的实际内容质量仍纳入真实文本模型手工验收。

### 主流程一：初始化与登录

1. 从已迁移但无管理员的数据库启动生产服务。
2. 本机创建唯一管理员。
3. 退出并使用密码重新登录。
4. 后续业务接口只接受有效 Cookie 会话。

结果：通过。

### 主流程二：人物、资料与兴趣

1. 创建学院档案事实资料。
2. 创建原创人物及候选版本。
3. 发布人物版本，再显式关联资料。
4. OpenViking 关闭时创建兴趣运行。
5. Worker 通过 SQLite FTS5 检索，保存人物设定和 `canon_fact` 证据快照。
6. 结构化返回概率、信心、结论、因素和不确定性。

结果：通过；运行固定记录 `contextProvider=sqlite_fts5`。

### 主流程三：规格、文本块与三格式导出

1. 创建不含图片的文档规划运行。
2. AI 规格进入 `awaiting_confirmation`，未确认时 Worker 不执行正文。
3. 规格只包含文字块，用户确认后串行执行。
4. 每个成功块保存独立尝试并选择一个历史结果。
5. 同一组选中块渲染 HTML、Markdown、Txt。
6. 三种格式分别下载，内容非空，HTML 不包含脚本。

结果：通过，共完成 3 次纯文本格式导出。

### 主流程四：反馈、评测、发布与回滚

1. 对已完成文档提交显式长期人物反馈。
2. 模型建议目标为人物，用户确认修改高风险 `summary` 字段。
3. 系统创建候选记忆、不可变候选版本和高风险修订提案。
4. 创建固定人物评测用例并由后台任务执行。
5. 必需词、禁用词和分数门禁全部通过。
6. 高风险提案没有自动发布，必须提交 `confirmed=true` 人工发布。
7. 发布后把人物当前指针回滚到基础版本。

结果：通过；候选版本与基础版本均保留，当前指针正确回滚。

### 主流程五：备份恢复

1. 在线创建一致性备份。
2. 停止生产服务。
3. CLI 只读验证清单、哈希、迁移和 SQLite。
4. CLI 原子恢复并保留回退目录。
5. 使用同一会话密钥重启，恢复前 Cookie 访问审计接口返回 HTTP 401。
6. 重新登录后继续完成 OpenViking 和图片组合验收。

结果：通过；最终审计包含 `data_restored`。

## 能力组合

### OpenViking 关闭、图片模型关闭

- 纯文本兴趣与文档运行通过 SQLite FTS5 完成。
- 请求 `includeImages=true` 返回 HTTP 422 和 `CAPABILITY_DISABLED`。
- 图片能力缺失不影响纯文本规格、块执行和三格式导出。

结果：通过。

### OpenViking 开启、图片模型开启

- OpenViking 健康检测通过。
- 从 SQLite 唯一资料事实全量重建外部索引：1 项资料、1 项成功、0 项失败。
- 新兴趣运行固定记录 `contextProvider=openviking`，远端结果复制为 SQLite 证据快照。
- 图文规格包含标题、图片和正文块，图片响应经魔数校验后保存为本地 PNG。
- HTML、Markdown、Txt 引用同一图片资产，三种带资源导出均成功。
- OpenViking 检索模拟 HTTP 503 时，应用返回 `PROVIDER_UNAVAILABLE`，运行数量不增加，没有静默改用 SQLite。

结果：通过，共完成 3 次带图片格式导出。

本机 OpenViking 插件的真实健康接口另行确认：服务已初始化，存储为 VikingFS。为避免污染用户现有记忆库，真实服务只做健康检查；应用读写协议使用隔离替身验收。

## 异常退出与任务恢复

1. 让兴趣任务进入 `running`，并保持文本供应商请求未完成。
2. 对生产进程发送 `SIGKILL`，不执行正常关闭钩子。
3. 把测试任务租约调整为已过期，模拟真实等待超过租约时间。
4. 保持同一数据目录重启生产服务。
5. 单实例锁识别原 PID 已退出并清理失效锁。
6. Worker 恢复过期任务，以第二次尝试完成原任务。

结果：通过；运行最终 `succeeded`，原任务 `attemptCount=2`，没有创建重复业务运行。

## 永久删除演练

1. 创建并发布一次性原创人物。
2. 删除前读取影响范围，确认 `canDelete=true`、版本数为 1。
3. 执行永久删除，返回 HTTP 204。
4. 再次读取返回 HTTP 404。
5. 最终审计包含 `persona_deleted`。

结果：通过。

## 真实模型待验项

```dotenv

NUXT_IMAGE_MODEL_API_KEY=

```

待配置后必须记录供应商、模型名称、非敏感接口来源、输入、参数、规格和结果，并验证：

1. 原创人物在无资料时保持稳定风格且承认未知。
2. 资料型人物引用正确证据，不把推断称为原著事实。
3. 混合人物面对冲突时遵循系统、人物设定、场景和资料角色优先级。
4. 同一人物完成兴趣判断和指定格式图文生成。
5. 用户修改规格后，实际输出遵循确认版本。
6. 图片供应商失败时文字块保留，运行呈现部分成功。
7. 长期反馈不直接改写已发布版本，高风险字段必须人工确认。
