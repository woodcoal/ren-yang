# 启动资料可见性与分析组件修复

## 故障现象

- 人物或世界详情页服务端渲染时提示 `Failed to resolve component: AnalysisAnalysisPanel`。
- 启动后界面被误判为资料列表丢失。

## 诊断证据

- `data/app.sqlite` 完整性检查结果为 `ok`。
- SQLite 中仍有 16 项资料、5 条人物资料关系、10 条世界资料关系。
- 当前分页资料接口请求返回 HTTP 200；直接执行同等分页查询能够返回第一页 10 项资料。
- Nuxt 生成的组件清单将 `app/components/analysis/AnalysisPanel.vue` 注册为 `AnalysisPanel`，不会重复保留相邻的 `analysis` 名称段。
- 人物和世界详情页错误使用了 `AnalysisAnalysisPanel`，因此 Vue 只能把它当作未解析组件。

## 调整内容

- 人物详情页和世界详情页显式导入 `AnalysisPanel`，并统一使用 `<AnalysisPanel>`。
- 增加回归测试，禁止详情页再次出现错误的 `AnalysisAnalysisPanel` 名称。
- 未执行清库、迁移或资料重建；SQLite 事实数据保持不变。

## 验证标准

- 定向测试：2 个文件、5 项测试通过；资料分页组件能够渲染接口返回的资料项。
- 全量测试：36 个文件、191 项测试通过。
- `pnpm build` 通过。
- 源码、Nuxt 缓存和生产构建产物中均不再包含 `AnalysisAnalysisPanel`；服务端详情页直接引用 `AnalysisPanel` 模块。
- `pnpm typecheck` 仍在读取项目源码前被 TypeScript 7.0.2 与 vue-tsc 3.3.11 的包导出兼容问题阻断，错误为 `ERR_PACKAGE_PATH_NOT_EXPORTED: ./lib/tsc`；本次变更未引入该工具链问题。
