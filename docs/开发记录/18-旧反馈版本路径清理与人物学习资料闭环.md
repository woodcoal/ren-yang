# 旧反馈版本路径清理与人物学习资料闭环开发记录

## 阶段目标

移除反馈直接生成固定字段人物版本和候选记忆的旧路径，使运行反馈只能在用户明确确认后成为人物反馈资料，再进入现有成长分析与人工审核闭环；同时物理删除统一心智模型已经替代的旧表和失效接口。

## 完成内容

### 1. 反馈人物学习规则

反馈流程调整为：

```text
提交运行反馈
→ AI 只建议反馈用途
→ 用户确认“作为人物学习资料”
→ SQLite 原子创建 persona_feedback_sources
→ 可选投影到人物 Peer Resource
→ 用户手动发起人物成长分析
→ AI 生成成长候选
→ 用户审核后才可能生效
```

确认人物学习时：

- 从运行固定的 `soul_versions.persona_id` 校验所属人物；
- 原子写入 `feedback_resolutions` 和 `persona_feedback_sources`；
- 反馈资料使用 `source_type = 'run_feedback'`、`source_id = feedbackId`；
- 保存正文 SHA-256、启用状态和审计事件；
- OpenViking 启用时排队人物反馈资料 Resource 投影；
- 不创建灵魂草稿、灵魂版本、成长或记忆；
- 同一反馈只能确认一次，重复请求不会创建重复资料。

反馈分类提示升级为 `feedback-classification-v2`，明确 AI 不能因自由文本评价自行修改人物灵魂、成长或记忆。

### 2. 退出旧候选版本与评测运行

删除以下旧能力：

- 固定八字段人物补丁；
- 反馈直接创建候选人物版本；
- 反馈直接创建候选记忆；
- 旧提案自动发布和人工发布；
- `evaluate_proposal` Worker 任务；
- 旧人物记忆单条状态接口；
- `/api/v1/revision-proposals/**`；
- `/api/v1/evaluation-runs/**`；
- `/evaluations/[id]` 页面及旧提案、评测结果组件。

人物回归用例表、接口和管理表单保留，供后续基于自由章节的灵魂修改提案评测复用。后续实现不得恢复旧固定字段版本路径。

### 3. 数据迁移

新增：

- `drizzle/0012_steep_umar.sql`；
- `drizzle/meta/0012_snapshot.json`。

迁移物理删除：

- `revision_proposals`；
- `candidate_memories`；
- `evaluation_runs`；
- `evaluation_results`；
- `persona_growth_records`；
- `persona_memories`。

保留并继续使用：

- `feedback_events`、`feedback_suggestions`、`feedback_resolutions`；
- `persona_feedback_sources`；
- `growth_records`、`growth_revisions`；
- `memory_records`、`memory_revisions`；
- `analysis_batches`、`iteration_proposals`；
- `evaluation_cases`。

### 4. 后台和文档

- 运行详情把“长期人物”改成“作为人物学习资料”，并说明仍需成长分析和人工审核；
- 学习中心移除失效修订提案列表，只展示反馈记录和回归用例；
- 仪表盘不再请求已删除的旧修订提案接口；
- 删除失效评测详情路由映射；
- 更新接口、反馈迭代和后台页面文档，明确当前能力与后续自由章节灵魂提案的边界；
- 未新增公共样式，继续使用已有独立样式文件和组件工具类。

## 分层约束

- API 控制器只调用 `FeedbackApplicationService`；
- 反馈应用服务只通过 `FeedbackRepository`、模型、标识、时钟和同步队列端口访问数据与外部系统；
- `SqliteFeedbackRepository` 在短事务内确认反馈并创建人物反馈资料；
- Worker 路由不再依赖反馈服务；
- SQLite 继续是唯一业务事实源，OpenViking 只接收可重建投影。
