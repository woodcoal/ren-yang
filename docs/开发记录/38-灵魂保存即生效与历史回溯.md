# 灵魂保存即生效与历史回溯

## 调整范围

- 人物和世界列表移除“设定状态”及待确认统计，只保留启用或禁用状态。
- 新建人物和世界默认启用，初始提示词直接写入 `soul_versions` 并设为当前版本，不再创建初始草稿。
- 灵魂详情改为页面内大文本编辑框；左下角提供 AI 整理和历史入口，右下角提供保存按钮。
- AI 整理只回填编辑框，不自动保存；处理期间显示最高层级全屏模糊加载层和持续旋转图标。
- 历史选择只回填编辑框；再次保存时创建以所选历史为父版本的新版本，不移动旧版本指针。
- 新增人物和世界灵魂 `PUT` 接口，保存后立即生成不可变历史并切换当前版本。
- 旧草稿接口继续兼容已有客户端，但已退出后台主流程。

## 数据与事务

- `ContentApplicationService` 在创建对象前规范化初始提示词并检查对应 Token 预算。
- `SqliteContentRepository` 在同一事务中创建对象、初始灵魂版本并写入当前版本指针。
- `SoulApplicationService.saveVersion` 校验对象及基础版本归属，完成文本规范化和 Token 预算检查。
- `SoulRepository.saveSoulVersion` 在同一 SQLite 事务中插入不可变版本、切换当前指针并写入 `soul_version_saved` 审计记录。
- `drizzle/0004_soul_save_immediately.sql` 沿用现有草稿 UUID，把草稿提升为当前历史版本，保留基础版本关系并清空兼容草稿表。

## 架构边界

- 新增控制器只解析路径和请求体，并调用 `SoulApplicationService.saveVersion`。
- 应用服务只通过 `ContentRepository`、`SoulRepository`、Token 计数、标识和时钟端口访问外部能力。
- 页面不直接操作数据层；AI 整理和版本保存使用两个明确接口，避免模型成功即隐式生效。

## 测试质量审查

- 组件测试验证直接编辑、AI 请求与回填、全屏加载层、历史回填、保存事件和服务端版本同步。
- 集成测试验证创建即生效、默认启用、不可变历史、回溯父版本、迁移、审计事务和草稿清空。
- 测试缺口审查补充 Token 精确上限、超限无副作用和跨对象历史归属校验。
- 实际注入 3 个错误变体：两处 `>` 改为 `>=`、移除基础版本归属检查；新增测试均能使对应变体失败。所有变体已经撤销，恢复后定向测试通过。
- 新增测试同时使用错误码、深层对象、当前版本指针、版本数量和数据库计数断言，没有只依赖存在性或真值判断。

- 定向测试：5 个文件、47 项通过；补充边界测试后内容管理集成测试 23 项通过。
- 全量 Vitest：37 个文件、203 项通过。
- `pnpm exec nuxt prepare`：通过。
- `pnpm exec tsc -p .nuxt/tsconfig.json --noEmit`：通过。
- `pnpm build`：通过，并生成两个人物/世界灵魂保存路由。
- Playwright 主流程：1 项通过，覆盖创建即生效、资料关联、灵魂保存、历史弹窗、人物任务和三格式导出。
