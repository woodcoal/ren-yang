## 实现边界

本阶段只建立可追溯的本地事实源，不模拟人物，也不调用外部服务。事实关系如下：

```text
World 0..1 ───── 0..N Persona
  │                       │
  ├── WorldVersion        ├── PersonaVersion
  └── SourceMaterial ─────┘
              │
              └── SourceChunk ── FTS5
```

- 人物支持 `original`、`source_based`、`hybrid` 三种来源。
- 原创和混合人物无需资料；资料型人物至少关联一项资料。
- 人物可以不关联世界；删除世界前必须先解除全部人物关联。
- 资料独立保存，通过关联表复用于人物和世界。
- SQLite 是唯一业务事实源；本阶段没有 OpenViking 数据或开关。

| `source_chunks` | 顺序稳定的检索切片 | `(source_id, ordinal)` 唯一；哈希 CHECK |
| `persona_sources` | 人物与资料关联 | 联合唯一；资料删除受限 |
| `world_sources` | 世界与资料关联 | 联合唯一；资料删除受限 |

迁移还创建外部内容 FTS5 虚表 `source_chunks_fts`，采用 `trigram` 分词器，使连续中文短语可检索。插入、更新、删除触发器与 `source_chunks` 同步。少于三个字符的查询使用转义后的参数化 `LIKE`，避免 trigram 的最短长度限制。

所有主键由应用生成 UUID，时间为 UTC Unix 毫秒。人物/世界创建、初始版本和初始资料关系在同一短事务内完成；版本发布和当前指针切换在同一短事务内完成；资料正文与切片替换在同一短事务内完成。

## 版本规则

### 人物

人物快照固定分为：

- 人物定位。
- 身份事实。
- 兴趣偏好。
- 价值与动机。
- 表达风格。
- 外观描述。
- 视觉风格。
- 约束。

初始档案和后续修订都先创建 `candidate`。发布只允许执行一次，原子改为 `published` 并切换人物当前指针。已发布版本没有更新接口。回滚只验证目标属于该人物且已发布，然后修改 `personas.active_version_id`；后续版本、父链、发布时间和快照全部保留。

### 世界

世界名称和摘要是可变元数据，规则与背景正文保存在不可变版本快照。候选、发布、差异和回滚规则与人物一致。

版本差异由应用服务按稳定字段生成，不向界面暴露数据库 JSON。人物显示八个档案字段的变化；世界显示正文变化。

## 资料处理与安全

支持三种输入：

- 粘贴文本。
- UTF-8 `.txt`。
- UTF-8 `.md` 或 `.markdown`。

服务端执行以下校验：

- 单文件和规范化正文最大 2,000,000 字节。
- multipart 有 Content-Length 时先拒绝超过 2.1 MB 的请求。
- 一次必须且只能提交一个文件。
- 扩展名仅允许 TXT 或 Markdown，媒体类型必须在白名单内。
- UTF-8 使用严格解码，不替换非法字节。
- 拒绝 NUL 字符、空文件和空正文。
- 统一 BOM、CRLF 和首尾空白后计算 SHA-256。
- 文件名不进入存储路径；原文件使用资料 UUID 命名。
- 删除文件只接受 `sources/{UUID}.txt|md` 受控路径。

切片优先按 Markdown 标题和空段落划分，单片目标上限 1,200 字符；超长段落确定性硬切分。每个切片保存正文、标题上下文、序号和 SHA-256。检索响应复制这些字段，可在阶段三创建运行时原样写入真正的 `EvidenceSnapshot`。

编辑文件导入资料的正文时，资料会明确转为 `paste`，数据库事务成功后删除旧原始文件，避免数据库正文与文件内容不一致。

## 应用分层

```text
Nuxt 页面 / API 控制器
          ↓
ContentApplicationService
          ↓
ContentRepository / SourceContentProcessor / SourceFileStorage
          ↓
SQLite / FTS5 / 本地 sources 目录
```

- API 控制器只读取路由、查询、JSON 或 multipart，使用共享 Zod Schema 校验，然后调用 `ContentApplicationService`。
- 应用服务只依赖领域类型和端口，不导入 H3、Drizzle、better-sqlite3 或文件系统。
- `SqliteContentRepository` 负责短事务和参数化 SQL。
- `NodeSourceContentProcessor` 负责安全解码、规范化、哈希和切片。
- `LocalSourceFileStorage` 负责受控资料文件路径。
- `ApplicationRuntime` 仍是唯一组合根；控制器没有跨层访问数据层。

## API

新增受登录保护的 `/api/v1` 接口：

- 人物：列表、创建、详情、元数据修改、候选版本、发布、差异、回滚、删除影响和永久删除。
- 世界：列表、创建、详情、元数据修改、候选版本、发布、差异、回滚、删除影响和永久删除。
- 资料：列表、粘贴创建、文件导入、详情、正文修改、FTS5 检索、建立/解除关联、删除影响和永久删除。

关键错误使用稳定代码：`RESOURCE_NOT_FOUND`、`VERSION_CONFLICT`、`SOURCE_REQUIRED`、`RESOURCE_IN_USE` 和 `VALIDATION_FAILED`。删除前必须调用影响分析；世界仍有人物、资料仍有关联时，删除应用服务再次校验并返回 HTTP 409，不依赖界面自觉。

## 管理界面

新增桌面优先且可窄屏查看的工作台布局：

- 主导航：仪表盘、人物、世界、资料。
- 仪表盘：三类资源数量和 SQLite/Worker 状态。
- 人物：创建、来源模式、可选世界和资料、元数据、候选版本、发布、回滚、字段差异、关联资料和删除确认。
- 世界：创建、元数据、候选版本、发布、回滚、正文差异、关联人物/资料和删除阻断。
- 资料：粘贴/文件导入、中文证据检索、正文与哈希、切片、人物/世界关联、解除关联和删除确认。

页面使用 `useFetch` 读取服务端事实，写操作使用显式 `$fetch`，不引入 Pinia。表单复用共享 Zod Schema，服务端仍重复校验。不可信资料只通过文本插值或 `<pre>` 展示，没有使用 `v-html`。

永久删除采用两步交互：先读取影响范围，再要求勾选确认。人物删除不删除共享世界和资料；世界有关联人物时禁止删除；资料有任何人物或世界关联时禁止删除。

## 已知边界

- `EvidenceSnapshot` 必须属于一次不可变生成运行；本阶段尚无 `generation_runs`，因此只返回带正文和哈希的证据候选。阶段三创建运行时再复制入证据快照，避免建立无所有者的提前表结构。
- 人物快照字段目前使用可审阅的长文本，而不是 AI 自动抽取的逐事实结构；模型抽取属于阶段三。
- 资料更新是整份正文替换和整份重切片，不提供局部切片编辑。
- 资料角色已保存，但最终检索重排和“用户设定 > 原著事实 > 普通资料 > AI 推断”的提示组合将在阶段三实现；本阶段没有 AI 推断。
- 中文 FTS5 使用 trigram，适合连续短语检索；复杂布尔查询、同义词和语义检索不在本阶段范围。
- multipart 在解析后仍执行硬大小校验；已提供 Content-Length 预拒绝。MVP 是登录保护的单机应用，本阶段未实现流式上传解析。
- 原文件删除发生在数据库更新或删除成功后；极端文件系统故障可能留下不再引用的孤儿文件，但不会丢失 SQLite 事实。阶段六存储审计再处理孤儿清单。
- 管理界面移动端支持查看和简单确认，不承诺舒适完成长档案编辑。
