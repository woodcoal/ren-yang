## 实现边界

本阶段坚持以下边界：

- 只支持单主机、单 Node.js 进程和本地文件系统中的 SQLite。
- SQLite 与引用文件是唯一可恢复业务事实；OpenViking 是恢复后重建的外部索引。
- 管理面板只允许在线创建备份，恢复必须由有主机权限的维护人员在应用停机后执行 CLI。
- 不实现自动定时备份、远端对象存储、多实例协调、维护模式或 SQLite 网络文件系统。
- 不把模型密钥、会话密钥、日志、缓存、未引用文件或 OpenViking 数据写入备份。

## 一致性备份

新增 `BackupApplicationService` 和 `BackupPort`，基础设施适配器使用 `better-sqlite3 backup()` 从活动 WAL 数据库生成一致副本。备份目录先在隐藏的 `.pending` 目录构建，全部文件和清单验证通过后再原子改名为完成目录；失败会清理未完成目录。

固定格式如下：

```text
backup-<ISO 时间>-<UUID>/
├── manifest.json
├── app.sqlite
├── sources/<sourceId>.txt|md
└── artifacts/<runId>/assets/<assetId>.png|jpg|webp
```

清单记录格式版本、备份标识、创建时间、当前迁移数量，以及每个文件的受控相对路径、媒体类型、字节数和 SHA-256。备份只根据一致副本中的数据库引用收录资料原文件和图片资产，不扫描并打包数据目录中的其他内容。

在线备份完成后把副本切换为 `journal_mode=DELETE`，并移除副本可能产生的 WAL/SHM 边车。验证器递归枚举备份目录，拒绝符号链接、特殊节点和任何未列入清单的额外文件，防止文件夹被夹带未校验内容。

## 验证与停机恢复

提供三个本机维护命令：

```bash
pnpm backup
pnpm restore:validate -- <备份目录>
pnpm restore -- <备份目录>
```

只读验证依次检查：

1. 清单 JSON 结构、格式版本、重复路径和迁移数量。
2. 所有相对路径均符合固定白名单，不能使用绝对路径、反斜杠或路径穿越。
3. 清单文件均为普通文件，大小和 SHA-256 完全一致。
4. 目录中不存在清单外文件、符号链接或特殊节点。
5. SQLite `integrity_check`、外键和 Drizzle 迁移数量正常。
6. 数据库实际引用、清单路径和媒体类型完全一致。

恢复流程固定为：

```text
只读验证
  → 同文件系统 staging 目录完整复制
  → 重建 FTS、撤销会话、标记 OpenViking 待重建
  → 当前数据目录改名为 rollback
  → staging 原子改名为活动数据目录
```

恢复前通过数据目录实例锁确认应用已经停止。切换失败时立即把回退目录改回活动目录；切换成功后永久保留带时间标识的回退目录，由维护人员验收后自行处理。

恢复数据库会在一个事务中：

- 重建 `source_chunks_fts`。
- 递增唯一管理员 `credential_version`，使恢复前全部 Cookie 会话失效。
- 把 OpenViking 同步记录改为 `pending`，说明需要全量重建。
- 写入 `data_restored` 关键审计。

## 单实例与生命周期

`ApplicationInstanceLock` 先写入包含当前 PID 的完整候选文件，再通过同文件系统硬链接原子发布进程锁，拒绝第二个进程共享同一 SQLite；只在确认原 PID 已不存在时清理失效锁。

运行时关闭顺序为停止 Worker、关闭 SQLite、释放实例锁。清理使用嵌套 `finally`，前一步发生异常也不会跳过后续资源释放。

生产黑盒发现 Nitro 已经监听后，插件初始化异常只形成 `unhandledRejection`，第二实例可能短暂继续运行。启动插件现已在配置校验、运行时构造或启动失败时关闭已创建运行时、输出不含内部细节的固定错误，并以退出码 1 终止进程。

## 资源限制

新增全局 API 请求正文实际字节限制。中间件在 H3 解析正文前读取并计数原始流，超限返回 HTTP 413 和稳定错误码 `REQUEST_TOO_LARGE`，因此没有 `Content-Length` 的分块传输也不能绕过。默认上限为 2,200,000 字节。

资料与图片写入前由 `NodeStorageCapacityGuard` 使用 `statfs` 检查可用空间。预计写入后少于保留阈值时返回 `INSUFFICIENT_STORAGE`；底层 `ENOSPC` 同样映射为该稳定错误。默认必须保留 100 MiB。

阶段一至五已有的限制继续生效：

- 资料原文件不超过 2 MB。
- 图片资产不超过 10 MiB，且只接受 PNG、JPEG、WebP。
- 模型调用具有超时、最大输出和结构化结果块数限制。
- 持久任务具有租约、最大尝试次数和可恢复状态机。
- 管理接口列表和审计查询具有固定最大数量。

新增部署配置：

```dotenv
NUXT_LIMITS_REQUEST_BODY_BYTES=2200000
NUXT_LIMITS_MINIMUM_FREE_DISK_BYTES=104857600
NUXT_LOGGING_MAXIMUM_FILE_BYTES=5242880
NUXT_LOGGING_RETENTION_DAYS=14
```

## 日志与审计

`LocalStructuredLogger` 写入本地 JSON Lines 日志。请求完成记录只包含时间、级别、事件、请求标识、HTTP 方法、路径、状态码和耗时，响应同步返回 `X-Request-Id`。

日志器不会记录请求正文、Cookie、认证头、提示词、模型输入或模型输出。对象字段递归检查敏感键，字符串额外脱敏 Bearer 令牌、`sk-*` 形式凭据和 URL 用户信息。活动日志达到大小阈值后轮转，并按配置天数清理旧文件。

新增 `audit_events` 表和只读审计列表接口。以下关键动作写入 SQLite：

- 管理员创建与密码重置。
- 人物、世界版本发布与回滚。
- 人物、世界和资料永久删除。
- 人物修订提案发布与拒绝。
- 数据恢复。

发布、回滚、删除、密码重置等动作的审计与对应业务状态位于同一个 SQLite 事务，避免业务成功但审计缺失。审计详情只保存标识、动作和必要结构，不保存密码、正文、提示或模型输出。

## HTTP 安全

- 浏览器修改请求必须同源；跨站 `Origin` 返回 HTTP 403 和 `CROSS_SITE_REQUEST_REJECTED`。
- 没有 `Origin` 的本机维护脚本仍可调用 API。
- 首次管理员创建同时检查直接套接字地址、`X-Forwarded-For` 和 `X-Real-IP`。
- 任一代理转发地址指向远端时，首次设置返回 `LOCAL_SETUP_REQUIRED`。
- 不可信人物、资料、日志和模型文本只通过 Vue 文本插值展示，源码不存在 `v-html`。
- 错误响应使用稳定错误码，不回显堆栈、绝对路径或供应商响应正文。

## 应用分层

```text
页面 / API 控制器
        ↓
认证、内容、生成、反馈、备份、系统应用服务
        ↓
仓储、备份、存储容量、模型和上下文端口
        ↓
SQLite / 本地文件 / OpenAI-compatible HTTP / OpenViking HTTP

内部 Worker
        ↓
WorkerApplicationService → TaskRoutingApplicationService
        ↓
生成 / 反馈评测 / 上下文同步应用服务
```

- 控制器只解析输入并调用请求上下文中的应用服务。
- 应用服务只依赖端口，不导入 H3、Drizzle、better-sqlite3 或基础设施目录。
- Worker 只调用任务应用服务，不访问 SQLite、文件存储或外部 HTTP 适配器。
- `ApplicationRuntime` 是唯一组合根，负责创建并连接具体适配器。
- 恢复 CLI 通过同一个备份应用服务执行，不绕过应用层直接操作数据库。

## 生产黑盒

使用真实 `.output/server/index.mjs`、真实 SQLite 和临时数据目录完成以下检查：

1. 未登录访问审计接口返回 HTTP 401。
2. 跨站修改设置请求返回 HTTP 403 和 `CROSS_SITE_REQUEST_REJECTED`。
3. 本机首次创建管理员、Cookie 会话和重新登录成功。
4. 转发远端地址的首次设置返回 HTTP 403 和 `LOCAL_SETUP_REQUIRED`。
5. 在线备份返回 HTTP 201；最终备份目录只有 `manifest.json` 和 `app.sqlite`，没有 WAL/SHM。
6. 超限请求返回 HTTP 413 和 `REQUEST_TOO_LARGE`。
7. 审计接口返回管理员创建记录。
8. 第二实例和缺失会话密钥的无效配置均输出固定安全错误，并以退出码 1 终止。
9. 活动实例执行恢复被拒绝，当前 SQLite 保持不变。
10. 停机后 `restore:validate` 和 `restore` 成功，回退目录保留。
11. 恢复前 Cookie 访问审计接口返回 HTTP 401；重新登录后可见 `data_restored` 记录。
12. 数据目录、备份与日志未检出本次黑盒使用的管理员明文密码或会话密钥；请求日志只包含受控元数据。

测试中先发现并修复两个真实问题：

- Nitro 插件启动失败没有自动终止监听进程。
- SQLite 在线副本验证后残留未入清单的 WAL/SHM 文件。

针对第二个问题增加了备份目录洁净性校验和额外文件拒绝回归测试。最终生产黑盒重新构建并完整复测恢复闭环。

## 已知边界

- 在线备份当前为同步管理操作，没有后台备份任务和进度查询；适合 MVP 单机数据规模。
- 备份保存在活动数据目录下不等于异地灾备，必须由维护人员复制到其他设备并再次验证。
- 回退目录不会自动删除，避免错误清理唯一可恢复数据；容量由维护人员负责。
- 备份格式只接受当前迁移数量，不支持用旧程序直接恢复新迁移备份。
- 恢复要求数据目录与 staging 位于同一文件系统，以保证最终目录改名原子性。
- 恢复后只标记 OpenViking 待重建，不自动执行可能耗时且依赖外部服务的重建。
- 日志仅保存在单机文件系统，没有集中采集、告警或指标后端。
- 请求同源检查不能替代 HTTPS、反向代理来源限制和主机防火墙。
- 自动定时备份、远端对象存储和异地灾备属于 MVP 后扩展。
