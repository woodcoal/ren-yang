## 已实现内容

### 工程与界面

- 创建 Nuxt 4、TypeScript 严格模式和 pnpm 工程。
- 接入 Nuxt UI，提供浅色和深色主题。
- 创建首次设置页、登录页和工程状态首页。
- 页面是组合层；登录和首次设置表单是独立组件。
- 全局路由中间件依据服务端设置状态和登录状态导航。
- 前端共享 Zod Schema，不使用 Pinia。

### 认证

- 数据库通过固定主键和唯一索引保证最多一名管理员。
- 首次创建管理员只接受直接回环地址请求。
- 密码使用 nuxt-auth-utils 同源的 Scrypt 实现，不保存明文。
- 会话由 nuxt-auth-utils 密封 Cookie 承担。
- 每次受保护请求都比较数据库凭据版本；密码重置后旧会话立即失效。
- 登录失败统一返回 `INVALID_CREDENTIALS`，不泄露用户名是否存在。
- 提供不回显密码的本机交互式重置命令。

### SQLite

- Drizzle 初始迁移创建 `administrators` 和 `task_jobs`。
- 启动和迁移命令均设置：
  - `foreign_keys = ON`。
  - `journal_mode = WAL`。
  - `busy_timeout = 5000`。
- 运行时自动创建 `sources`、`artifacts`、`exports`、`backups` 和 `logs` 子目录。
- 健康检查执行 SQLite `integrity_check`，浏览器响应不暴露数据库绝对路径。
- 系统未安装 `sqlite3` 命令行工具，不影响内嵌 SQLite 运行。

### Worker

- Nuxt/Nitro 与唯一 Worker 位于同一 Node.js 进程。
- Worker 只调用 `WorkerApplicationService`。
- 任务领取使用 SQLite 立即事务、条件更新、尝试次数和租约。
- 启动时恢复过期租约；达到最大尝试次数的任务转为失败。
- 关闭 Nitro 时停止新轮询、等待当前轮询结束，再关闭数据库。
- 阶段一没有业务任务处理器；未知任务明确失败，不静默成功。

### 分层

```text
页面 / 控制器 / 认证中间件
            ↓
        应用服务
            ↓
        领域与端口
            ↓
 SQLite / 会话 / 密码 / Worker 适配器
```

- 控制器没有导入基础设施、Drizzle、SQLite、文件系统、模型或 OpenViking。
- Worker 没有导入仓储或基础设施实现。
- 应用层没有依赖 H3、表现层或基础设施层。
- Nitro 插件是唯一运行时组合根，为请求上下文注入应用服务。

## 构建与黑盒验证

### 类型与构建

- `pnpm typecheck`：通过。
- `pnpm build`：通过，生成 Nitro Node Server。
- 构建过程中 Nuxt 依赖产物出现一条 Rollup 注解位置警告，Rollup 自动移除该注解，未影响构建结果。

### 生产产物黑盒流程

使用临时数据目录启动 `.output/server/index.mjs`，验证结果：

1. 首次设置状态返回 `setupRequired: true`。
2. 未登录访问系统健康接口返回 HTTP 401。
3. 从 `127.0.0.1` 创建管理员成功并建立 Cookie 会话。
4. 登录后健康接口返回 SQLite `wal`、外键启用、完整性 `ok`、Worker 运行中。
5. 退出接口清除会话。
6. 退出后再次访问健康接口返回 HTTP 401。

临时数据库、Cookie 和日志均在验证后移入系统回收站，不进入仓库。

### 迁移命令

- `pnpm migrate` 在独立临时目录执行成功。
- 命令完成后主动检查数据库完整性。

## 已知边界

- 当前只有工程状态首页，不是完整管理面板。
- 尚无人物、世界、资料、生成、反馈、评测、OpenViking 或图片模型能力。
- `task_jobs.run_id` 在运行表建立前允许为空；后续生成任务必须关联运行。
- Worker 长任务心跳将在首次引入真实模型任务时实现；当前没有会超过租约的业务处理器。
- 管理员重置的核心应用服务和会话撤销已自动测试；终端不回显交互只做代码与类型检查，未做伪终端自动化。
- 生产启动要求从包含 `drizzle/` 迁移目录的项目根目录运行。
