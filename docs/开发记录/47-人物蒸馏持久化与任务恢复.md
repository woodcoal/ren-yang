# 人物蒸馏持久化与任务恢复

## 完成范围

- 新增人物蒸馏运行、输入、认知候选、精确证据和候选评测表。
- 为资料增加可选来源地址、作者、发表时间和原始来源键。
- 新增人物蒸馏仓储接缝与 SQLite 适配器，保存全部阶段快照。
- 资料确认、候选编辑和最终人物创建均使用状态与更新时间条件更新。
- 最终确认在同一事务内创建人物、初始当前灵魂版本、资料关系并完成蒸馏运行。
- 前台任务仓储可以领取人物蒸馏任务，并处理取消、租约恢复、尝试耗尽和不可重试失败。
- 失败运行可以使用原输入与算法快照创建新的可追溯重试运行。
- 用户删除原资料时清除蒸馏输入正文，保留标题、哈希和来源不可用状态。
- 数据库触发器拒绝任务引用不存在的蒸馏运行，以及候选跨运行引用输入。
- 一致性备份与停机恢复保留人物蒸馏运行及其人物关联。

## 关键约束

- `task_jobs.run_id` 继续只锚定生成运行；人物蒸馏任务使用受触发器校验的 `payload_json.distillationRunId`。
- 候选正文编辑后立即清空旧 `evaluated_prompt_hash`，必须重新评测。
- 只有候选正文哈希与最近通过硬门禁的评测哈希一致时才能确认。
- OpenViking 仍不是业务事实源；运行与全部阶段快照保存在 SQLite。
- 人物蒸馏运行完成后创建的是初始当前灵魂版本，不把候选误记为灵魂草稿。

## 验证

- 人物蒸馏 SQLite 集成测试覆盖迁移、阶段快照、取消、失败、重试、证据隔离和原子确认。
- SQLite 全迁移、任务通道和备份恢复相关测试通过。
- `pnpm check` 通过：73 个测试文件、456 项测试、严格类型检查和生产构建全部成功。
