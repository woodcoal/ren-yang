# 人物蒸馏应用闭环与后台工作区

## 完成范围

- 注册代码固定的 `persona_distillation` 四步算法及已发布提示词，步骤模型仍由管理员显式配置。
- 新增人物蒸馏应用服务与内部接口，覆盖运行创建、资料确认、候选重评、最终确认、取消和失败重试。
- 前台 Worker 按固定顺序执行资料分类、认知提取、灵魂综合和六类评测，长模型调用不占用 SQLite 事务。
- 人物列表唯一创建入口改为异步人物蒸馏，不再同步整理或直接创建人物。
- 新增可恢复的人物蒸馏工作区，以独立组件展示四段进度、覆盖统计、资料分类纠正、认知证据、质量门禁和六类评测。
- 候选正文编辑后只能保存并重新评测；当前正文哈希与最近完整评测一致且没有硬失败时才允许确认创建。
- 失败运行保留固定输入与错误，支持创建新运行；活动运行支持协作式取消并阻止重复点击。

## 关键约束

- 资料覆盖确认和最终候选确认是仅有的两个强制人工检查点。
- 候选是基于资料生成的模拟对象，不代表本人真实意图或授权；界面不把它称为灵魂草稿。
- 页面重新进入时主动读取 SQLite 中的最新运行状态；只在自动步骤执行期间每两秒轮询，人工检查点不轮询。
- 新流程只处理已经导入且启用的文本资料，不增加联网采集或公共人物蒸馏接口。
- 既有同步人物草稿算法和历史快照暂不删除，后台人物列表已停止调用同步入口。

## 验证

- 人物蒸馏应用、迁移、任务、备份相关基础测试通过：6 个文件、68 项测试。
- 后台工作区基础组件测试通过：2 个文件、9 项测试，覆盖两个检查点、失败展示、恢复和重复取消锁。
- `pnpm typecheck` 通过。
- 完整 `pnpm check` 与核心 Playwright 闭环统一留到全部人物蒸馏阶段完成后执行。
