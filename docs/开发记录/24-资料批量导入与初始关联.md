# 资料批量导入与初始关联开发记录

## 1. 已确认范围

- 粘贴文本与文件导入都可选择多个人物和多个世界，关联对象可以为空。
- 文件输入支持一次选择多个 TXT、Markdown 文件。
- 一批文件共用资料用途和关联对象；每个资料名称默认取去掉扩展名后的文件名，并可单独修改。
- 文件按选择顺序逐个上传；部分失败不回滚成功项，界面汇总成功数、失败数和逐文件原因。
- 世界详情继续提供“新建资料并自动加入”，但创建时直接原子关联当前世界。

## 2. 数据一致性

- SQLite 仍是唯一业务事实源。
- 创建前由应用服务验证、去重全部人物和世界目标，初始关系优先级固定为 `100`。
- 仓储把单项资料正文、检索切片、人物关系和世界关系写入同一个 SQLite 事务。
- 无效目标或数据库错误不会留下资料、切片或关系；文件导入在数据库写入失败时清理本次原始文件。
- OpenViking 同步仍在 SQLite 单项事务成功后异步排队，不参与浏览器请求事务。

## 3. 接口与界面

- `POST /api/v1/sources` 新增可选 `targets`。
- `POST /api/v1/sources/files` 的 multipart 元数据新增 JSON 字段 `targets`，接口仍只接收一个文件并保持单请求大小限制。
- 资料库页面并行读取资料、人物和世界；关联对象加载失败时仍允许无关联导入。
- `SourceTargetPicker` 只负责人物和世界多选；`SourceImportForm` 负责粘贴输入、多文件选择、默认命名、单独改名和事件提交；页面负责逐项请求及结果汇总。
