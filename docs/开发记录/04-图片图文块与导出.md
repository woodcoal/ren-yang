## 实现边界

本阶段不实现反馈归因、人物自动迭代、评测或 OpenViking。图片只辅助内容表达，不提供参考图、固定外观资产或跨图片人物一致性承诺。

```text
管理页面 / API 控制器 / InternalWorker
                  ↓
       GenerationApplicationService
       ↓          ↓             ↓
 RunRepository  ImageModelPort  ImageAssetStorage
       ↓          ↓             ↓
    SQLite    OpenAI-compatible  data/artifacts
```

- 控制器和 Worker 仍只调用应用服务。
- 应用服务只通过端口访问 SQLite、模型和文件资产。
- 图片网络调用、远程下载和文件写入不持有 SQLite 事务。
- 文本、图片、选择指针和导出都以已确认规格及持久块事实为准。

## 数据迁移与兼容

新增迁移 `drizzle/0003_image-artifacts.sql`：

- `generation_runs.image_model_snapshot_json` 保存非敏感图片模型快照。
- `artifact_blocks` 支持 `text`、`image`，增加图片角色、取消状态、`selected_at` 和 `locked_at`。
- 新增 `image_assets`，记录尝试、相对路径、媒体类型、字节数、SHA-256、替代文本和创建时间。
- 图片媒体类型限制为 PNG、JPEG、WebP，单文件上限为 10 MiB。
- 图片资产与块尝试一对一；尝试删除时资产事实级联删除。

Drizzle 会把单次迁移放入事务，迁移 SQL 内切换外键不会立即生效。因此 `SqliteDatabase` 在迁移前显式关闭外键，迁移结束后恢复，并执行 `foreign_key_check`。自动化升级测试使用只含 `0000` 至 `0002` 的真实旧迁移创建数据库，写入已选择且锁定的文字块和成功尝试，再应用 `0003`；块、选择指针、锁定标志、输出和尝试均保留，外键检查为空。

阶段三已落库的规格没有 `purpose`、`constraints`、`requestedFormats` 和块 `type`。共享 Zod Schema 为这些字段提供兼容默认值，读取旧规格时归一化为完整阶段四结构。

## 图片能力与运行快照

创建图文运行新增显式 `includeImages`：

- `false` 时不读取或保存图片模型快照，模型不得规划图片块。
- `true` 时必须配置图片模型，并在运行创建时固定提供器、模型名称和 Endpoint Origin。
- 执行、整文重试和图片单块重试前会比较当前配置与运行快照，防止重启后静默换模型。
- 文本运行在图片模型未配置时仍可创建、规划、确认、执行和导出。

生产配置来自仓库外环境变量：

- `NUXT_IMAGE_MODEL_ENDPOINT`
- `NUXT_IMAGE_MODEL_API_KEY`
- `NUXT_IMAGE_MODEL_MODEL`

能力接口只公开配置状态、模型名称和 Origin，不返回密钥或完整凭据。

## 图片模型与下载安全

`OpenAiCompatibleImageModel` 调用 OpenAI-compatible Images Generations，固定请求一张图片并优先要求 `b64_json`。供应商只返回 URL 时执行受限下载：

- 仅允许无用户名和密码的 HTTP(S) URL。
- 每次重定向重新校验目标，最多三次。
- 使用 Node 网络块列表拒绝本机、私网、链路本地、组播、保留、文档和基准测试地址，包含 IPv4 映射 IPv6。
- `Content-Length` 和流式实际读取均执行 10 MiB 限制。
- 图片生成及下载共用运行超时信号。
- 429、5xx、超时、无效响应、阻断下载和超限输出映射为稳定错误码。

本地存储不信任供应商媒体类型。`LocalImageAssetStorage` 根据魔数识别 PNG、JPEG 或 WebP，再与声明类型交叉校验；扩展名只由魔数决定。文件先写入同目录临时文件，再原子改名到：

```text
data/artifacts/{runId}/assets/{assetId}.{ext}
```

运行标识、资产标识和相对路径均使用严格白名单。数据库完成图片尝试失败时，应用服务删除刚写入的单文件；仓储也会在尝试或块状态不符合预期时回滚事务，避免错误选择和孤儿事实。

## 图文规格与块执行

提示版本升级为 `artifact-v2`。`DocumentSpec` 新增：

- 文档目的、约束和请求导出格式。
- `text` 与 `image` 联合块类型。
- 图片主题、主体、构图、色彩、质感、宽高比、替代文本和负面约束。

确认规格仍在一个短事务内创建统一产物、全部顺序块和执行任务。Worker 串行扫描：

1. 已成功且有选择的块直接复用，不再次调用模型。
2. 显式依赖失败时追加 `DEPENDENCY_FAILED` 尝试，不调用模型。
3. 文字块调用文本模型并校验纯文本结构。
4. 图片块调用图片模型、校验并保存文件，再原子保存资产事实和选择指针。
5. 单块最多自动尝试两次；失败不覆盖其他成功块。
6. 全部、部分或没有块成功时，运行分别进入 `succeeded`、`partial` 或 `failed`。

单块手工重试创建新的 `execute_block` 任务和新尝试，不覆盖旧尝试。成功后默认选择新尝试，用户可切回任意历史成功尝试。选择操作只更新选择指针和时间。锁定块拒绝单块重试；整文重试只恢复失败且未锁定块，成功选择保持不变。

## 同源渲染与导出

渲染器只读取当前选中的成功尝试，不调用模型。HTML、Markdown 和 Txt 使用相同块顺序及文本：

- HTML 使用语义标题、段落、列表、引用和 `figure`，所有文字先清理控制字符并做实体转义。
- Markdown 转义结构控制符和尖括号，图片只引用受控 `assets/` 相对路径。
- Txt 清理控制字符，并输出可读的图片说明和文件路径。
- 模型文字不会作为任意 HTML 执行。

无图片时直接下载目标文档。含图片时使用 `fflate` 生成 ZIP，包含：

```text
document.html | document.md | document.txt
assets/{assetId}.{ext}
manifest.json
```

清单记录运行、人物版本、导出时间、格式，以及每个文件的相对路径、媒体类型、字节数和 SHA-256。文件名前缀执行 Unicode 归一化、路径与控制字符清理、保留名规避和长度限制。

## API

新增受登录保护的接口：

- `POST /api/v1/runs/{runId}/blocks/{blockId}/attempts`
- `POST /api/v1/runs/{runId}/blocks/{blockId}/select`
- `POST /api/v1/runs/{runId}/blocks/{blockId}/lock`
- `POST /api/v1/runs/{runId}/render`
- `GET /api/v1/runs/{runId}/exports/{format}`
- `GET /api/v1/runs/{runId}/assets/{assetId}`

二进制控制器统一设置可信 `Content-Type`、`Content-Length`、`X-Content-Type-Options: nosniff` 和安全附件文件名。资产查询同时校验资产确属路径中的运行，不能跨运行读取。

## 管理界面

- `/workbench` 显示图片能力；模型未配置时禁用图片开关并解释纯文本仍可使用。
- `DocumentSpecEditor` 支持文档目的、约束、导出格式、文字块、图片块和完整视觉简报。
- `ArtifactBlockCard` 显示文字或图片尝试、当前选择、错误、锁定、历史选择和单块重试。
- `ArtifactPreview` 在无脚本权限的 `sandbox` iframe `srcdoc` 中预览服务端受控 HTML；Markdown 和 Txt 以纯文本展示。
- 预览时只把受控相对图片路径改写为登录保护的资产接口；不使用 `v-html`。
- 三种格式均提供独立下载入口。

页面保持 props 下传、事件上抛。运行详情页只负责编排 API、轮询和刷新，块与预览职责拆为独立组件，不引入额外全局状态。

## 已知边界

- 图片质量、提示服从度和人物外观一致性取决于供应商；MVP 不提供参考图或一致性工作流。
- 远程 URL 下载在请求前校验 DNS 结果和每次重定向目标；更强的 DNS 解析固定及出口代理属于阶段六部署安全加固。
- 导出包即时生成，不保存导出文件历史；运行删除影响包含源图片资产，持久导出记录不在当前范围。
- Markdown 在管理界面按源码预览，不引入第三方 Markdown 渲染器。
- OpenViking、反馈、评测和人物版本自动迭代仍属于阶段五。
