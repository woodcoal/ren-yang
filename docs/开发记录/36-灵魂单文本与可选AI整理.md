# 灵魂单文本与可选 AI 整理

## 调整范围

- 人物和世界灵魂统一为唯一 `promptText`，移除章节编辑和第二份运行摘要。
- 灵魂新建、修改改为一个大文本弹窗；用户可选择原文保存或让 AI 整理为标准提示词。
- 手动保存只去除整段首尾空白；AI 只能整理表达，不得增加事实。
- 两种保存方式都只形成修改稿，不自动发布；模型不可用或输出无效时不覆盖当前草稿。
- 草稿删除、确认发布、历史版本查看和复制为修改稿继续保留。
- 人物与世界快捷初始化继续使用结构化模型协议，但灵魂只返回 `{ snapshot: { promptText } }`。
- 生成、兴趣判断、分析、上下文快照和运行详情统一读取已发布版本的 `promptText`。

## 数据迁移

- 新增 `drizzle/0003_soul_prompt_text.sql`。
- `soul_drafts.runtime_summary` 无损迁移为 `soul_drafts.prompt_text`。
- `soul_versions.runtime_summary` 无损迁移为 `soul_versions.prompt_text`。
- 迁移后删除 `chapters_json` 和 `runtime_summary`，保留对象归属、版本关系、状态、时间和 Token 计数。
- 使用真实 `data/app.sqlite` 的只读备份副本完成迁移验证；原数据库未被修改。副本迁移数为 4，完整性检查为 `ok`，外键违规为 0。

## 架构边界

- 人物和世界灵魂控制器仍只负责参数校验并调用 `SoulApplicationService`。
- `SoulApplicationService` 只通过 `SoulRepository` 保存草稿和版本，通过 `TextModelPort` 执行可选 AI 整理。
- 模型网络调用发生在数据库写入前；整理失败不会产生部分写入。

## 验证结果

- 定向测试：9 个文件、92 项测试通过。
- 全量测试：37 个文件、199 项测试通过。
- `pnpm exec tsc -p .nuxt/tsconfig.json --noEmit` 通过。
- `pnpm build` 生产构建通过。
- `pnpm typecheck` 仍被既有 TypeScript 7.0.2 与 vue-tsc 3.3.11 包导出兼容问题阻断：`ERR_PACKAGE_PATH_NOT_EXPORTED: ./lib/tsc`；源码已经由直接 `tsc` 完成类型检查。

## 回归测试证据

- `手动保存灵魂只移除首尾空白且不调用模型`：验证原文保存边界。
- `自动分析把模型整理结果保存为未发布草稿`：验证 AI 整理结果不会直接生效。
- `自动分析不可用或输出无效时不覆盖原草稿`：验证失败原子性。
- `灵魂单文本迁移保留旧运行摘要并移除旧结构字段`：验证数据库升级兼容和外键完整性。
- `灵魂使用单文本弹窗，可选择原文保存或自动分析且不会直接发布`：验证人物和世界共用的前端交互。
- `无资料创建原创人物，草稿发布后不可变且历史版本只能复制为新草稿`：验证发布和历史版本规则。
- `从自然语言和选定资料生成不落库的结构化人物候选草稿`、`从自然语言生成不落库的结构化世界候选草稿`：验证快捷创建协议仍可用。
- `灵魂自动分析只允许整理表达并要求单文本结果`：验证模型提示明确禁止新增事实并只允许返回 `promptText`。
