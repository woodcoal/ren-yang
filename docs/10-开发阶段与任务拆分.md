# 开发阶段与任务拆分

## 实施原则

- 按可运行的纵向闭环推进，每一阶段都包含页面、控制器、应用服务、领域规则、数据和必要测试。
- 控制器与 Worker 只调用应用服务；应用服务通过端口访问数据和外部能力。
- 先保证 SQLite 唯一事实源和持续 FTS5 降级，再接入 OpenViking 异步投影与记忆处理。
- SQLite 是 MVP 唯一数据库实现；不同时建设 PostgreSQL。
- 当前阶段未被验收前，不提前实现后续业务扩展。

阶段一至阶段七记录现有 MVP 的原始建设顺序。当前心智模型改造以 [15-统一心智模型与迭代开发设计.md](./15-统一心智模型与迭代开发设计.md) 为准，不继续在固定人物八字段、世界单正文或反馈直接产生人物版本的旧路径上追加功能。

## 阶段一：工程基线、登录与 SQLite

### 任务

- 创建 Nuxt 4、TypeScript 严格模式和 pnpm 工程。
- 配置 Nuxt UI、Zod、Drizzle、SQLite 和 `nuxt-auth-utils`。
- 建立表现层、应用层、领域层、端口和基础设施目录边界。
- 实现首次管理员初始化、登录、登出和本机密码重置。
- 建立迁移、配置校验、数据目录和健康状态。
- 建立同进程 Worker 骨架、任务租约和优雅退出。

### 验证

- 全新数据目录可迁移和创建管理员。
- 未登录访问业务页面或接口被拒绝。
- 控制器和 Worker 没有直接导入数据库或外部适配器。
- 重启后会话、迁移和空任务 Worker 行为符合设计。

### 完成标准

应用可本地构建、启动、登录并显示系统状态；SQLite 迁移和分层约束有自动化验证。

## 阶段二：人物、世界与资料

### 任务

- 实现原创、资料型、混合型人物创建。
- 实现人物候选版本、发布、差异和当前版本回滚。
- 实现可选世界及不可变版本。
- 实现粘贴文本、TXT、Markdown 导入和安全校验。
- 实现资料切片、证据快照和 SQLite FTS5 检索。
- 实现资料与人物、世界、版本之间的关联和删除影响分析。

### 验证

- 无资料时可以创建并发布原创人物。
- 三类人物和可选世界关联均能保存、查询和比较。
- 已发布版本不能原地修改，回滚只改变当前指针。
- FTS5 能检索已导入资料；危险或超限文件被拒绝。
- 删除前能列出所有引用和受影响文件。

### 完成标准

用户可在管理界面维护可靠的人物事实源，版本和证据关系可追溯，不依赖任何外部模型。

## 阶段三：文本生成与兴趣判断

### 任务

- 定义文本模型端口、生产适配器和固定结果测试适配器。
- 实现参数方案、提示分层、证据检索和输入快照。
- 实现基础兴趣判断 Schema 和图文生成运行创建。
- 实现 `DocumentSpec` 生成、编辑、校验和确认。
- 实现文字块串行生成、有限重试、取消和运行历史。
- 实现租约恢复、结构化输出校验和稳定错误码。

### 验证

- 兴趣判断返回分值、结论、理由、证据和不确定性。
- 人物设定、资料事实和 AI 推断遵循既定优先级。
- 用户未确认规格时不能执行块生成。
- 模型超时、格式错误、限流和进程重启都有可恢复结果。
- 场景上下文只进入当前运行快照，不直接修改人物。

### 完成标准

在仅配置文本模型时，用户可以完成兴趣判断和结构化纯文本创作，运行全过程可查询和恢复。

## 阶段四：图片、图文块与三格式导出

### 任务

- 定义图片模型端口及可选能力检测。
- 实现图片视觉简报、下载、媒体校验和本地资产保存。
- 实现块尝试选择、锁定、单块重试和部分成功。
- 实现统一产物文档及 HTML、Markdown、Txt 渲染器。
- 实现资源包、清单、相对路径和 SHA-256 校验。
- 实现安全预览和导出下载。

### 验证

- 图片模型未配置时图片入口禁用，纯文本路径不受影响。
- 图片失败不覆盖成功文字块，运行可以正确标记部分成功。
- 三种格式来自同一组选中块，顺序和文本一致。
- HTML、Markdown 资源路径存在，Txt 有可读图片引用。
- 不可信 HTML、路径和文件名不能进入可执行输出或越过数据目录。

### 完成标准

用户可以按确认规格生成、调整并导出图文产物；图片仍是辅助表达，不承诺人物外观一致。

## 阶段五：反馈、评测、版本与 OpenViking

### 任务

- 实现反馈提交、目标分类、修订提案和候选记忆。
- 实现字段级风险分类和人工确认规则。
- 实现人物评测用例、评测运行、退化判定和结果快照。
- 实现灵魂修改提案、成长和记忆候选的人工审核门禁。
- 实现 OpenViking 世界 User / 人物 Peer 投影、Session、候选记忆回写、能力检测和重建。
- 保证 SQLite 保存全部业务事实、投影和审核状态，OpenViking 只提供可重建派生能力。

### 验证

- 当前产物、参数、长期人物和资料事实反馈能正确归因。
- 灵魂、成长和记忆提案均不能自动发布或生效。
- 场景内容只影响当前运行，不能自动形成候选记忆或进入已发布版本。
- 评测结果只作为审核依据，不自动发布灵魂或让成长、记忆生效。
- OpenViking 健康与 FTS5 降级路径执行同一业务用例并返回一致业务结构。
- OpenViking 数据删除后可以从 SQLite 的资料、关联、成长、记忆和任务状态重建。

### 完成标准

反馈能够以可审查、可评测、可回滚的方式迭代人物；OpenViking 自动提取结果也必须经过相同门禁，且不改变主事实源和分层边界。

## 阶段六：备份恢复、限制与正式启动

### 任务

- 实现手工一致性备份、清单、哈希和只读恢复验证。
- 实现应用停机后的 CLI 恢复、失败回退和索引重建。
- 完成请求、文件、任务、模型和磁盘资源限制。
- 完成日志脱敏、轮转、审计和安全错误映射。
- 完成生产构建、启动脚本、反向代理说明和运维文档。
- 执行密钥、路径穿越、XSS、提示注入和删除边界审查。

### 验证

- 活动 WAL 数据库可生成一致备份，清单与文件哈希相符。
- 损坏备份在替换当前数据前被拒绝。
- 恢复演练成功且能回退到恢复前数据。
- 密钥不出现在仓库、数据库、备份、导出和日志。
- 超限输入与磁盘不足能安全失败，不破坏已有数据。
- 局域网部署说明要求 HTTPS，应用仍保持登录保护。

### 完成标准

单机生产运行具备可恢复数据、明确限制和基础安全保障，运维动作可验证且不会静默破坏数据。

## 阶段七：MVP 总体验收

### 任务

- 在干净环境从零安装、迁移、初始化和启动。
- 执行全部自动化测试和五条端到端主流程。
- 分别验证 OpenViking 开/关、图片模型有/无的能力组合。
- 使用真实文本和图片模型完成人物行为手工验收。
- 执行异常退出、任务恢复、备份恢复和永久删除演练。
- 对照产品范围逐项保存验收证据和已知限制。

### 验证

- `docs/08-测试与验收方案.md` 的 MVP 验收矩阵全部通过。
- 没有违反严格分层、版本不可变和证据优先级的不一致实现。
- 所有阻断缺陷关闭；非阻断限制有明确记录。

### 完成标准

用户能从创建人物开始，完成兴趣判断、图文生成、三格式导出、反馈迭代、评测发布、回滚和备份恢复的完整闭环。

## 阶段八：统一心智模型改造

### 8.1 共享契约与数据迁移

#### 任务

- 增加世界/人物灵魂自由章节、草稿、不可变版本和运行摘要契约。
- 增加成长修订、记忆修订、人物反馈资料、处理记录、分析批次和迭代提案结构。
- 增加提示词世界/人物父子 Token 预算和运行上下文快照。
- 以新迁移回填旧人物八字段、世界单正文、成长和记忆，保留历史运行兼容读取。

#### 验证

- 迁移前后世界、人物、版本、成长、记忆和运行引用数量一致。
- 空字段不产生空章节，非空内容和哈希不丢失。
- 历史运行仍能读取旧快照；新写入使用新模型。

### 8.2 世界与人物灵魂闭环

#### 任务

- 实现共享灵魂领域规则及世界/人物独立业务入口。
- 实现草稿编辑、删除、差异、发布、基于历史创建草稿和版本清理限制。
- 实现运行摘要 Token 检查和自由章节编辑器。
- 提示构建切换到当前已发布世界与人物灵魂运行摘要。

#### 验证

- 控制器和 Worker 只调用应用服务。
- 草稿可编辑，发布版本不可变，被运行引用的版本不可删除。
- 世界和人物灵魂均不再依赖固定旧字段。

### 8.3 世界与人物成长闭环

#### 任务

- 世界资料增加启用状态和世界成长分析。
- 实现人物反馈资料逐条及批量启用、禁用、删除和同步。
- 实现成长增量/完整分析、提案审核、修订、合并、取代、归档和恢复。
- 实现世界和人物成长工作区。

#### 验证

- 世界成长只使用已启用世界资料；人物成长只使用人物反馈资料。
- 删除或禁用原始资料不静默改变已确认成长。
- OpenViking 删除失败可以补偿，FTS5 只检索 active 成长。

### 8.4 人物处理记录与记忆闭环

#### 任务

- 任务完成后建立人物处理记录并同步对应 Peer Session。
- 实现处理记录批量启用、禁用和分析。
- 实现记忆去重、独立证据、提案、修订和状态管理。
- 实现记忆转为人物反馈资料。

#### 验证

- 世界不能创建记忆。
- 同一运行重复数据不虚增独立证据。
- OpenViking 派生内容不能绕过 SQLite 审核。
- 记忆不能自动变成长。

### 8.5 提示词预算与可追溯运行

#### 任务

- 实现 Token 计数端口、精确/估算标识和安全余量。
- 实现世界与人物父子预算、资料预算和分类选择算法。
- 实现预算预览、实际选入、跳过原因和运行详情。
- 保证 OpenViking 与 FTS5 使用同一 SQLite 有效范围。

#### 验证

- 灵魂摘要超限时阻止发布或运行，不在运行时随机截断。
- 成长、记忆和资料按规则整条跳过。
- 核心内容超限返回稳定错误且不调用模型。
- 运行快照可以完整解释预算和上下文选择。

### 8.6 工作区与总验收

#### 任务

- 人物工作区完成概览、灵魂、成长、记忆、世界与资料、版本。
- 世界工作区完成概览、灵魂、成长、世界资料、使用人物、版本。
- 按 `docs/UX` 模板拆分公共与特性样式，不把样式集中到单一文件。
- 完成迁移、OpenViking 故障、FTS5 降级、预算和历史兼容验收。

#### 完成标准

[12-人物灵魂成长与记忆机制修改需求.md](./12-人物灵魂成长与记忆机制修改需求.md) 与 [15-统一心智模型与迭代开发设计.md](./15-统一心智模型与迭代开发设计.md) 的完成条件全部具备测试证据；每个子阶段分别记录、提交并推送。

## MVP 后续事项

以下事项必须在 MVP 验收后重新决策，不纳入当前阶段：

- PostgreSQL 适配与数据迁移工具。
- 多用户、组织、权限和协作审批。
- 独立 Worker 进程、队列服务和水平扩展。
- PDF、EPUB、DOCX 等新导出格式。
- PDF、网页、图片 OCR、音视频等资料导入。
- 参考图、角色外观资产和跨图片一致性流程。
- 批量人物实验、群体模拟和对比研究。
- 内容平台发布、营销变体、互动叙事和游戏 NPC 接口。
- 自动定时备份、远端对象存储和异地灾备。

每个后续事项应以真实使用数据和明确业务目标立项，不因当前代码中预留接口而自动进入范围。
