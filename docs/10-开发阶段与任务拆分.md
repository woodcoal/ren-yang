# 开发阶段与任务拆分

## 实施原则

- 按可运行的纵向闭环推进，每一阶段都包含页面、控制器、应用服务、领域规则、数据和必要测试。
- 控制器与 Worker 只调用应用服务；应用服务通过端口访问数据和外部能力。
- 先保证无 OpenViking、无图片模型时的完整文本流程，再接入可选能力。
- SQLite 是 MVP 唯一数据库实现；不同时建设 PostgreSQL。
- 当前阶段未被验收前，不提前实现后续业务扩展。

## 阶段一：工程基线、登录与 SQLite

### 任务

- 创建 Nuxt 4、TypeScript 严格模式和 pnpm 工程。
- 配置 Nuxt UI、Zod、Drizzle、SQLite 和 `nuxt-auth-utils`。
- 建立表现层、应用层、领域层、端口和基础设施目录边界。
- 实现首次管理员初始化、登录、登出和本机密码重置。
- 建立迁移、配置校验、数据目录和健康状态。
- 建立同进程 Worker 骨架、任务租约和优雅退出。

### 验证

- 全新数据目录可迁移和创建管理员。
- 未登录访问业务页面或接口被拒绝。
- 控制器和 Worker 没有直接导入数据库或外部适配器。
- 重启后会话、迁移和空任务 Worker 行为符合设计。

### 完成标准

应用可本地构建、启动、登录并显示系统状态；SQLite 迁移和分层约束有自动化验证。

## 阶段二：人物、世界与资料

### 任务

- 实现原创、资料型、混合型人物创建。
- 实现人物候选版本、发布、差异和当前版本回滚。
- 实现可选世界设定及不可变版本。
- 实现粘贴文本、TXT、Markdown 导入和安全校验。
- 实现资料切片、证据快照和 SQLite FTS5 检索。
- 实现资料与人物、世界、版本之间的关联和删除影响分析。

### 验证

- 无资料时可以创建并发布原创人物。
- 三类人物和可选世界关联均能保存、查询和比较。
- 已发布版本不能原地修改，回滚只改变当前指针。
- FTS5 能检索已导入资料；危险或超限文件被拒绝。
- 删除前能列出所有引用和受影响文件。

### 完成标准

用户可在管理界面维护可靠的人物事实源，版本和证据关系可追溯，不依赖任何外部模型。

## 阶段三：文本生成与兴趣判断

### 任务

- 定义文本模型端口、生产适配器和固定结果测试适配器。
- 实现参数方案、提示分层、证据检索和输入快照。
- 实现基础兴趣判断 Schema 和图文生成运行创建。
- 实现 `DocumentSpec` 生成、编辑、校验和确认。
- 实现文字块串行生成、有限重试、取消和运行历史。
- 实现租约恢复、结构化输出校验和稳定错误码。

### 验证

- 兴趣判断返回分值、结论、理由、证据和不确定性。
- 人物设定、资料事实和 AI 推断遵循既定优先级。
- 用户未确认规格时不能执行块生成。
- 模型超时、格式错误、限流和进程重启都有可恢复结果。
- 场景上下文只进入当前运行快照，不直接修改人物。

### 完成标准

在仅配置文本模型时，用户可以完成兴趣判断和结构化纯文本创作，运行全过程可查询和恢复。

## 阶段四：图片、图文块与三格式导出

### 任务

- 定义图片模型端口及可选能力检测。
- 实现图片视觉简报、下载、媒体校验和本地资产保存。
- 实现块尝试选择、锁定、单块重试和部分成功。
- 实现统一产物文档及 HTML、Markdown、Txt 渲染器。
- 实现资源包、清单、相对路径和 SHA-256 校验。
- 实现安全预览和导出下载。

### 验证

- 图片模型未配置时图片入口禁用，纯文本路径不受影响。
- 图片失败不覆盖成功文字块，运行可以正确标记部分成功。
- 三种格式来自同一组选中块，顺序和文本一致。
- HTML、Markdown 资源路径存在，Txt 有可读图片引用。
- 不可信 HTML、路径和文件名不能进入可执行输出或越过数据目录。

### 完成标准

用户可以按确认规格生成、调整并导出图文产物；图片仍是辅助表达，不承诺人物外观一致。

## 阶段五：反馈、评测、版本与 OpenViking

### 任务

- 实现反馈提交、目标分类、修订提案和候选记忆。
- 实现字段级风险分类和人工确认规则。
- 实现人物评测用例、评测运行、退化判定和结果快照。
- 实现低风险风格或兴趣变更的受控自动发布。
- 实现 OpenViking 上下文适配器、能力开关、索引写入和重建。
- 保证 SQLite 保存全部业务事实，OpenViking 只提供可选上下文能力。

### 验证

- 当前产物、参数、长期人物和资料事实反馈能正确归因。
- 事实、价值观和禁用项提案不能自动发布。
- 场景内容只能形成候选记忆，未经流程不能进入已发布版本。
- 低风险提案只在评测通过后按设置自动发布。
- OpenViking 开启与关闭路径执行同一业务用例并返回一致业务结构。
- OpenViking 数据删除后可以从 SQLite 和资料文件重建。

### 完成标准

反馈能够以可审查、可评测、可回滚的方式迭代人物；可选 OpenViking 不改变主事实源和分层边界。

## 阶段六：备份恢复、限制与正式启动

### 任务

- 实现手工一致性备份、清单、哈希和只读恢复验证。
- 实现维护模式下实际恢复、失败回退和索引重建。
- 完成请求、文件、任务、模型和磁盘资源限制。
- 完成日志脱敏、轮转、审计和安全错误映射。
- 完成生产构建、启动脚本、反向代理说明和运维文档。
- 执行密钥、路径穿越、XSS、提示注入和删除边界审查。

### 验证

- 活动 WAL 数据库可生成一致备份，清单与文件哈希相符。
- 损坏备份在替换当前数据前被拒绝。
- 恢复演练成功且能回退到恢复前数据。
- 密钥不出现在仓库、数据库、备份、导出和日志。
- 超限输入与磁盘不足能安全失败，不破坏已有数据。
- 局域网部署说明要求 HTTPS，应用仍保持登录保护。

### 完成标准

单机生产运行具备可恢复数据、明确限制和基础安全保障，运维动作可验证且不会静默破坏数据。

## 阶段七：MVP 总体验收

### 任务

- 在干净环境从零安装、迁移、初始化和启动。
- 执行全部自动化测试和五条端到端主流程。
- 分别验证 OpenViking 开/关、图片模型有/无的能力组合。
- 使用真实文本和图片模型完成人物行为手工验收。
- 执行异常退出、任务恢复、备份恢复和永久删除演练。
- 对照产品范围逐项保存验收证据和已知限制。

### 验证

- `docs/08-测试与验收方案.md` 的 MVP 验收矩阵全部通过。
- 没有违反严格分层、版本不可变和证据优先级的不一致实现。
- 所有阻断缺陷关闭；非阻断限制有明确记录。

### 完成标准

用户能从创建人物开始，完成兴趣判断、图文生成、三格式导出、反馈迭代、评测发布、回滚和备份恢复的完整闭环。

## MVP 后续事项

以下事项必须在 MVP 验收后重新决策，不纳入当前阶段：

- PostgreSQL 适配与数据迁移工具。
- 多用户、组织、权限和协作审批。
- 独立 Worker 进程、队列服务和水平扩展。
- PDF、EPUB、DOCX 等新导出格式。
- PDF、网页、图片 OCR、音视频等资料导入。
- 参考图、角色外观资产和跨图片一致性流程。
- 批量人物实验、群体模拟和对比研究。
- 内容平台发布、营销变体、互动叙事和游戏 NPC 接口。
- 自动定时备份、远端对象存储和异地灾备。

每个后续事项应以真实使用数据和明确业务目标立项，不因当前代码中预留接口而自动进入范围。
