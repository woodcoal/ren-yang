# 图文文档与导出规范

## 统一文档模型

HTML、Markdown 和 Txt 共用一个产物文档，不分别调用模型生成三份内容。模型只生成文档规格与块内容，渲染器负责格式差异。

```text
DocumentSpec
  └── BlockSpec[]
          ↓ 生成
ArtifactDocument
  └── ArtifactBlock[]
          └── BlockAttempt[]
                  ↓ 选择成功尝试
          SelectedAttempt
                  ↓
HTML / Markdown / Txt Renderer
```

## 文档规格

文档规格包含：

| 字段 | 规则 |
|---|---|
| `title` | 任务内文档名称 |
| `purpose` | 文档目标和受众 |
| `constraints` | 全文事实、长度、禁用项和格式要求 |
| `blocks` | 有序块规格，至少一个 |
| `requestedFormats` | `html`、`markdown`、`txt` 的非空集合 |

每个块规格包含：

| 字段 | 规则 |
|---|---|
| `id` | 规格内稳定标识 |
| `type` | `text` 或 `image` |
| `role` | 标题、导语、正文、列表、说明、主图、插图等 |
| `requirements` | 内容、长度、语气和视觉要求 |
| `dependsOn` | 依赖块标识列表，只允许指向前序块 |
| `acceptance` | 可执行的块验收规则 |

系统必须拒绝循环依赖、未知依赖、空块列表和未配置能力对应的块类型。

## 规格确认

- AI 首次生成的规格处于待确认状态。
- 用户可以编辑块要求、增加或删除块、用按钮调整顺序。
- MVP 不实现拖放排序，避免额外交互复杂度。
- 修改顺序后必须重新校验依赖。
- 确认后规格不可原地修改；需要调整时创建新的规格修订。

## 文字块

文字块输出保存纯文本或结构化列表数据，不保存模型生成的任意 HTML。验收可以包含：

- 最小和最大字数。
- 必需关键词或字段。
- 禁用表达。
- 标题层级或列表项目数。
- 必须引用的证据。
- 语言和语气要求。

格式标记由渲染器根据块角色生成。

## 图片块

图片块输入由应用生成视觉简报，至少包括主题、主体、构图、色彩、质感、宽高比、替代文本和负面约束。

MVP 限制：

- 图片只辅助内容表达。
- 不上传参考图片。
- 不承诺同一人物在不同图片中外观一致。
- 图片模型未配置时，禁止创建包含图片块的运行规格。
- 模型返回的远程图片必须下载到本地文件存储并校验媒体类型与大小。

## 块状态

```text
pending → running → succeeded
    │         └────→ failed
    └──────────────→ canceled
```

- `succeeded` 块可以产生多个成功尝试，用户选择其一。
- `failed` 块不导致其他成功块回滚。
- `locked` 是独立标志；锁定块不能被批量重试替换。
- 解除锁定、重试和选择尝试都要记录时间。

## 执行顺序

Worker 按文档顺序扫描块：

1. 依赖未完成的块保持等待。
2. 依赖完成后构造该块输入快照。
3. MVP 单 Worker 串行调用模型，不实现块并发。
4. 块失败后按任务规则自动尝试一次。
5. 仍失败则继续处理不依赖该块的后续块。
6. 最终根据成功与失败数量确定运行是成功、部分成功或失败。

## HTML 渲染

- 使用语义标签：标题、段落、列表、`figure`、`img`、`figcaption`。
- 图片使用相对 `assets/` 路径和必需 `alt`。
- 不执行模型生成的脚本、事件属性或任意内联 HTML。
- 管理界面预览放入受控容器，并对所有可变 HTML 再次净化。
- 导出 HTML 不依赖应用运行时即可打开。

## Markdown 渲染

- 标题、段落和列表使用标准 Markdown。
- 图片使用相对路径：`![替代文本](assets/file.ext)`。
- 对块正文中的 Markdown 控制字符按角色转义，表达样例不能注入额外结构。
- 不生成依赖特定平台的私有扩展语法。

## Txt 渲染

Txt 不能嵌入图片，按块顺序写入可读引用：

```text
[图片：替代文本]
文件：assets/file.ext
```

标题和块之间使用空行；列表使用 `- `；不使用 ANSI 控制字符。

## 导出包

每次导出请求只选择一种格式。包含图片时下载一个 ZIP 资源包，包内不增加额外顶层目录：

```text
├── document.{html|md|txt}
├── manifest.json
└── assets/
    └── {file-id}.{ext}
```

ZIP 只包含请求格式对应的一个文档、清单和被该文档引用的资源。没有图片时直接下载单个文档文件，不创建 ZIP。

`manifest.json` 保存运行标识、人物版本、导出时间、格式、文件相对路径、媒体类型、大小和 SHA-256，不包含模型密钥或隐藏提示。

## 文件命名

- 用户标题只用于安全化后的显示前缀。
- 实际唯一性由运行标识和文件标识保证。
- 去除路径分隔符、控制字符和保留名称。
- 文件扩展名由已验证媒体类型决定，不信任模型返回名称。

## 格式模板

格式模板只定义结构指导 `guidance`、最少块数 `minimumBlocks` 和最多块数 `maximumBlocks`。模板版本不可原地修改；调整时创建新版本。

模板不包含人物个性和模型密钥。人物决定表达，模板决定结构，参数方案决定调用行为。

## 导出验收

- 三种格式来自同一组选中块。
- 块顺序一致。
- HTML 和 Markdown 的所有图片路径存在。
- Txt 中每张图片都有可读引用。
- 资源清单数量、大小和哈希与实际文件一致。
- 导出包即时生成，不写入数据库或持久导出历史；图片块资产仍随运行数据接受删除影响分析。
