# 图文文档与导出规范

## 直接生成模型

用户只提交人物、生成条件、输出格式和图片数量。系统不向用户暴露大纲、文档规格、块、锁定或单块重试操作。

```text
生成条件 + 人物固定快照
  → 一次生成完整文章
  → 按需分析全部配图及正文位置
  → 逐张生成并校验图片
  → HTML 混排或文本与图片数据分离返回
```

完整文章固定包含标题、摘要和有序正文段落。结构化输出无效时允许一次不携带旧模型回答的修正调用；仍不合法则任务失败，不把半成品规格交给用户处理。

## 图片生成

图片数量为零时不调用配图分析或图片模型。图片数量大于零时，配图分析一次返回与请求数量严格一致的视觉简报和段落插入位置；每项视觉简报至少包含主题、主体、构图、色彩、质感、宽高比、替代文本和负面约束。

- 图片只辅助文章表达，不上传参考图片，也不承诺跨图片人物外观一致。
- 图片提示只使用人物与世界视觉身份、当前视觉简报、必要前文和负面约束。
- 模型返回图片必须下载到本地并校验 PNG、JPEG 或 WebP 文件头及大小。
- 图片超过算法步骤配置的最大宽高时执行二次居中裁剪，并同时保留裁剪前原图；尺寸一致或更小时不处理。
- 个别图片失败时保留已完成文章和成功图片，运行按实际结果标记为部分成功或失败。

## HTML 渲染

- 使用语义标签：标题、段落、列表、`figure`、`img`、`figcaption`。
- 图片使用相对 `assets/` 路径和必需 `alt`。
- 不执行模型生成的脚本、事件属性或任意内联 HTML。
- 管理界面预览放入受控容器，并对所有可变 HTML 再次净化。
- 导出 HTML 不依赖应用运行时即可打开。

## Markdown 渲染

- 标题、段落和列表使用标准 Markdown。
- 图片使用相对路径：`![替代文本](assets/file.ext)`。
- 对块正文中的 Markdown 控制字符按角色转义，表达样例不能注入额外结构。
- 不生成依赖特定平台的私有扩展语法。

## Txt 渲染

Txt 不能嵌入图片，按块顺序写入可读引用：

```text
[图片：替代文本]
文件：assets/file.ext
```

标题和正文段落之间使用空行，不使用 ANSI 控制字符。

## 导出包

每次导出请求只选择一种格式。包含图片时下载一个 ZIP 资源包，包内不增加额外顶层目录：

```text
├── document.{html|md|txt}
├── manifest.json
└── assets/
    └── {file-id}.{ext}
```

ZIP 只包含请求格式对应的一个文档、清单和被该文档引用的资源。没有图片时直接下载单个文档文件，不创建 ZIP。

`manifest.json` 保存运行标识、世界与人物心智快照标识、导出时间、格式、文件相对路径、媒体类型、大小和 SHA-256，不包含模型密钥或隐藏提示。

## 文件命名

- 用户标题只用于安全化后的显示前缀。
- 实际唯一性由运行标识和文件标识保证。
- 去除路径分隔符、控制字符和保留名称。
- 文件扩展名由已验证媒体类型决定，不信任模型返回名称。

## 内部结构与算法

用户不选择格式模板或参数方案，只提交人物、生成条件、输出格式和图片数量。文章算法一次生成完整正文；需要图片时，配图分析算法根据最终文章形成内部顺序快照，图片算法再生成指定数量资源。

人物决定表达风格，固定算法决定模型、提示词和调用参数，代码固定安全预算约束上下文与运行上限。以上配置都写入运行快照，后续发布新算法配置不会追溯改变旧运行。

## 导出验收

- 三种格式来自同一篇最终文章和同一组图片。
- 正文段落和图片位置顺序一致。
- HTML 和 Markdown 的所有图片路径存在。
- Txt 中每张图片都有可读引用。
- 资源清单数量、大小和哈希与实际文件一致。
- 导出包即时生成，不写入数据库或持久导出历史；图片资产仍随运行数据接受删除影响分析。
