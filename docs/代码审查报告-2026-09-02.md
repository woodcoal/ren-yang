## 3. 已确认问题与处理结果

### 3.1 P1：任务模型快照受当前配置漂移影响

- 证据：`server/application/aiConfiguration/AiAlgorithmApplicationService.ts` 的步骤执行曾重新读取当前部署和连接，并比较模型、地址、User-Agent、启停状态和思考格式。
- 违反：任务创建时保存的非敏感快照应冻结模型调用事实，后续管理员修改不得追溯改变旧任务。
- 影响：排队任务可因配置编辑或停用无故失败，重试也无法复现创建时行为。
- 修复：执行阶段使用快照中的 endpoint、model、User-Agent、思考格式和参数；当前数据库只按 `connectionId` 提供可轮换密文。连接记录确实消失时仍明确失败，因为快照不得保存密钥。
- 验证：新增“快照创建后编辑并停用连接和部署，旧任务仍按原非敏感配置、使用当前密钥执行”的集成测试。
- 状态：已修复。

### 3.2 P1：完整备份遗漏人物头像和裁剪前原图

- 证据：`server/infrastructure/backup/LocalBackupManager.ts` 原白名单只允许资料和文章图片，恢复 staging 也未创建 `avatars/`。
- 影响：备份验证显示正常，但恢复后人物头像静默丢失；二次裁剪的原图同样不可恢复。
- 修复：只发现备份数据库中仍存在人物的 `avatar`、`avatar-original`；校验普通文件、拒绝符号链接，并按文件头识别 PNG、JPEG、WebP。孤立人物目录不进入备份，恢复时创建头像目录。
- 验证：集成测试覆盖结果头像、原图、清单、恢复和孤立头像排除；另在隔离目录执行真实备份命令和 `restore:validate`。
- 状态：已修复。

### 3.3 P1：关闭 OpenViking 会误消费待同步意图

- 证据：`SqliteContextSyncTaskQueue.claimNext()` 原先不检查当前启用状态；任务领取后应用服务直接跳过远端处理，Worker 随后会把意图标记成功并删除。
- 影响：关闭期间产生的数据变化丢失补偿意图，重新开启后无法自动同步。
- 修复：outbox 在关闭时不领取既有意图，不修改状态与尝试次数；重新开启后继续领取。
- 验证：新增“排队后关闭不领取、重新开启继续领取”的集成测试。
- 状态：已修复。

### 3.4 P1：Worker 只在启动瞬间恢复过期租约

- 证据：`InternalWorker.start()` 原先只恢复一次。若进程在任务租约尚未到期时重启，启动恢复查不到该任务，后续轮询也不再恢复。
- 影响：任务可永久停留在 `running`，后台数量和实际执行状态随之失真。
- 修复：每次任务领取前先恢复当前已过期租约。现有单通道防重入保证不会恢复本进程仍在执行的任务。
- 验证：新增每轮恢复调用断言，以及“重启时未过期、后续轮询到期后恢复并执行”的单元测试。
- 状态：已修复。

### 3.5 P1：公共写幂等存在业务成功后的崩溃窗口

- 证据：`PublicApiApplicationService.executeIdempotent()` 依次保存空占位、执行业务、另行保存结果，三者不在同一持久事务中。
- 原风险：业务成功而结果保存失败时，旧实现会释放占位；客户端重试可能再次执行创建、删除或发布动作。
- 本次修复：严格区分业务失败和结果完成失败。只有业务动作失败才释放占位；业务已成功后，完成记录失败会返回 `IDEMPOTENCY_COMPLETION_FAILED` 并保留占位，后续相同请求返回 `IDEMPOTENCY_IN_PROGRESS`，禁止重复写入。
- 验证：新增故障注入测试，确认完成记录失败后业务只执行一次且占位不释放。
- 剩余风险：若进程在业务成功与结果落库之间直接退出，占位无法自动还原首次响应，需要管理员核查。完整闭合必须让业务写入与幂等结果共享同一数据库事务，或引入预分配资源 ID 与可恢复操作日志；当前异步应用服务与单 SQLite 连接不能通过简单超时删占位安全解决。
- 状态：已降低重复写入风险，跨崩溃自动恢复未闭合。

### 3.6 P2：公共资源 DELETE 与 HTTP 契约不一致

- 证据：人物、世界和资料永久删除接口原返回 `200` JSON，而接口事实源要求 `204`。
- 修复：三个资源删除接口统一返回 `204` 空正文；幂等层仍保存首次删除结果用于重放和审计；OpenAPI 同步声明空响应。
- 边界：解除人物世界、资料关联和全局范围不是资源永久删除，仍返回 `200` 和更新后的业务对象。
- 验证：OpenAPI 测试确认三个删除操作只声明 `204` 且无 JSON 内容。
- 状态：已修复。

### 3.7 P2：基础设施反向依赖应用层

- 证据：`server/infrastructure/models/SqliteConfiguredModels.ts` 曾从应用服务导入密文上下文函数。
- 影响：破坏依赖方向，基础设施适配器与具体用例实现耦合。
- 修复：把无 I/O 的稳定密文上下文函数下沉到 `server/domain/ai/AiConnectionSecret.ts`，配置应用服务、算法服务和基础设施共同依赖领域函数。
- 门禁：新增“基础设施不得依赖应用层”架构测试，组合根目录除外。
- 状态：已修复。

### 3.8 P2：生产源码使用非空断言掩盖不变量

- 证据：反馈回读、算法步骤、提示词变量、成长与记忆依赖、同步记录、SQLite 写后回读及 Vue 表单共存在多处 `!`。
- 影响：数据库异常或快照损坏时可能退化为不稳定 `TypeError`，无法返回既有业务错误；模板索引变化也可能造成运行时异常。
- 修复：全部改为显式判空、稳定业务错误、写后读一致性错误或按已有条件安全收窄；Vue 算法步骤使用定义与表单数据配对后的行模型。
- 门禁：架构测试使用 TypeScript 语法树扫描生产 `server/`、`shared/`，不以正则误判字符串感叹号。
- 状态：已修复。

### 3.9 P2：AI 接口地址允许非 HTTP(S) 协议

- 证据：共享 Schema 原只拒绝 URL 凭据、查询和片段，`ftp:` 等地址可以保存，但模型适配器运行时无法解析。
- 修复：保存边界只接受 `http:`、`https:`，继续拒绝账号、密码、查询参数和片段。
- 验证：新增非法协议与查询密钥测试。
- 状态：已修复。

### 3.10 P2：OpenViking 设置控制器未在 HTTP 边界解析

- 证据：控制器用 TypeScript 泛型读取未知正文，把运行时校验推迟到应用层。
- 修复：控制器使用共享 Zod Schema 解析后再调用应用服务；应用层保留二次校验。控制器使用外部上下文通用命名，未引入具体适配器依赖。
- 状态：已修复。

### 3.11 P2：当前图文产品文档仍描述已废弃的规格确认和块操作

- 证据：`docs/05-人物生成与反馈迭代.md`、`docs/06-图文文档与导出规范.md` 与高优先级产品决策冲突。
- 修复：统一为“用户条件 → 完整文章 → 内部配图分析 → HTML 混排或文本与图片分离返回”，明确不暴露大纲、规格、锁定和单块重试。
- 状态：已修复。

### 3.12 P3：前端存在确定性死变量

- 证据：严格 `vue-tsc` 报告 AI 算法、人物、世界和资料列表页共 10 个未使用派生统计量。
- 修复：只删除这些无调用变量，不调整组件职责或页面结构。
- 验证：`vue-tsc --noUnusedLocals --noUnusedParameters` 通过。
- 状态：已修复。

## 5. 架构与维护性债务

以下问题不适合在本次缺陷修复中顺带重构：

1. `GenerationApplicationService.ts` 约 2,459 行，同时承担能力检测、人物/世界草稿、兴趣批次、直接文章、历史块兼容、渲染和导出编排。建议后续按已存在用例边界拆成兴趣、直接文章、历史兼容三个应用服务，保持端口和事务语义不变。
2. `ContentApplicationService.ts` 约 1,363 行，聚合人物、世界、资料、头像和删除影响。建议只在新增相关功能时按聚合拆分，避免无业务收益的大规模迁移。
3. 历史 `document_specs`、格式模板和参数方案仍由迁移与兼容读取使用。当前没有生产创建入口，但直接删除会扩大迁移、备份和旧运行恢复风险，本次保留。
4. 公共写幂等的完整跨崩溃恢复应作为独立架构任务，先定义事务边界和故障恢复契约，再修改全部公共写用例；禁止以“占位超时删除”替代幂等保证。
5. `docs/10-开发阶段与任务拆分.md` 和 `docs/开发记录/` 保留原始建设路径。它们不是当前产品事实源，后续应在文档入口进一步标记“历史”，避免被误作现行需求。
