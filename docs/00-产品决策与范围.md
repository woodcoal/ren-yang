# 产品决策与范围

## 文档职责

本文是 MVP 产品范围的唯一事实源。领域语言以 [CONTEXT.md](../CONTEXT.md) 为准；实现细节分别见后续文档。

## 产品定义

系统是一个单人本地运行的“AI 人物模拟、兴趣判断与图文创作工作台”。用户可以从零创建原创人物，也可以利用参考资料建立资料型或混合型人物；系统按当前人物版本判断其对内容的兴趣，或生成符合人物表达方式的结构化图文，并把用户反馈转化为可评测、可发布、可回滚的人物修订。

系统不是聊天机器人、开放世界模拟器、通用知识库或自动微调平台。

## 目标用户与运行环境

- 首期只有一个本地管理员。
- 应用直接运行在长期存活的 Node.js 进程中，不提供 Docker 和桌面壳。
- 本地访问也必须登录。
- 管理界面以桌面端为主，平板可用；移动端只保证查看人物、任务状态和历史。

## 核心价值

1. 人物不是一段不可审计的提示词，而是有来源、版本和发布规则的行为模型。
2. 兴趣判断必须给出置信度、分项因素和证据，而非只有模型理由。
3. 图与文分别生成，以块为单位确认、重试和替换，再统一导出。
4. 反馈先记录事实，再按目标归因；修改当前产物不等于修改长期人物。
5. 任一重要结果都能追溯到人物版本、模型、参数、证据和生成尝试。

## 已确认决策

| 主题 | 决策 |
|---|---|
| 人物来源 | 支持原创、资料型、混合型；参考资料不是必需条件 |
| 资料导入 | MVP 只支持粘贴文本、TXT、Markdown |
| 资料分类 | 人物事实、世界设定、表达样例、创作灵感 |
| 资料优先级 | 已发布用户设定 > 明确原著事实 > 普通参考资料 > AI 推断 |
| 世界设定 | 可选，多个人物可以共享 |
| 未知处理 | 事实必须有证据；偏好与风格可标记为推断；证据不足允许未知 |
| 主验证链 | 图文生成闭环为主，附带基础兴趣判断 |
| 文档计划 | AI 生成文档规格，用户编辑确认后执行 |
| 图片定位 | 图片辅助表达内容，不承诺同一人物外观一致 |
| 场景状态 | 默认仅本次运行有效，可形成候选记忆但不能直接固化 |
| 反馈发布 | 低风险变化评测通过后可自动发布；核心变化人工确认 |
| 导出格式 | HTML、Markdown、Txt，共用一套产物文档 |
| 数据库 | MVP 仅实现 SQLite；PostgreSQL 是未来迁移目标 |
| OpenViking | 可选上下文提供器，关闭后系统主流程仍可运行 |
| 图片模型 | 可选，未配置时禁用图片块生成 |
| 技术栈 | Nuxt 4、TypeScript、Nuxt UI、Drizzle ORM、Zod、nuxt-auth-utils |

## MVP 用户闭环

```text
首次启动并创建管理员
  → 创建人物与可选世界设定
  → 输入或导入文本资料
  → 发布初始人物版本
  → 执行兴趣判断或创建图文任务
  → 确认文档规格
  → 逐块生成、重试、锁定并导出
  → 提交反馈
  → 形成修订提案与候选人物版本
  → 评测并发布或拒绝
  → 必要时回滚
```

## MVP 功能范围

### 管理能力

- 唯一管理员首次设置、登录、退出和本地密码重置。
- 人物、人物版本、世界设定和文本资料管理。
- 格式模板、参数方案、能力状态和系统设置管理。
- 运行历史、块尝试、反馈、修订提案和评测结果查询。
- 完整备份、恢复和显式删除。

### AI 能力

- 从自然语言创建结构化人物候选档案。
- 本地全文检索；配置 OpenViking 后使用语义检索。
- 结构化兴趣判断。
- 结构化文档规格规划。
- 文字块与辅助图片块生成。
- 反馈分类、修订提案和比例化人物评测。

### 文档能力

- 用户编辑、确认和锁定文档规格或产物块。
- 单块失败保留其他成功结果。
- HTML、Markdown、Txt 渲染及包含资源文件的下载包。

## 能力降级

| 配置状态 | 可用能力 | 明确不可用 |
|---|---|---|
| 只配置文本模型 | 人物创建、兴趣判断、文字文档、反馈与版本 | 图片块生成 |
| 配置文本和图片模型 | 完整图文工作流 | 人物外观一致性保证 |
| OpenViking 关闭 | SQLite FTS5 基础检索、完整主流程 | 语义检索与分层上下文 |
| OpenViking 开启 | 语义证据检索、已确认反馈召回 | 不替代业务版本和运行历史 |

管理界面必须显示当前能力状态；能力缺失应在创建任务前阻止不可能的操作，而不是运行中途静默降级。

## MVP 完成标准

完成必须同时满足：

1. [08-测试与验收方案.md](./08-测试与验收方案.md) 中的完整垂直闭环通过。
2. 应用重启后，未完成任务可按状态机恢复或明确失败。
3. 同一运行的输入、人物版本、参数、模型、证据和块尝试可追溯。
4. OpenViking 启用与关闭两条路径均通过验收。
5. 没有图片模型时，纯文本闭环仍完整可用。
6. 备份恢复后，数据库记录与文件清单一致。

## MVP 明确不做

- 多用户、角色权限、多租户、注册、OAuth 和计费。
- Docker、Electron、Tauri、Serverless 和 Edge 部署。
- PostgreSQL 适配、双写、热备和运行时数据库切换。
- PDF、EPUB、DOCX、网页抓取、OCR、目录批量导入和参考图片。
- 人物外观一致性、参考图条件控制和视频生成。
- 多人物自主互动、共享实时世界状态和开放世界模拟。
- 自动 DPO、LoRA 或人物专属模型训练。
- Word、PDF、长图等额外导出格式。
- 修改 OpenViking Studio 承载本项目业务管理。

## 后续业务方向

完成 MVP 后按以下顺序验证，不提前实现：

1. IP 人物渠道化内容运营。
2. 人物一致性与 OOC 审核。
3. 虚拟受众内容预评审。
4. 多人物编剧室、游戏 NPC、品牌人格。
5. 人物运行接口、多租户平台、偏好数据与评测服务。
