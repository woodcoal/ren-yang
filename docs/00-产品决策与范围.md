# 产品决策与范围

## 文档职责

本文是 MVP 产品范围的唯一事实源。领域语言以 [CONTEXT.md](../CONTEXT.md) 为准；实现细节分别见后续文档。

## 产品定义

系统是一个单人本地运行的“AI 人物模拟、兴趣判断与图文创作工作台”。用户可以直接创建人物，并按需选择世界与参考资料；系统使用世界和人物当前有效的灵魂、成长与记忆判断人物对内容的兴趣，或生成符合人物表达方式的结构化图文，并把世界资料、人物反馈和处理记录转化为可审查的长期迭代提案。

系统不是聊天机器人、开放世界模拟器、通用知识库或自动微调平台。

系统同时提供独立版本的公共维护 API，供管理员授权的外部 Agent、脚本和集成系统维护人物、世界和资料库；网页内部接口与公共接口保持不同认证和版本边界。

## 目标用户与运行环境

- 首期只有一个本地管理员。
- 应用直接运行在长期存活的 Node.js 进程中，不提供 Docker 和桌面壳。
- 本地访问也必须登录。
- 管理界面以桌面端为主，平板可用；移动端只保证查看人物、任务状态和历史。

## 核心价值

1. 世界和人物不是不可审计的长提示词：二者都有版本化灵魂和可追溯成长，只有人物额外拥有从有效处理记录中提炼的记忆。
2. 兴趣判断必须给出置信度、分项因素和证据，而非只有模型理由。
3. 用户只提交人物、生成条件、输出格式和图片数量；系统先生成完整文章，再按文章内容生成指定数量配图并直接返回最终结果。
4. 反馈先记录事实，再按目标归因；修改当前产物不等于修改长期人物。
5. 任一重要结果都能追溯到世界与人物心智、模型、参数、提示词预算、证据和生成尝试。

## 已确认决策

| 主题 | 决策 |
|---|---|
| 人物创建 | 不区分来源模式；世界与参考资料均为可选关系 |
| 资料导入 | MVP 只支持粘贴文本、TXT、Markdown |
| 资料分类 | 原著事实、普通参考、表达样例；世界使用独立世界对象 |
| 资料优先级 | 已发布用户设定 > 明确原著事实 > 普通参考资料 > AI 推断 |
| 世界 | 世界是没有记忆的特殊模拟对象；一个世界可包含多个人物，一个具体人物只属于一个世界 |
| 未知处理 | 事实必须有证据；偏好与风格可标记为推断；证据不足允许未知 |
| 主验证链 | 图文生成闭环为主，附带基础兴趣判断 |
| 内容生成 | 按人物个性和生成条件直接生成完整文章，不向用户暴露大纲、规格或块操作 |
| 图片定位 | 图片辅助表达内容，不承诺同一人物外观一致 |
| 图片尺寸 | 图片算法按配置的最大宽高检查模型结果；未超限时原样保留，超限时居中裁剪并同时保留裁剪前原图 |
| 兴趣附加提示词 | 可选且对同一兴趣批次全部文本生效；不提供年龄、地点等结构化场景字段，也不形成成长或记忆 |
| 长期变化 | 灵魂修改始终由用户确认；成长与记忆默认由用户校准发布，管理员为具体对象明确开启学习自动化后，定时提炼结果可直接发布为当前版本 |
| 学习自动化 | 人物与世界分别设置、默认关闭；人物自动提炼并发布成长和记忆，世界只处理成长；检查周期为后台统一小时参数 |
| 提示词预算 | 按模型总上下文、世界、人物、灵魂、成长、记忆和资料分配 Token 预算；核心灵魂不得静默截断 |
| 输出格式 | HTML 按正文位置图文混排；文本返回正文和独立图片数据 |
| 数据库 | MVP 仅实现 SQLite；PostgreSQL 是未来迁移目标 |
| OpenViking | 异步语义与记忆处理器；SQLite 是唯一事实源，FTS5 是持续维护的故障降级能力；已受理操作直接使用 OpenViking 官方任务日志，不进入业务任务历史 |
| 默认模型 | 分别配置默认文本与图片部署；算法步骤显式绑定优先，未绑定时使用同类型默认部署 |
| 模型超时 | 模型部署保存默认请求超时；算法步骤超时为 `0` 时继承该值，正数显式覆盖，实际值在新任务快照中固定 |
| 图片模型 | 可选；算法步骤和默认图片模型均未配置时禁用图片生成 |
| 技术栈 | Nuxt 4、TypeScript、Nuxt UI、Drizzle ORM、Zod、nuxt-auth-utils |
| 公共 API | `/api/v2`；API Key Bearer 鉴权；开放人物、世界、资料库、批量兴趣判定与直接图文运行闭环 |
| 公共人物标识 | `/api/v2` 需要人物的路径、正文、查询和资料关系均接受人物 UUID、用户名或邮箱；响应统一返回 UUID |

## MVP 用户闭环

```text
首次启动并创建管理员
  → 创建世界与人物
  → 输入或导入文本资料
  → 发布世界和人物的初始灵魂
  → 执行兴趣判断或创建图文任务
  → 直接生成完整文章，并按需生成指定数量配图
  → 查看或下载 HTML 混排结果，或分别获取文本和图片数据
  → 提交并筛选人物反馈资料，形成成长候选
  → 累积并筛选人物处理记录，形成记忆候选
  → 审核长期迭代提案
  → 必要时把成长吸收到新灵魂草稿并发布
```

## MVP 功能范围

### 管理能力

- 唯一管理员首次设置、登录、退出、登录后修改密码和忘记密码时的本地重置。
- 人物、世界、灵魂草稿与版本、成长、记忆和文本资料管理。
- 世界资料、人物反馈资料和人物处理记录的逐条及批量状态管理。
- 统一 AI 接口、模型部署、固定算法、提示词版本、能力状态、默认安全限制、备份和审计管理。
- 运行历史、块尝试、分析批次、迭代提案和评测结果查询。
- 完整备份、恢复和显式删除。
- API Key 的创建、一次性明文查看、权限分配、状态查看、立即吊销，以及已吊销 Key 的永久删除。
- `/api/v2/docs` 公共接口文档和 `/api/v2/openapi.json` OpenAPI 3.1 契约。
- 通过 `/api/v2` 创建、查询、取消和整体重试直接图文运行，并渲染、读取图片或下载结果。
- 通过 `/api/v2` 为同一人物批量创建兴趣判定、按输入顺序查询结果，并仅重试一个失败条目。

### AI 能力

- 从自然语言创建自由章节灵魂草稿和运行摘要。
- 从世界资料分析世界成长，从人物反馈资料分析人物成长，从人物处理记录分析人物记忆。
- 按后台统一周期检查已明确开启的对象；仅在存在新素材且没有同类活动批次时创建增量分析并自动发布。
- 持续维护 SQLite FTS5；OpenViking 健康时使用隔离语义检索，并异步处理 Resource、Session 与派生记忆素材。
- 仅在 OpenViking 专属 outbox 保存尚未送达的同步意图；已受理操作直接读取 OpenViking 官方日志，不显示于业务任务列表，不提供单独历史清理。
- 结构化兴趣判断。
- 符合人物个性和生成条件的完整文章生成。
- 基于最终文章的配图位置分析和指定数量图片生成；按图片算法上限二次裁剪并保留裁剪前原图。
- 人物头像不再固定裁剪或缩放；头像算法触发尺寸裁剪时同时保留裁剪结果与供应商原图。
- 反馈分类、修订提案和比例化人物评测。

### 文档能力

- 内部文档快照按文章顺序保存正文与配图，但不向用户暴露技术块操作。
- 图片失败时保留已经成功的完整文章，整体重试只处理失败内容。
- HTML 图文混排渲染、纯文本与图片数据分离返回，以及对应下载包。

## 能力降级

| 配置状态 | 可用能力 | 明确不可用 |
|---|---|---|
| 配置对应文本算法 | 对应的人物创建、兴趣判断、文字文档、反馈与版本能力 | 未配置算法对应的 AI 操作 |
| 配置文章文本与图片算法 | 完整图文工作流 | 人物外观一致性保证 |
| OpenViking 未启用或故障 | SQLite FTS5 检索、管理、资料、世界、人物和生成主流程 | 语义召回、新分析派生和 Session 远端处理 |
| OpenViking 健康 | 世界 User / 人物 Peer 隔离语义检索、Resource 与 Session 处理、受限记忆素材派生 | 自动修改灵魂、自动让成长或记忆生效 |

管理界面必须显示当前能力状态。新运行在创建前完成一次提供器选择并写入快照；尚未创建运行时可以因 OpenViking 故障选择 FTS5，已创建运行不得切换提供器。

## MVP 完成标准

完成必须同时满足：

1. [08-测试与验收方案.md](./08-测试与验收方案.md) 中的完整垂直闭环通过。
2. 应用重启后，未完成任务可按状态机恢复或明确失败。
3. 同一运行的输入、世界和人物心智、提示词预算、参数、模型、证据和块尝试可追溯。
4. OpenViking 健康、启动前故障降级、异步补偿和 SQLite 全量重建路径均通过验收。
5. 没有图片模型时，纯文本闭环仍完整可用。
6. 备份恢复后，数据库记录与文件清单一致。

## MVP 明确不做

- 多用户、角色权限、多租户、注册、OAuth 和计费。
- Docker、Electron、Tauri、Serverless 和 Edge 部署。
- PostgreSQL 适配、双写、热备和运行时数据库切换。
- PDF、EPUB、DOCX、网页抓取、OCR、目录批量导入和参考图片。
- 人物外观一致性、参考图条件控制和视频生成。
- 多人物自主互动、共享实时世界状态和开放世界模拟。
- 世界记忆、人物跨世界共享同一成长或记忆状态。
- 自动 DPO、LoRA 或人物专属模型训练。
- Word、PDF、长图等额外导出格式。
- 修改 OpenViking Studio 承载本项目业务管理。
- 通过公共 API 触发反馈分类、成长提炼等兴趣判定和直接图文生成之外的 AI 运行。

## 后续业务方向

完成 MVP 后按以下顺序验证，不提前实现：

1. IP 人物渠道化内容运营。
2. 人物一致性与 OOC 审核。
3. 虚拟受众内容预评审。
4. 多人物编剧室、游戏 NPC、品牌人格。
5. 扩展公共 AI 运行范围、多租户平台、偏好数据与评测服务。
