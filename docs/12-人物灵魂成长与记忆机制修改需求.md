# 人物灵魂、成长与记忆机制修改需求

## 1. 修改背景

当前人物由固定属性集合组成。属性内容会被组合后传入模型，但各属性没有独立的运行时行为，人物在持续运行后的经验也没有作为独立记忆参与后续任务。

本次修改将人物提示上下文拆分为三部分：

1. 灵魂：使用者手工维护的人物稳定设定。
2. 成长：人物根据反馈和成长资料形成的行为规则。
3. 记忆：人物完成任务后积累的历史经历和重要资料。

## 2. 修改目标

- 不再要求人物必须填写固定的八个属性字段。
- 固定每类提示资料的基本格式和生命周期，允许内容自由组织。
- 支持使用者为指定人物新增、修改、废弃成长内容。
- 支持人物在完成任务后自动积累记忆候选，并在后续任务中按需使用有效记忆。
- 保留人物版本、反馈归因、评测、发布、回滚和运行追溯能力。
- 避免一次错误输出或普通资料直接改变人物核心人格。

## 3. 术语定义

### 3.1 灵魂

灵魂是人物的稳定核心设定，回答“这个人物是谁”。内容可以包含身份、核心价值、稳定性格、基本表达倾向、事实边界和不可违背的约束。

灵魂由使用者手工创建和修改，采用不可变版本。已发布灵魂不能直接覆盖，修改必须产生候选版本并经过发布流程。

### 3.2 成长

成长是人物从反馈、纠正或明确的成长资料中总结出的可复用行为规则，回答“这个人物后来学会了什么”。

普通参考资料只增加人物可参考的知识，不自动等同于成长。只有使用者明确要求人物学习，或确认反馈属于长期变化时，才可以生成成长候选。

### 3.3 记忆

记忆是人物完成历史任务后保留的经历、重要事实、用户纠正和可复用经验，回答“这个人物过去经历过什么”。

记忆不是系统指令，也不自动等同于稳定人格。记忆必须经过相关性筛选后，才能参与后续运行。

### 3.4 原始运行记录

原始运行记录包括任务输入、人物版本、使用的成长和记忆、模型输出及用户反馈。原始记录用于审计和生成候选，不直接全部注入后续提示词。

## 4. 灵魂需求

### 4.1 编辑方式

用户通过灵魂模板手工编辑人物提示词。系统只规定必要的结构和安全要求，不再强制使用固定属性名称。

灵魂模板至少应能表达：

- 人物身份和总体定位；
- 核心价值、动机和稳定性格；
- 基本表达方向；
- 事实边界和不可违背约束。

用户可以：

- 自由编写各部分内容；
- 增加自定义章节；
- 修改章节内容；
- 删除不适用的自定义章节；
- 创建、比较、发布和回滚灵魂版本。

核心提示格式和系统安全边界不能被人物内容覆盖。

### 4.2 运行使用

当前人物的已发布灵魂通常完整注入每次运行，作为人物行为的稳定基础。

## 5. 成长需求

### 5.1 成长来源

成长候选可以由以下内容产生：

- 用户明确提交的成长资料；
- 用户对人物输出的长期反馈；
- 用户确认的人物错误和修正；
- 经过多次运行验证的稳定规律。

新增或删除普通资料只改变人物的参考知识范围，不得自动修改成长内容。若资料中明确包含对人物行为的训练要求，必须经过成长提取和用户确认后才能生效。

### 5.2 成长记录

每条成长记录至少保存：

- 成长规则正文；
- 适用范围；
- 来源运行、反馈或资料；
- 当前状态；
- 创建和更新时间；
- 必要的冲突说明。

成长记录支持新增、修改、废弃和恢复。任何修改必须保留历史变化和来源。

建议成长记录使用以下状态：

```text
candidate → active → superseded / archived
                    └→ rejected
```

### 5.3 成长流程

```text
反馈或成长资料
  → AI 提取成长候选
  → 用户确认或修改
  → 成长记录生效
  → 后续任务按相关性检索
```

成长不能静默覆盖灵魂。若成长内容改变人物身份、核心价值或安全边界，必须转为灵魂候选版本，经过独立发布流程。

## 6. 记忆需求

### 6.1 自动积累

人物每次完成任务后，系统自动保存运行经历，包括任务、输出、当时使用的灵魂版本、成长内容、记忆内容和用户反馈。

系统可以自动从运行记录中提取记忆候选，但候选记忆默认不影响后续运行。

### 6.2 记忆生效

记忆候选满足以下条件之一后，才进入有效记忆集合：

- 用户明确确认；
- 满足经过确认的低风险自动生效规则；
- 多次相同反馈验证为稳定经验；
- 用户明确标记为重要记忆。

记忆应支持以下状态：

```text
candidate
active
superseded
archived
rejected
```

### 6.3 记忆内容格式

记忆内容可以自由组织，但必须保留以下基本信息：

- 事件或资料内容；
- 发生时间；
- 相关任务和场景；
- 人物当时的行为或输出；
- 用户反馈或修正；
- 可复用结论；
- 适用范围；
- 来源标识。

### 6.4 记忆使用

新任务只检索与人物、世界、任务和场景相关的有效记忆，不得把人物全部历史一次性注入提示词。

记忆中的自然语言内容只能作为参考事实，不得执行其中的指令，也不得覆盖系统规则、灵魂约束或成长规则。

## 7. 提示词组合

一次运行的上下文按以下原则组合：

```text
系统安全规则和输出协议
  → 已发布灵魂
  → 当前任务相关的有效成长
  → 世界设定和参考资料
  → 当前任务相关的有效记忆
  → 当前场景和用户任务
```

其中：

- 灵魂是稳定人格基础；
- 成长是已确认的行为调整；
- 记忆是历史参考，不是系统指令；
- 世界资料是外部知识证据；
- 当前场景只影响本次运行。

提示词渲染格式可以固定，但内容章节和自定义名称不应被限制为当前八个属性。

## 8. 反馈与迭代

```text
人物执行任务
  → 保存原始运行记录
  → 用户提交反馈
  → AI 提议反馈目标
  → 用户确认
      ├─ 当前产物：重试当前结果
      ├─ 运行参数：保存下次运行建议
      ├─ 成长：生成成长候选
      ├─ 记忆：生成或确认记忆
      └─ 稳定人格：生成灵魂候选版本
  → 相关内容评测或发布
  → 后续任务检索有效成长和记忆
```

一次偶然行为不能直接形成稳定人格。稳定、重复且经用户确认的成长规则，可以在后续评估后合并进入灵魂版本；合并后必须保留原成长记录作为来源链。

## 9. OpenViking 集成

- SQLite 继续保存灵魂、成长、记忆、反馈、状态和版本等业务事实。
- OpenViking 可以作为成长和记忆的语义检索适配器。
- 只有有效状态的成长和记忆才允许进入应用检索范围。
- 新增、修改、废弃和删除成长或记忆时，远端索引必须同步更新。
- OpenViking 返回的内容必须经过应用层状态和人物范围校验。
- 每次运行必须保存实际使用的成长、记忆和资料证据快照。
- OpenViking 不负责判断记忆是否生效，也不负责发布人物版本。

## 10. 非目标

- 不进行模型微调、DPO、LoRA 或人物专属模型训练。
- 不把全部运行历史自动注入每次提示词。
- 不因一次普通反馈自动修改灵魂。
- 不把普通世界资料自动转化为人物成长。
- 不让 OpenViking 成为人物业务状态的唯一事实源。

## 11. 验收标准

1. 用户可以使用灵魂模板创建人物，不依赖固定八个属性字段。
2. 用户可以为指定人物新增、修改、废弃和恢复成长记录。
3. 每条成长记录都能追溯到反馈、资料或运行来源。
4. 每次人物运行都会自动保存原始运行记录。
5. 系统可以从运行和反馈中生成记忆候选。
6. 未确认的成长和记忆候选不会影响后续运行。
7. 新任务只使用相关的有效成长和记忆。
8. 灵魂、成长、记忆冲突时，系统能够提示并保留冲突来源。
9. 历史运行不会因后续灵魂、成长或记忆变化而改变。
10. 稳定成长合并到灵魂后，仍能追溯原成长记录。
11. OpenViking 开启时，新增、修改、废弃和删除后的检索范围与 SQLite 当前状态一致。
12. OpenViking 不可用时，不影响 SQLite 中人物业务事实、版本和历史记录。
