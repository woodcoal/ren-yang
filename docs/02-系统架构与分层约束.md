# 系统架构与分层约束

## 架构目标

以最少部署单元完成单人本地 MVP，同时把数据库、模型、上下文检索和文件存储隔离在明确接缝后。系统采用 Nuxt 4 长期运行的 Node.js 服务，Web 与内部 Worker 位于同一进程，任务事实保存在 SQLite。

## 技术基线

| 区域 | 选择 |
|---|---|
| 运行时 | Node.js 当前 LTS、长期运行进程 |
| 全栈框架 | Nuxt 4、Nitro Node Server |
| 语言 | TypeScript 严格模式 |
| 包管理 | pnpm |
| UI | Vue 3 Composition API、Nuxt UI |
| 接口校验 | Zod |
| 数据访问 | Drizzle ORM、SQLite |
| 登录会话 | nuxt-auth-utils |
| 软件测试 | Vitest、Nuxt Test Utils、Playwright |

具体依赖版本必须由锁文件固定；本文不写死尚未安装的版本号。

## 运行拓扑

```text
浏览器
  │ HTTPS/HTTP
  v
Nuxt/Nitro 单进程
  ├── 页面与控制器
  ├── 应用服务
  ├── 内部 Worker
  ├── SQLite
  ├── 本地文件存储
  ├── 文本/图片模型适配器 ──> 外部模型接口
  └── 上下文适配器 ─────────> SQLite FTS5 / OpenViking
```

不使用 Nitro 实验性 Tasks 和 Database 作为核心事实源。Worker 是应用内部受控循环，任务状态由应用自己的任务表管理。

## 严格分层

```text
表现层：页面、控制器、认证中间件
                ↓
应用层：用例编排、事务边界、任务协调
                ↓
领域层：人物、版本、反馈、文档和状态规则
                ↓
端口：数据访问、模型、上下文、文件、时间等接口
                ↓
基础设施层：Drizzle、SQLite、OpenViking、HTTP 模型、本地文件适配器
```

### 表现层

- `server/api/` 文件是控制器，只负责认证、解析请求、调用一个应用服务方法和映射响应。
- 控制器可以使用共享 Zod Schema，但不能导入 Drizzle、SQLite、模型 SDK、OpenViking SDK 或文件系统实现。
- `app/pages/` 是页面组合层，不承载完整业务逻辑。
- 页面只通过服务端接口访问业务数据，不直接读取本地文件或数据库。

### 应用层

- 应用服务是业务编排的唯一入口。
- 应用服务可以调用领域模块以及注入的数据访问、模型、上下文和文件端口。
- 事务由应用服务定义，不由控制器或 UI 定义。
- Worker 必须调用应用服务，不能直接调用仓储或外部适配器。
- 一个应用服务方法对应一个明确用例，不创建仅转发参数的浅层方法。

### 领域层

- 保存状态机、不变式、差异计算、参数合并和发布判定等纯业务逻辑。
- 不依赖 Nuxt、H3、Drizzle、Node 文件系统或第三方 SDK。
- 使用明确输入并返回结果；I/O 副作用由应用层协调。

### 端口与基础设施层

- 数据访问端口隐藏查询和持久化细节，Drizzle/SQLite 是其适配器。
- 文本模型、图片模型、上下文提供器和文件存储各自拥有小接口。
- OpenViking 与本地 FTS5 是上下文端口的两个真实适配器。
- 生产外部适配器和测试适配器通过同一接口接受契约测试。
- 基础设施层不能回调控制器或页面。

## 禁止依赖

| 调用方 | 禁止直接依赖 |
|---|---|
| 页面 | 数据库、文件系统、模型、OpenViking |
| 控制器 | 仓储实现、Drizzle、模型 SDK、OpenViking SDK |
| Worker | 仓储实现、模型 SDK、文件系统实现 |
| 领域模块 | Nuxt、H3、Drizzle、网络和文件系统 |
| 数据适配器 | 应用服务、控制器、UI |

代码审查应使用依赖方向检查这些规则；不为分层创建无行为的 DTO 复制层。

## 深模块

| 模块 | 对外接口职责 | 隐藏的复杂度 |
|---|---|---|
| 人物档案 | 创建候选、发布、回滚、读取当前版本 | 来源优先级、不可变快照、差异、风险 |
| 人物运行 | 创建兴趣或生成运行、查询结果 | 参数解析、证据检索、模型编排、快照 |
| 图文文档 | 确认规格、重试块、锁定块、渲染 | 块依赖、尝试历史、格式差异、资源路径 |
| 反馈学习 | 记录反馈、归因、提出修订 | 目标识别、候选记忆、冲突和风险分类 |
| 评测门禁 | 执行评测、给出发布结论 | 硬校验、回归用例、模型评分、退化判断 |
| 任务执行 | 入队、取消、恢复、完成 | 租约、心跳、尝试次数、超时和进程重启 |

## 典型调用链

```text
POST /api/generation-runs
  → 控制器校验 CreateGenerationRunInput
  → GenerationApplicationService.createRun()
  → 领域规则校验能力、人物版本和参数
  → 仓储事务写入运行与任务
  → 控制器返回 202 + runId

Worker 领取任务
  → GenerationApplicationService.executeRun(runId)
  → ContextPort.retrieveEvidence()
  → TextModelPort / ImageModelPort
  → ArtifactFilePort.save()
  → 仓储事务写入尝试、结果和任务状态
```

## 进程生命周期

1. 启动时加载并校验非敏感配置和外部密钥状态。
2. 执行 SQLite 迁移并检查完整性。
3. 初始化唯一适配器实例。
4. 启动 Nuxt 服务和内部 Worker 循环。
5. Worker 对过期运行租约执行恢复。
6. 收到退出信号后停止领取新任务，等待当前安全点并关闭连接。

启动失败必须明确指出配置、迁移或数据目录问题；不以静默降级绕过数据库损坏和会话密钥缺失。
