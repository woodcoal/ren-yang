# 系统架构与分层约束

## 架构目标

以最少部署单元完成单人本地 MVP，同时把数据库、模型、上下文检索和文件存储隔离在明确接缝后。系统采用 Nuxt 4 长期运行的 Node.js 服务，Web 与内部 Worker 位于同一进程，任务事实保存在 SQLite。

## 技术基线

| 区域 | 选择 |
|---|---|
| 运行时 | Node.js 当前 LTS、长期运行进程 |
| 全栈框架 | Nuxt 4、Nitro Node Server |
| 语言 | TypeScript 严格模式 |
| 包管理 | pnpm |
| UI | Vue 3 Composition API、Nuxt UI |
| 接口校验 | Zod |
| 数据访问 | Drizzle ORM、SQLite |
| 登录会话 | nuxt-auth-utils |
| 软件测试 | Vitest、Nuxt Test Utils、Playwright |

具体依赖版本必须由锁文件固定；本文不写死尚未安装的版本号。

## 运行拓扑

```text
浏览器
  │ HTTPS/HTTP
  v
Nuxt/Nitro 单进程
  ├── 页面与控制器
  ├── 应用服务
  ├── 内部 Worker
  ├── SQLite
  ├── 本地文件存储
  ├── 文本/图片模型适配器 ──> 外部模型接口
  └── 上下文适配器 ─────────> SQLite FTS5 / OpenViking

外部 Agent / 脚本
  │ Authorization: Bearer <api_key>
  v
/api/v2 公共控制器 ─────────> 同一应用服务与 SQLite 事实源
```

不使用 Nitro 实验性 Tasks 和 Database 作为核心事实源。Worker 是应用内部受控循环，任务状态由应用自己的任务表管理。

## 严格分层

```text
表现层：页面、控制器、认证中间件
                ↓
应用层：用例编排、事务边界、任务协调
                ↓
领域层：模拟对象、灵魂、成长、记忆、反馈、文档和状态规则
                ↓
端口：数据访问、模型、上下文、文件、时间等接口
                ↓
基础设施层：Drizzle、SQLite、OpenViking、HTTP 模型、本地文件适配器
```

### 表现层

- `server/api/` 文件是控制器，只负责认证、解析请求、调用一个应用服务方法和映射响应。
- `/api/v1` 是网页登录会话使用的内部接口；`/api/v2` 是 API Key 鉴权的公共接口。两者复用应用服务，不能互相转发 HTTP 请求。
- `/api/v2/openapi.json` 与 `/api/v2/docs` 只公开公共契约，不要求 API Key；其余 `/api/v2` 路径必须先完成 Bearer Key 认证和权限检查。
- 公共兴趣与图文接口和网页接口复用 `GenerationApplicationService`；公共控制器只增加权限、持久幂等、审计、ISO 时间转换和二进制响应头。
- 控制器可以使用共享 Zod Schema，但不能导入 Drizzle、SQLite、模型 SDK、OpenViking SDK 或文件系统实现。
- `app/pages/` 是页面组合层，不承载完整业务逻辑。
- 页面只通过服务端接口访问业务数据，不直接读取本地文件或数据库。

### 应用层

- 应用服务是业务编排的唯一入口。
- 应用服务可以调用领域模块以及注入的数据访问、模型、上下文和文件端口。
- 事务由应用服务定义，不由控制器或 UI 定义。
- Worker 必须调用应用服务，不能直接调用仓储或外部适配器。
- 一个应用服务方法对应一个明确用例，不创建仅转发参数的浅层方法。
- 已固定主体快照的文本算法调用在应用层按缓存亲和键调度：同键 FIFO 串行、异键并行；调度器只存在于当前进程，不改变 SQLite 任务、租约、幂等、重试或输出契约。

### 领域层

- 保存灵魂章节与版本、成长/记忆修订、分析提案、提示词预算、状态机、差异计算和发布判定等纯业务逻辑。
- 不依赖 Nuxt、H3、Drizzle、Node 文件系统或第三方 SDK。
- 使用明确输入并返回结果；I/O 副作用由应用层协调。

### 端口与基础设施层

- 数据访问端口隐藏查询和持久化细节，Drizzle/SQLite 是其适配器。
- 文本模型、图片模型、上下文提供器和文件存储各自拥有小接口。
- `AiConfigurationRepository` 隔离加密接口、模型部署和算法配置版本；`AiModelFactory` 只在算法步骤执行时使用临时解密凭据创建模型端口，不缓存密钥。
- AI 算法的步骤、顺序、变量组装和输出 Schema 位于领域与应用代码；SQLite 只保存固定步骤的模型、提示词和参数绑定，不能把数据库配置提升为任意代码执行器。
- OpenViking 与本地 FTS5 是上下文端口的两个真实适配器；运行创建前选择一次，运行快照固定实际提供器。
- SQLite 同时承担唯一业务事实源、持久任务队列、OpenViking 投影状态和重建来源，不把 OpenViking 当作主库。
- OpenViking 的 Resource、Session、派生内容和删除写入只能由 Worker 调用上下文同步应用服务；控制器和 Worker 均不得跨层直连适配器。
- 生产外部适配器和测试适配器通过同一接口接受契约测试。
- 基础设施层不能回调控制器或页面。

## 禁止依赖

| 调用方 | 禁止直接依赖 |
|---|---|
| 页面 | 数据库、文件系统、模型、OpenViking |
| 控制器 | 仓储实现、Drizzle、模型 SDK、OpenViking SDK |
| Worker | 仓储实现、模型 SDK、文件系统实现 |
| 领域模块 | Nuxt、H3、Drizzle、网络和文件系统 |
| 数据适配器 | 应用服务、控制器、UI |

代码审查应使用依赖方向检查这些规则；不为分层创建无行为的 DTO 复制层。

## 深模块

| 模块 | 对外接口职责 | 隐藏的复杂度 |
|---|---|---|
| 灵魂管理 | 编辑草稿、发布、基于历史创建草稿、读取当前版本 | 自由章节、不可变发布版本、差异、运行摘要预算 |
| 成长迭代 | 管理原始资料、创建分析、审核提案 | 世界/人物来源边界、修订、合并、取代、冲突 |
| 人物记忆 | 管理处理记录、分析和审核记忆 | 独立证据、去重、自我强化防护、OpenViking 派生素材 |
| 人物运行 | 创建单条/批量兴趣或生成运行、查询结果、单项重试 | 心智范围、Token 预算、固定缓存前缀、证据检索、逐项校验、模型与算法快照 |
| 图文文档 | 创建直出任务、查询结果、取消、整体重试、渲染和导出 | 完整文章生成、后置配图分析、内部顺序快照、格式差异和资源路径 |
| 反馈学习 | 记录反馈、归因、指导当前产物重试或转为成长素材 | 目标识别、来源边界和人工确认 |
| 任务执行 | 入队、取消、恢复、完成 | 租约、尝试次数、协作取消和进程重启 |
| AI 配置与算法 | 管理加密连接和模型部署、发布固定算法配置、执行步骤 | 凭据上下文绑定、动态端点、不可变配置、运行快照、缓存亲和调度和输出校验 |
| 公共 API 访问 | 创建/吊销 Key、认证、权限、幂等和审计 | 明文一次性返回、摘要索引、永久幂等结果、请求追踪和公共响应映射 |

## 典型调用链

```text
POST /api/v1/generation-runs
或 POST /api/v2/generation-runs
  → 控制器校验 CreateGenerationRunInput
  → GenerationApplicationService.createGenerationRun()
  → 领域规则校验能力、世界/人物心智、参数和提示词预算，并固定文章生成、正文修正与可选配图分析、图片生成算法快照
  → 仓储事务写入运行与任务
  → 控制器返回 202 + runId

Worker 领取任务
  → GenerationApplicationService.executeRun(runId)
  → ContextPort.retrieveEvidence()
  → TextModelPort / ImageModelPort
  → ArtifactFilePort.save()
  → 仓储事务写入尝试、结果和任务状态
```

## 进程生命周期

1. 启动时加载并校验非敏感配置和外部密钥状态。
2. 执行 SQLite 迁移并检查完整性。
3. 初始化唯一适配器实例。
4. 启动 Nuxt 服务和内部 Worker 循环。
5. Worker 对过期运行租约执行恢复。
6. 收到退出信号后停止领取新任务，等待当前安全点并关闭连接。

启动失败必须明确指出配置、迁移或数据目录问题；不以静默降级绕过数据库损坏和会话密钥缺失。
