# 测试与验收方案

## 测试目标

测试分为软件正确性和人物行为质量两套体系。前者验证状态、数据、接口与渲染是否可靠；后者验证人物表达是否符合设定。不得用主观模型评分替代确定性软件测试，也不得用代码覆盖率代表人物质量。

## 测试分层

| 层级 | 工具 | 重点 |
|---|---|---|
| 领域单元测试 | Vitest | 灵魂版本、成长/记忆修订、分析提案、提示词预算、证据优先级和任务转换 |
| 应用服务测试 | Vitest + 测试适配器 | 用例编排、事务边界、权限、降级与失败恢复 |
| 基础设施集成测试 | Vitest + 真实 SQLite + 临时文件系统 | 迁移、查询、FTS5、租约、文件一致性 |
| 组件测试 | Nuxt Test Utils | 表单、状态反馈、差异展示和能力禁用 |
| 端到端测试 | Playwright | 少量高价值主流程 |
| 反馈闭环测试 | Vitest + 真实 SQLite | 分类确认、修正重试、成长素材转换和人工发布边界 |

不设置形式化高覆盖率门槛。关键不变式、状态转换、数据恢复和导出正确性必须有测试，纯展示代码按风险选测。

## 领域与应用测试

至少覆盖：

- 人物蒸馏固定使用资料分类、认知提取、灵魂综合和候选评测四个模型步骤；步骤与顺序不能由数据库改变。
- 人物蒸馏状态机拒绝越序推进；全部非终态允许协作式取消，模型执行状态可以明确失败并通过新运行重试。
- 相同原始作品、访谈或事件的转载和切片只计一个独立来源；六类资料覆盖按独立来源统计，不使用单一综合分数。
- 模型候选只能引用本次运行输入，引文必须能在固定正文中定位；明确陈述、观察结论和推断分别满足来源关系与诚实边界规则。
- 反对证据必须保留为显式冲突；重复候选合并证据、最高置信度和冲突，但不虚增独立来源。
- 无有效候选、证据越界、未知边界捏造和候选哈希未通过对应评测属于硬失败；资料缺口、推断结论和非独立评分只形成具体软警告。
- 最终候选编辑后旧评测立即失效；只有候选正文哈希与最近通过硬门禁的评测哈希一致时才能创建人物。
- 用户发布设定高于原著事实，原著事实高于普通资料，普通资料高于 AI 推断。
- 事实缺少证据时不能伪装为确定事实；允许输出未知。
- 世界和人物灵魂使用自由章节；草稿可编辑，发布版本不可修改，回滚基于历史创建新草稿。
- 世界只有灵魂和成长，不允许创建处理记录或记忆。
- 兴趣附加提示词只进入当前批次各条运行，不写入灵魂、成长或记忆；后台不再提交年龄、地点等结构化场景。
- 反馈能归因到当前产物、参数、人物学习、灵魂修改或资料事实。
- 普通反馈只有经用户确认后才进入 OpenViking Session，并在人物学习目标下转为人物反馈资料；未确认反馈不能被补偿扫描读取，普通人物资料不能作为成长来源。
- 手动成长和记忆流程继续要求用户发布；对象级学习自动化默认关闭，明确开启后定时提炼结果允许直接形成不可变当前版本。
- 删除或禁用原始资料不自动改变已确认成长或记忆。
- 记忆证据信号由程序依据批次输入类型派生，模型只能引用输入 UUID；同一任务记录只计一个独立证据，处理记录分析正文不包含人物完整文章或回答。
- 记忆转成长必须先转为反馈资料，成长吸收灵魂必须经过草稿发布。
- 图片能力关闭时拒绝图片数量大于零的运行，但允许纯文本运行。
- 完整文章只调用一次文本生成；配图分析必须基于最终文章并返回与请求严格一致的数量和有效段落位置。
- HTML 按分析位置从头到尾混排图片；文本正文不含图片占位符，图片通过独立资产数据返回。
- 图片未超过算法最大宽高时字节不变；超限时只裁剪超出维度并保留原图，最终图与原图均可读取、备份和删除。
- 上传或未触发算法尺寸规则的人物头像保持原始尺寸，不执行固定 512×512 裁剪或缩放；算法触发二次裁剪时结果图与原图均可读取，后续未裁剪替换会清除旧原图。
- 图片失败时保留成功文章并标记部分成功；整体重试不重复生成已成功正文，只处理失败图片。
- 图片生成提示只包含人物与世界视觉身份、视觉简报、必要前文和负面约束，不包含成长、记忆、普通资料证据或无关场景全文。
- 调用前按世界和人物父子 Token 预算选择上下文；无精确分词器时使用标记为估算的保守计数。
- 灵魂摘要超限阻止发布或运行，成长、记忆和资料达到预算后整条跳过并保存原因。
- 成功响应和结构校验失败响应都保存供应商用量，自动重试和手工重试不能覆盖既有用量。
- 文本步骤关闭思考时仅发送模型部署声明的一种请求字段；未声明字段的模型拒绝执行。最大输出 Token 不设上限，值为 `0` 时请求不发送该字段。
- 模型部署默认超时进入管理视图和持久化记录；算法步骤超时为 `0` 时在任务创建阶段继承所选模型默认值，正数显式覆盖，模型配置后续修改不改变旧任务快照。
- 取消、失败、部分成功和重启恢复符合状态机。
- 控制器与 Worker 都只通过应用服务执行业务用例。
- 公共 API Key 明文只在创建响应出现一次，数据库、日志、审计和列表均不包含明文。
- 无 Key、无效、过期和吊销 Key 返回统一 `401`；权限不足返回 `403`，且不进入业务用例。
- 相同 Key、方法、路径、幂等键和载荷只执行一次；载荷变化返回 `409`。
- `/api/v2` 人物、世界、资料和必要关系复用网页端应用服务的校验、引用约束、状态与删除规则。
- `/api/v2` 所有人物引用均可使用 UUID、用户名或邮箱，并统一解析为真实 UUID；覆盖大小写、首尾空白、不存在、跨字段歧义和 v1 仍只接受 UUID。
- 后台和 `/api/v2` 批量兴趣创建与查询始终保持输入顺序；同一人物多项只发起一次主调用，整批附加提示词在单项重试时保持不变，单项缺失或格式错误不影响其他项，单项重试不携带旧回答且不重跑全批。
- 同一人物心智下的兴趣判断、文章生成和正文修订保持系统消息逐字一致；本次文本、附加提示词和检索证据只进入用户消息，缓存亲和键由实际系统消息哈希生成。
- 提示词发布校验每个变量的 system/user 位置与稳定/变化缓存角色，JSON 编码变量在调用前验证；历史版本使用发布时固定的变量契约而非当前定义。
- 完整 system 与 user 提示在供应商调用前同时接受字符上限、上下文窗口、输出预留、安全余量和累计 Token 门禁；结构输出失败只追加固定 user 修正要求重试一次，system 与缓存亲和键不变且两次用量累计。
- GPT-5.6 缓存亲和调用发送稳定 `prompt_cache_key`、显式缓存模式和系统消息末尾断点；其他兼容模型及后台算法诊断不发送缓存扩展字段。

## SQLite 与文件集成测试

每个测试套件使用独立临时目录和真实 SQLite 文件，不使用与生产行为不同的内存替代品验证关键持久化逻辑。

验证项：

- 从空数据库执行全部迁移后结构正确。
- 旧人物八字段和世界单正文无损迁移为灵魂章节；旧运行仍可读取旧快照。
- 当前迁移基线仅支持重新初始化的数据库；`0010` 后的历史迁移链已合并。重新初始化后既有模型部署默认无关闭思考格式，算法步骤模型列允许为空，图片资产可选原图字段完整，外键与完整性检查通过，重复启动不重复迁移。
- 空库和既有库迁移后均包含十五个固定算法；重复启动不重复迁移，外键与完整性检查通过。
- 重复启动不会重复应用迁移或破坏数据。
- 外键、唯一约束、检查约束和必要索引生效。
- 新建和既有数据库中的模型部署均具有 60000 毫秒默认超时，且数据库拒绝超出 1000–120000 毫秒范围的值。
- FTS5 索引写入、删除、重建和检索结果可预测。
- 世界/人物灵魂发布、当前版本切换、草稿删除和审计位于同一事务。
- 分析批次与输入任务原子创建；提案重复审核不会重复应用修订。
- 两阶段分析分别保存模型提取原文和程序校验事实；空事实不调用综合且不创建草稿，学习提示词版本或草稿在分析期间变化时以 `VERSION_CONFLICT` 结束而不覆盖现状。
- 运行与任务创建位于同一事务，失败不留下孤立任务。
- 任务租约竞争只允许一个 Worker 成功领取。
- 前台 Worker 只领取 `task_jobs` 中的业务任务，OpenViking Worker 只领取专属 outbox 中的三类同步意图；OpenViking 长请求期间前台 Worker 仍能独立轮询。
- 旧 `task_jobs` 中的 OpenViking 活动项升级后进入 outbox，终态历史被移除；业务任务列表、顶部与侧栏计数不包含 OpenViking。
- OpenViking outbox 成功或终止后不留历史，管理页直接读取各受管 User 的官方 `/api/v1/tasks` 日志，页面不存在 OpenViking 清理入口。
- 数据库记录与资料原文件、图片资产引用一致；导出按请求即时生成，不存在持久导出文件引用。
- 删除影响分析覆盖引用中的文件，且不越过数据目录边界。
- WAL 模式下备份得到一致副本。

测试结束只删除测试自身创建的临时目录。

## 外部能力测试

文本模型、图片模型和 OpenViking 均通过端口提供测试适配器：

- 测试适配器返回固定成功、结构错误、超时、限流和永久失败结果。
- 同一组契约测试验证生产适配器和测试适配器的输入输出语义。
- 模型结构化输出必须经过 Zod 校验，修复重试达到上限后明确失败。
- OpenViking 开启时验证世界/User、人物/Peer 投影隔离，世界/人物/反馈 Resource，Peer Session，派生素材门禁，删除、精确 URI 检索和重建；故障时验证 FTS5 接管新运行。
- 外部服务故障不得破坏已经提交的业务事实和成功块。

自动化测试不调用真实收费模型，避免成本、速率和随机性。真实模型只进入手工验收。

## 组件测试

使用 Nuxt Test Utils 以用户可见行为为断言，重点覆盖：

- 首次管理员初始化与登录错误；已登录管理员修改密码必须校验当前密码、撤销其他旧会话并保持当前会话有效。
- 人物创建与草稿助手不显示或提交来源模式，参考资料为空时仍可创建。
- 世界人物管理只搜索独立人物，添加和解除关系均不删除人物数据。
- 人物成长页区分反馈资料与成长结果，记忆页区分处理记录与记忆结果。
- 世界页包含灵魂和成长且不存在记忆入口。
- 批量启用、禁用、删除和审核显示明确影响。
- 提示词预算显示父子占用、估算方式和跳过原因。
- 证据和推断标识清楚可见。
- 图片能力关闭时图片选项禁用且原因可见。
- 直接生成表单一次提交人物、生成条件、输出格式和图片数量。
- 兴趣表单一次提交同一人物的一至二十条文本和可选附加提示词，不显示年龄、地点、目标、情绪或事件。
- AI 管理侧栏分别显示“模型配置”和“算法配置”；模型页最后一个选项卡只维护默认文本与图片模型，不恢复旧内容模板、参数方案或场景参数。
- 算法步骤显式模型优先；步骤模型为空时，新任务解析同类型默认部署并固定到快照；两者都没有时返回明确能力错误。模型部署可编辑默认超时，算法步骤超时默认 `0` 并说明继承语义；文本步骤显示关闭思考开关与输出 Token 的零值说明，图片步骤不显示关闭思考开关。
- HTML 结果只在无脚本沙箱中显示；文本结果明确分隔正文与图片区域。
- 运行状态、部分成功、失败和重试操作正确显示。
- 灵魂没有自动发布入口；成长与记忆只有对象级开关明确开启时允许定时自动发布，关闭开关不创建该对象的定时分析任务。
- 学习自动化周期未到时不扫描；到期后只处理已启用且开启开关的对象，单对象无新素材、无素材、缺灵魂或已有活动批次不影响其他对象。
- 自动批次创建时固定 `auto_publish`，完成时在同一事务中保存模型结果、创建当前版本、清理草稿并完成批次；手动批次仍只生成草稿。
- 后台统一周期限制为 1–720 小时，默认 24 小时；修改后从保存时刻重算下次执行时间并持久保留。
- API Key 创建后显示一次完整明文；权限中文名与稳定标识分两行；到期日期和时间上下排列，日期通过 Nuxt UI 弹出日历选择，时间通过小时与分钟下拉选择。吊销后状态立即更新，只有已吊销 Key 可永久删除。
- `/api/v2/docs` 只展示公共接口，能输入 Bearer Key 直接试调，权限、分页、示例和错误码完整。
- 危险 HTML 和 Markdown 不被执行。

不要对 Nuxt UI 内部 DOM 结构或样式类做脆弱快照断言。

## 端到端主流程

Playwright 使用隔离 SQLite 数据目录、本地协议替身和真实生产 Nitro 服务，自动覆盖以下最高价值闭环：

1. 首次启动设置管理员，退出后重新登录；在系统中心修改密码后使用新密码再次登录。
2. 创建默认启用的世界和人物，确认初始灵魂立即生效，并分别保存新的灵魂历史版本。
3. 创建文本直接生成运行并下载文本结果，再创建带图 HTML 运行并核对图文顺序。
4. 添加人物反馈资料和处理记录，分别生成并审核成长与记忆候选。
5. 核对全局账户、后台任务与能力状态，并在 AI 管理查看接口、模型和固定算法配置。

反馈确认与提示词发布、备份恢复、OpenViking 能力组合和异常退出恢复依赖真实数据库、文件或进程边界，继续由 Vitest 集成测试和生产 HTTP/CLI 验收覆盖，不在浏览器层重复构造同一事实。发现页面编排回归风险时，再增加对应 Playwright 场景。

附加降级路径：

- OpenViking 关闭时，通过 FTS5 完成人物生成。
- OpenViking 开启但在运行创建前不可用时，新运行固定使用 FTS5；已创建运行不得在执行中更换提供器。
- Peer Session 派生内容只能成为分析素材或候选，不能直接进入运行提示词。
- FTS5 只能召回当前 active 成长和记忆，候选、归档、取代和拒绝状态均不可见。
- 图片模型未配置时，完成纯文本生成和导出。
- 进程在任务执行中重启后，过期租约能恢复且不会重复写入成功结果。

## 反馈闭环验证

当前产物反馈必须进入本次重试提示并新增一次可审计尝试；人物学习反馈只创建默认启用的成长素材，未经成长分析和人工发布不得改变后续任务提示词。参数建议与资料事实问题必须保持为可追溯记录，不得产生隐式业务修改。

## 手工真实模型验收

配置完成后先执行 `pnpm acceptance:preflight`。该命令只校验会话密钥、文本模型和图片模型配置，输出模型名称及接口来源，不联网、不发起收费请求，也不输出密钥。前置检查通过后再启动独立验收数据目录执行以下项目。

发布 MVP 前，使用实际配置至少验证：

- 人物在资料为空时能表达稳定风格，同时承认未知事实。
- 人物关联原著资料后能引用正确证据，不把 AI 推断描述为原著事实。
- 用户设定与资料冲突时遵循证据优先级。
- 同一人物完成兴趣判断，以及指定格式、指定图片数量的直接图文生成。
- 文章符合用户条件和人物个性；HTML 图片位置合理，文本正文与图片数据分离。
- 图片生成失败时保留文本块并呈现部分成功。
- 反馈不会直接污染灵魂；灵魂始终人工发布，成长与记忆仅在对象明确开启学习自动化时可按固定周期自动发布。

由于模型输出存在随机性，手工验收记录输入、模型、参数和结果，不要求逐字一致。

## MVP 验收矩阵

| 能力 | 成功条件 |
|---|---|
| 登录 | 未登录无法访问业务页和接口；会话重启策略符合配置 |
| 人物 | 创建不区分来源模式；自由章节灵魂、成长和记忆边界正确 |
| 世界 | 具备灵魂和成长但没有记忆；可模糊搜索添加独立人物并解除人物关系 |
| 资料 | 粘贴文本、TXT、Markdown 可导入、检索和删除分析 |
| 兴趣 | 后台和 API 均支持同一人物一至二十条批量判断及整批附加提示词，返回结构化分值、结论、理由、证据和不确定性 |
| 直接生成 | 输入人物、条件、格式和图片数量后无需大纲或规格确认即可得到最终文章 |
| 文本结果 | 正文符合人物个性与条件，且不包含图片占位符 |
| 图片结果 | 有模型时严格生成指定数量本地资源；无模型时图片数量入口正确禁用 |
| 导出 | HTML 按正文位置混排图片；文本正文与图片资产分离，资源路径和哈希正确 |
| 反馈 | 分类可追溯；转为反馈资料必须人工确认 |
| 迭代 | 世界成长、人物成长和人物记忆具备原始数据、批次、提案、修订与审核闭环 |
| 提示词预算 | 世界和人物父子预算在调用前生效，选入与跳过内容可解释 |
| OpenViking | 多范围投影、故障降级、异步补偿与全量重建可用，SQLite 始终保存唯一业务事实 |
| 任务 | 业务队列只包含生成、兴趣、成长和记忆；OpenViking 专属 outbox 独立串行、可恢复且不产生本地历史 |
| 备份恢复 | 备份一致、清单完整、恢复前可验证、失败不覆盖现有数据 |
| 删除 | 先展示影响范围，确认后完整删除且不越界 |
| 安全 | 密钥不入库、不入备份、不入日志；不可信内容不能执行 |
| 公共 API | Key 认证/权限/吊销、人物世界资料闭环、批量兴趣创建/查询/单项重试、直接图文运行创建与结果读取、关系维护、幂等、审计和 OpenAPI 契约通过；不包含其他 AI 运行 |

## 完成判定

- 自动化测试在干净环境通过。
- 数据库可从零迁移，备份可验证，任务可从重启恢复。
- Playwright 核心闭环通过；其余端到端主流程与降级路径有可复现的集成或生产验收证据。
- 手工真实模型验收有记录，没有未处理的阻断问题。
- 产品范围内每项验收条件都有对应证据；范围外事项不阻止 MVP 完成。
