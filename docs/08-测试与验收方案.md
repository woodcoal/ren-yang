# 测试与验收方案

## 测试目标

测试分为软件正确性和人物行为质量两套体系。前者验证状态、数据、接口与渲染是否可靠；后者验证人物表达是否符合设定。不得用主观模型评分替代确定性软件测试，也不得用代码覆盖率代表人物质量。

## 测试分层

| 层级 | 工具 | 重点 |
|---|---|---|
| 领域单元测试 | Vitest | 证据优先级、版本状态、反馈风险、文档依赖、任务转换 |
| 应用服务测试 | Vitest + 测试适配器 | 用例编排、事务边界、权限、降级与失败恢复 |
| 基础设施集成测试 | Vitest + 真实 SQLite + 临时文件系统 | 迁移、查询、FTS5、租约、文件一致性 |
| 组件测试 | Nuxt Test Utils | 表单、状态反馈、差异展示和能力禁用 |
| 端到端测试 | Playwright | 少量高价值主流程 |
| 人物行为评测 | 评测用例与人工复核 | 一致性、事实、风格、禁用项和回归 |

不设置形式化高覆盖率门槛。关键不变式、状态转换、数据恢复和导出正确性必须有测试，纯展示代码按风险选测。

## 领域与应用测试

至少覆盖：

- 用户发布设定高于原著事实，原著事实高于普通资料，普通资料高于 AI 推断。
- 事实缺少证据时不能伪装为确定事实；允许输出未知。
- 已发布人物版本不可修改，回滚只切换当前版本指针。
- 场景状态默认不进入长期人物，只能形成候选记忆。
- 反馈能归因到当前产物、参数、长期人物或资料事实。
- 事实、价值观和禁用项变更必须人工确认。
- 低风险风格或兴趣提案只有在评测通过后才能自动发布。
- 图片能力关闭时拒绝图片块，但允许纯文本运行。
- 文档规格拒绝循环依赖、未知依赖和无能力支持的块。
- 块重试不覆盖历史尝试，锁定块不被批量重试替换。
- 文字块与图片块分别计数；单块累计尝试达到快照上限后，整文和手工重试都不能继续调用供应商。
- 调用前按准确提示字符数拒绝超限输入；供应商响应后按已报告 Token 累计执行运行级上限。
- 成功响应和结构校验失败响应都保存供应商用量，自动重试和手工重试不能覆盖既有用量。
- 取消、失败、部分成功和重启恢复符合状态机。
- 控制器与 Worker 都只通过应用服务执行业务用例。

## SQLite 与文件集成测试

每个测试套件使用独立临时目录和真实 SQLite 文件，不使用与生产行为不同的内存替代品验证关键持久化逻辑。

验证项：

- 从空数据库执行全部迁移后结构正确。
- 旧运行和参数方案的五字段参数 JSON 可通过 Schema 默认值读取新增限制，无需数据迁移。
- 重复启动不会重复应用迁移或破坏数据。
- 外键、唯一约束、检查约束和必要索引生效。
- FTS5 索引写入、删除、重建和检索结果可预测。
- 人物发布、当前版本切换和审计记录位于同一事务。
- 运行与任务创建位于同一事务，失败不留下孤立任务。
- 任务租约竞争只允许一个 Worker 成功领取。
- 数据库记录与资料、产物和导出文件引用一致。
- 删除影响分析覆盖引用中的文件，且不越过数据目录边界。
- WAL 模式下备份得到一致副本。

测试结束只删除测试自身创建的临时目录。

## 外部能力测试

文本模型、图片模型和 OpenViking 均通过端口提供测试适配器：

- 测试适配器返回固定成功、结构错误、超时、限流和永久失败结果。
- 同一组契约测试验证生产适配器和测试适配器的输入输出语义。
- 模型结构化输出必须经过 Zod 校验，修复重试达到上限后明确失败。
- OpenViking 开启时验证写入、检索、不可用和重建；关闭时验证 FTS5 完整接管。
- 外部服务故障不得破坏已经提交的业务事实和成功块。

自动化测试不调用真实收费模型，避免成本、速率和随机性。真实模型只进入手工验收。

## 组件测试

使用 Nuxt Test Utils 以用户可见行为为断言，重点覆盖：

- 首次管理员初始化与登录错误。
- 人物来源模式切换后字段要求正确。
- 证据和推断标识清楚可见。
- 图片能力关闭时图片选项禁用且原因可见。
- 规格块使用按钮调整顺序并重新校验依赖。
- 运行状态、部分成功、失败和重试操作正确显示。
- 高风险提案没有自动发布入口。
- 危险 HTML 和 Markdown 不被执行。

不要对 Nuxt UI 内部 DOM 结构或样式类做脆弱快照断言。

## 端到端主流程

Playwright 使用隔离 SQLite 数据目录、本地协议替身和真实生产 Nitro 服务，自动覆盖以下最高价值闭环：

1. 首次启动设置管理员，退出后重新登录。
2. 创建原创人物，保存候选版本并发布。
3. 创建文本生成运行，确认规格，完成生成并导出三种格式。

反馈评测发布回滚、备份恢复、OpenViking 能力组合和异常退出恢复依赖真实数据库、文件或进程边界，继续由 Vitest 集成测试和生产 HTTP/CLI 验收覆盖，不在浏览器层重复构造同一事实。发现页面编排回归风险时，再增加对应 Playwright 场景。

附加降级路径：

- OpenViking 关闭时，通过 FTS5 完成人物生成。
- OpenViking 开启但不可用时，当前运行明确失败；用户关闭该能力后，后续运行可改用 FTS5。
- 图片模型未配置时，完成纯文本生成和导出。
- 进程在任务执行中重启后，过期租约能恢复且不会重复写入成功结果。

## 人物行为评测

每个人物可以维护评测用例，至少包含输入场景、期望行为、禁止行为、必须依据的事实和判定方式。

评测由三类检查组成：

1. 硬规则：Schema、禁用项、必需事实、证据引用和格式要求。
2. 可重复规则：关键词、长度、枚举选择、结构和确定性差异。
3. 模型辅助评分：风格、一致性、兴趣倾向等难以完全规则化的维度。

模型评分只作为证据之一。高风险人物变更即使评分通过，也必须人工确认。评测运行保存人物版本、用例版本、模型配置、输入、输出和判定快照。

## 手工真实模型验收

发布 MVP 前，使用实际配置至少验证：

- 原创人物在资料为空时能表达稳定风格，同时承认未知事实。
- 资料型人物能引用正确证据，不把 AI 推断描述为原著事实。
- 混合人物遇到冲突时遵循证据优先级。
- 同一人物完成兴趣判断和指定格式图文生成。
- 用户修改 `DocumentSpec` 后，执行结果遵循确认版本。
- 图片生成失败时保留文本块并呈现部分成功。
- 反馈不会直接污染已发布版本，高风险字段必须等待确认。

由于模型输出存在随机性，手工验收记录输入、模型、参数和结果，不要求逐字一致。

## MVP 验收矩阵

| 能力 | 成功条件 |
|---|---|
| 登录 | 未登录无法访问业务页和接口；会话重启策略符合配置 |
| 人物 | 三种来源模式可创建；资料可选；版本不可变且可回滚 |
| 世界 | 可选关联人物；版本变化不静默改写既有运行 |
| 资料 | 粘贴文本、TXT、Markdown 可导入、检索和删除分析 |
| 兴趣 | 返回结构化分值、结论、理由、证据和不确定性 |
| 规格 | AI 生成后必须由用户确认；依赖和能力校验有效 |
| 文本块 | 可生成、重试、锁定并选择历史尝试 |
| 图片块 | 有模型时生成本地资源；无模型时正确禁用 |
| 导出 | HTML、Markdown、Txt 内容同源，资源路径和哈希正确 |
| 反馈 | 分类可追溯；提案有差异、依据、风险和状态 |
| 评测 | 用例可复现；低风险自动发布受门禁约束 |
| OpenViking | 启用和关闭两条路径均可用，SQLite 始终保存业务事实 |
| 任务 | 租约、重试、取消、部分成功和重启恢复正确 |
| 备份恢复 | 备份一致、清单完整、恢复前可验证、失败不覆盖现有数据 |
| 删除 | 先展示影响范围，确认后完整删除且不越界 |
| 安全 | 密钥不入库、不入备份、不入日志；不可信内容不能执行 |

## 完成判定

- 自动化测试在干净环境通过。
- 数据库可从零迁移，备份可验证，任务可从重启恢复。
- Playwright 核心闭环通过；其余端到端主流程与降级路径有可复现的集成或生产验收证据。
- 手工真实模型验收有记录，没有未处理的阻断问题。
- 产品范围内每项验收条件都有对应证据；范围外事项不阻止 MVP 完成。
