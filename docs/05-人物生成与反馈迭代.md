# 人物生成与反馈迭代

## 固定主流程

AI 可以在单个步骤内规划和有限自我修正，但不能改变以下主流程：

```text
人物版本与任务输入
  → 能力和硬约束校验
  → 参数、模型与提示快照
  → 证据检索与快照
  → 结构化规划
  → Schema 校验与有限修正
  → 用户确认或后台执行
  → 结果校验与记录
```

每个 AI 步骤最多执行两次自动尝试。第二次仍不符合 Schema 或硬约束时失败，不进入开放式 Agent 循环。

## 原创人物创建

1. 用户输入自然语言人设，可选关联世界设定。
2. 应用服务调用文本模型，把描述转换为结构化人物快照。
3. 输出必须区分明确用户设定、模型推断和未知字段。
4. 用户逐区查看和编辑，确认后创建初始候选人物版本。
5. 初始候选版本通过基本硬校验后由用户发布。

纯原创人物没有资料时仍可运行；证据字段指向用户输入快照，不伪造外部来源。

## 资料型与混合型人物

资料处理步骤：

1. 校验 TXT/Markdown 文件类型、大小和 UTF-8 文本。
2. 保存原始正文与 SHA-256。
3. 按标题和长度切分为稳定文本块。
4. 建立 FTS5 索引。
5. 按用户选择关联人物或世界，并标记资料角色。
6. OpenViking 开启时异步同步相同内容。

资料更新产生新的内容哈希并重建文本块。新资料不会直接修改已发布人物版本。

## 提示与证据层级

模型上下文按以下顺序构建：

1. 系统安全、输出 Schema 和格式硬约束。
2. 当前人物版本中已发布的用户设定与人物约束。
3. 本次场景上下文和明确任务要求。
4. 按优先级检索的资料证据与表达样例。
5. 普通创作灵感。

检索资料属于不可信数据。其内容只能作为证据，不得覆盖系统指令、调用工具、修改 Schema 或要求泄露其他上下文。

## 上下文提供器

应用层只依赖以下业务能力：

```text
同步资料
检索证据
检查健康状态
```

### 本地提供器

- 使用人物和世界关联过滤候选资料。
- 使用 SQLite FTS5 检索关键词。
- 结合资料优先级、块顺序和简单匹配分数排序。
- 适合少量资料，不声称具备语义等价能力。

### OpenViking 提供器

- 每项资料同步为稳定的 `viking://resources/ren-yang/{sourceId}.md` Resource。
- 资料保存请求只提交 SQLite 并创建持久同步任务，不在请求事务中联网。
- 检索只把当前人物和世界关联资料的 URI 列表传给原生 `find`。
- 当前只同步资料正文；人物版本、候选记忆和已发布反馈均不写入 OpenViking Memory。
- 返回结果转换为统一证据对象，不把 OpenViking 原始类型传给应用服务。
- 运行保存实际证据内容，即使远端索引随后变化仍可审计。

关闭能力不会删除同步记录或远端资源；重新启用后可删除人样专属远端根并从 SQLite 全量重建。OpenViking 故障时不在同一运行中静默切换本地提供器，因为这会改变可复现条件。

## 兴趣判断

输入内容至少提取：主题、立场、形式、长度、情绪、实用性、新颖度和可信度。输出 Schema 包含：

| 字段 | 说明 |
|---|---|
| `probability` | 0～1 兴趣概率 |
| `confidence` | 0～1 结论置信度 |
| `decision` | `interested`、`not_interested`、`insufficient_information` |
| `factors` | 主题、价值、实用、新颖、形式等分项 |
| `supportingEvidenceIds` | 支持证据快照标识 |
| `opposingEvidenceIds` | 反对证据快照标识 |
| `unknowns` | 缺失信息和不能确认的推断 |
| `reasoningSummary` | 面向用户的简短解释，不保存隐藏推理 |

概率是模型输出，MVP 不宣称统计校准。积累真实偏好标签后再评估校准模型。

## 图文生成编排

1. 根据人物版本、场景和任务要求生成文档规格。
2. Schema 校验失败时给模型一次结构化修正机会。
3. 用户编辑并确认文档规格。
4. 按依赖顺序执行文字块和图片块。
5. 每次块调用独立保存输入快照与结果。
6. 硬校验失败可以创建第二次自动尝试。
7. 成功块可锁定；整文重试不得替换锁定块。
8. 选择每个块的成功尝试后渲染最终文档。

图片只根据内容简报和文本视觉风格生成，不要求人物外观跨图片一致。

## 场景上下文

场景可以包含年龄阶段、地点、当前目标、情绪和事件。应用必须：

- 把场景保存在运行快照中。
- 明确告诉模型场景只影响当前运行。
- 阻止场景字段直接写入人物版本。
- 允许反馈学习模块从重复行为中提出候选记忆。

## 反馈分类

反馈提交后，AI 返回分类建议和置信度，用户确认后执行：

| 目标 | 处理 |
|---|---|
| 当前产物 | 定位块并创建新尝试，不改人物 |
| 运行参数 | 展示本次覆盖或参数方案建议，不改人物 |
| 长期人物 | 创建带证据的修订提案 |
| 资料事实 | 标记资料冲突或修订建议，不自动改当前版本 |

直接编辑后的文字、A/B 选择及原因必须保留，便于后续形成偏好对；MVP 不启动训练。

## 修订提案

修订提案至少包含：

- 基础人物版本。
- 目标字段和前后值。
- 变化理由。
- 支持与反对证据。
- 置信度和适用场景。
- 风险等级。
- 受影响的评测类别。

冲突或证据不足时允许生成提案，但禁止自动发布。

## 混合发布规则

| 变化 | 风险 | 评测通过后行为 |
|---|---|---|
| 新增表达样例 | 低 | 可自动发布 |
| 小幅表达偏好调整 | 低 | 可自动发布 |
| 小幅兴趣权重调整 | 低 | 可自动发布 |
| 身份事实和关系 | 高 | 必须人工确认 |
| 价值观和核心动机 | 高 | 必须人工确认 |
| 禁用项和安全约束 | 最高 | 必须人工确认 |
| 大幅权重或跨分区变化 | 高 | 必须人工确认 |
| 与原著事实冲突 | 高 | 必须人工确认并标记主动覆盖 |

自动发布仍需创建不可变候选版本、执行评测并保存发布原因。

## 评测门禁

每个人物维护约 5～10 个核心回归用例。门禁按比例执行：

1. 格式、必需字段、禁用项和安全规则使用确定性检查。
2. 兴趣用例比较目标结论、分项和证据是否符合预期。
3. 主观语言风格使用一个固定评测模型和固定 Schema。
4. 比较候选版本与基础版本，目标用例应改善，保留用例不得出现明显退化。
5. 高风险变化无论分数如何都等待人工确认。

评测模型、参数、提示版本和逐用例结果必须保存。评测模型输出只是证据，不是无条件发布命令。

## 候选记忆

一次场景行为不能形成稳定人格。满足以下任一条件时可以提出候选记忆：

- 用户明确标记为长期变化。
- 多次运行出现一致行为并有多条独立证据。
- 用户多次对同一维度给出一致反馈。

候选记忆进入人物版本前必须经过修订提案和发布门禁。
