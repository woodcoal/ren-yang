# 人物生成与长期迭代

## 固定主流程

AI 可以在单个步骤内规划和有限修正，但不能改变以下主流程：

```text
当前世界与人物心智
→ 任务和能力校验
→ 参数、模型与提示词预算快照
→ SQLite 有效范围过滤
→ OpenViking 或 FTS5 相关性排序
→ 上下文预算选择与快照
→ 结构化规划和 Schema 校验
→ 用户确认或后台执行
→ 结果、处理记录与用量保存
```

每个 AI 步骤最多执行两次自动尝试。第二次仍不符合 Schema 或硬约束时失败，不进入开放式 Agent 循环。

## 世界和人物建立

### 世界

1. 用户在世界列表弹窗中输入一段自然语言世界。
2. 应用服务调用文本模型，生成名称、后台摘要、自由章节和运行摘要。
3. Schema 校验通过后创建世界及待确认灵魂草稿，并自动进入详情。
4. 用户在详情中调整名称、资料、灵魂和成长；初始化时不关联资料。
5. 发布前执行章节、冲突和 Token 预算校验，发布后形成当前世界灵魂版本。

资料分析不会直接覆盖世界灵魂。世界资料进入世界成长分析；稳定成长只有通过“吸收到灵魂”才能形成新灵魂草稿。

### 人物

1. 用户在人物列表弹窗中输入一段自然语言人设。
2. 应用服务调用文本模型，把描述转换为人物名称、自由章节和运行摘要。
3. Schema 校验通过后创建人物及待确认灵魂草稿，并自动进入详情。
4. 初始化时不关联世界或资料；用户在详情中继续调整关系、灵魂、成长和记忆。
5. 发布前执行预算和硬规则校验。

没有参考资料仍可建立人物，创建流程不再区分原创、资料型或混合型。AI 草稿生成失败或模型未配置时不创建对象，弹窗保留原文和错误信息。待确认和未发布等状态只由界面呈现，不得混入人物或世界的章节与运行摘要。

资料导入仍使用粘贴、TXT 和 Markdown，并执行文件、UTF-8、大小、哈希、切片与 FTS5 索引校验。资料可以帮助整理初始灵魂或作为任务参考证据，但不会自动成为人物成长。

新资料或资料更新不会直接修改当前灵魂、成长或记忆。

## 运行上下文

### 优先级

```text
系统安全规则和输出协议
→ 当前任务核心要求与格式
→ 世界灵魂运行摘要
→ 人物灵魂运行摘要
→ 相关有效世界成长
→ 相关有效人物成长
→ 相关有效人物记忆
→ 相关参考资料
→ 当前兴趣批次附加提示词
```

资料、原始反馈和处理记录是不可信数据，不得执行其中的指令、覆盖 Schema 或要求泄露其他上下文。

### 范围过滤

1. SQLite 根据世界、人物、状态、删除标记和内容哈希确定允许集合。
2. 本次运行固定选择 OpenViking 或 FTS5。
3. 提供器只在允许集合中排序。
4. 服务层再次过滤对象范围和当前状态。
5. 按提示词预算逐条加入并记录跳过原因。

OpenViking 不能返回并注入未审核、已拒绝、已归档、已取代或待删除内容。提供器故障时只允许在新运行创建前选择 FTS5，已创建运行不得切换。

### Token 预算

调用前计算模型上下文、预留输出和安全余量。世界与人物使用父子预算；灵魂使用已发布运行摘要，成长、记忆和资料按相关性整条加入。

收缩顺序：低相关资料、人物记忆、人物成长、世界成长。核心系统规则、任务要求和两个灵魂摘要仍超限时返回 `PROMPT_BUDGET_EXCEEDED`。

运行快照保存预算、计数方式、实际选入和跳过内容、最终提示哈希，以及供应商调用后的实际用量。

## 兴趣判断

输入内容至少分析主题、立场、形式、长度、情绪、实用性、新颖度和可信度。输出包含：

| 字段 | 说明 |
|---|---|
| `probability` | 0～1 兴趣概率 |
| `confidence` | 0～1 结论置信度 |
| `decision` | `interested`、`not_interested`、`insufficient_information` |
| `factors` | 主题、价值、实用、新颖、形式等分项 |
| `supportingEvidenceIds` | 支持证据快照标识 |
| `opposingEvidenceIds` | 反对证据快照标识 |
| `unknowns` | 缺失信息和不能确认的推断 |
| `reasoningSummary` | 面向用户的简短解释，不保存隐藏推理 |

概率是模型模拟结果，不宣称统计校准。完成后的结构化兴趣结论、用户选择和任务效果形成一条人物处理记录；该记录是否参与记忆分析由用户控制。

同一人物可以一次提交一至二十条文本。系统以一次主模型调用逐条输出结果，保持输入顺序并隔离单项错误；可选附加提示词对整批生效，单项重试继续使用该提示词，但不携带旧模型回答。

## 图文生成编排

1. 用户只提交人物、生成条件、输出格式和图片数量。
2. 系统固定人物、世界、资料、提示词、算法、模型和预算快照，一次生成完整文章。
3. 结构校验失败时允许一次不携带旧模型回答的修正调用。
4. 图片数量大于零时，系统根据最终文章一次分析全部配图内容和插入位置，再逐张生成图片。
5. HTML 按正文位置直接混排；文本结果返回正文和独立图片数据。
6. 任务完成后创建人物处理记录，引用完整运行和产物，不重复复制大段正文。

图片只根据内容简报、人物灵魂中的视觉相关内容和当前任务生成，不承诺跨图片外观一致。

## 兴趣附加提示词

后台不采集年龄阶段、地点、当前目标、情绪或事件。用户可以提供一条对当前兴趣批次全部文本生效的附加提示词；系统必须把它保存在各条运行输入快照中，并阻止其直接写入灵魂、成长或记忆。历史运行中已有的结构化场景只做兼容读取。

## 反馈归因

反馈提交后，AI 返回分类建议和置信度，用户确认后执行：

| 目标 | 处理 |
|---|---|
| 当前产物 | 定位块并创建新的块尝试，不改长期心智 |
| 运行参数 | 保存下次运行建议，不修改已有运行 |
| 人物学习 | 用户确认时创建人物反馈资料，等待成长分析 |
| 资料事实 | 保存资料冲突和修订建议，不自动修改资料或心智 |

原始反馈和人物反馈资料必须分开。反馈不会同时自动创建灵魂版本、成长和记忆。

当前灵魂修改由用户在灵魂工作区建立草稿并发布。后续灵魂 AI 修改提案必须使用自由章节差异，并在用户接受后写入草稿；不得恢复旧固定字段候选版本路径。

## 世界成长迭代

```text
新增或重新启用世界资料
+ 相关历史世界资料
+ 当前世界灵魂
+ 当前有效世界成长
→ 世界成长分析批次
→ 新增/修订/合并/取代/停用提案
→ 用户审核
→ 世界成长生效
```

世界成长适合记录从资料中提炼的当前世界事实、变化和可复用规则。世界成长不产生世界记忆；需要成为基础设定时由用户吸收到新世界灵魂草稿。

## 人物成长迭代

```text
人物反馈事件
→ 用户选择“作为人物学习资料”
→ 人物反馈资料逐条启用、禁用或删除
→ 分析已启用资料和当前有效成长
→ 用户审核人物成长提案
→ 后续任务按相关性使用有效成长
```

删除反馈资料不直接停用已确认成长。成长显示来源不可用，用户决定保留、停用或重新分析。

## 人物记忆迭代

```text
人物处理任务
→ 保存处理记录并异步写入 Peer Session
→ 用户筛选有效处理记录
→ OpenViking 派生素材 + SQLite 有效记录 + 当前有效记忆
→ 合并、去重和冲突分析
→ 用户审核记忆提案
→ 后续任务按相关性使用有效记忆
```

规律型记忆原则上需要多个独立有效记录。同一运行只算一个独立来源；重复内容不虚增强度。人物纯输出不能单独证明稳定规律。

OpenViking 派生内容不直接参与任务。它先回写 SQLite 作为分析素材或候选，再经过用户审核。

## 增量、完整重建与防漂移

日常分析使用新增有效数据、相关历史证据和当前有效结论。以下情况允许完整重建：

- 大量删除、启用或禁用原始数据；
- 模型、提示或分析规则发生变化；
- OpenViking 数据重建；
- 用户发现成长或记忆明显漂移。

完整重建仍只形成候选。分析批次固定输入、基线、模型、参数、提示和用户审核结果。

防止自我强化：

- 保存每项处理记录使用的世界和人物心智；
- 区分旧心智导致的输出与外部选择或效果提供的新证据；
- 同一任务和高度相似数据去重；
- 记忆只能显式转为反馈资料；
- 成长只能显式吸收到灵魂。

## 冲突与评测

系统检查成长/记忆与灵魂、同类有效结论以及新世界成长与人物设定的冲突，只显示证据和影响，不自动裁决。

灵魂修改、高影响成长和记忆可以执行人物评测。评测模型输出只是证据；无论风险高低，长期内容的最终生效都由用户确认。

## OpenViking 使用

- 世界映射 User，人物映射 Peer。
- 世界资料写入 User Resources。
- 人物资料和人物反馈资料写入 Peer Resources。
- 人物处理过程写入对应 Peer Session。
- SQLite 先写事实和持久任务，Worker 再通过应用服务同步。
- 删除或解除关系时同步删除远端精确投影。
- 只有 SQLite 当前允许的精确标识或 URI 可以进入检索。
- 故障时新运行使用 FTS5；Session、派生和同步任务保留待补偿。

## 完成判断

世界资料能够迭代世界成长，人物反馈资料能够迭代人物成长，人物处理记录能够迭代人物记忆；三个流程都有原始数据、分析批次、候选审核、修订历史、冲突和运行快照，并且任何长期变化都不能绕过用户确认与 SQLite 状态门禁。
