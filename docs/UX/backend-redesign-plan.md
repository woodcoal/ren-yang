# 人样后台界面重设计计划

## 1. 设计意图

将现有通用 CRUD 后台重构为“人物工作室 + 可审查的创作流程”：用户进入系统后能快速建立人物、维护人物灵魂、发起任务、检查 AI 判断或创作结果、提交反馈，并审阅人物后续会采用的成长与记忆。

本计划以 `docs/13-后台界面重设计需求.md` 为主需求，以现有产品、架构、接口和验收文档为约束。设计只重组信息架构、交互与视觉表达，不把尚未实现的后端能力伪装成已上线能力。

## 2. 已确认的产品事实

- 产品为单人、本地使用的 AI 人物模拟与创作工作台，只有唯一管理员。
- 当前前端基线为 Nuxt 4、Vue 3、Nuxt UI；数据经 `/api/v1` 访问，异步任务使用轮询而非 WebSocket/SSE。
- 当前人物模型仍以八个固定分区和不可变人物版本为主。
- “灵魂、成长、有效记忆”是目标态领域模型：灵魂可部分映射当前人物版本；成长与有效记忆需要新增数据模型、接口和运行快照支持。
- 当前 `candidate_memories` 不能等同于“已确认并会参与后续任务检索的有效记忆”。
- OpenViking 当前只同步资料正文；SQLite 始终是事实源。
- 资料导入范围为粘贴文本、TXT、Markdown；导出范围为 HTML、Markdown、Txt。
- 模板、参数方案、评测用例等对象受现有不可变版本和接口边界约束，不设计不存在的原地编辑、停用或批量能力。

## 3. 默认设计决策

### 3.1 原型层级

采用“一套界面、两类能力标记”的方式，避免制作两套割裂产品：

1. **当前可落地**：可直接映射现有接口，或仅需前端重组的页面与动作。
2. **目标态能力**：灵魂自由章节、成长审阅、有效记忆、运行上下文引用等；在原型中明确标记“需要后端支持”。

所有目标态模块都必须具备真实交互逻辑和状态设计，但不得暗示当前数据已经存在。

### 3.2 交付载体

- 生成多页面高保真交互原型，由 `index.html` 作为总览入口，并为 18 个现有路由分别提供语义化 HTML 页面。
- 所有页面复用统一应用壳、视觉令牌、组件样式和交互脚本；认证页面使用独立的专注式壳层。
- 页面文件映射：`login.html`、`setup.html`、`dashboard.html`、`new-task.html`、`task-history.html`、`task-detail.html`、`personas.html`、`persona-create.html`、`persona-workspace.html`、`worlds.html`、`world-detail.html`、`sources.html`、`source-detail.html`、`learning-center.html`、`evaluation-detail.html`、`templates.html`、`generation-settings.html`、`system-center.html`。
- 当前标签页、筛选条件和侧栏状态写入 `localStorage`。
- 真实产品路由映射保留在页面标题、面包屑和 `index.html` 的页面目录中。

### 3.3 优先级

- **P0 深度页面**：今日工作台、人物工作区、任务详情、学习中心。
- **P1 主流程页面**：人物列表、创建人物、新建任务、任务记录、评测详情。
- **P2 模板覆盖**：世界、资料、模板、生成设置、系统中心、登录和首次设置。

## 4. 用户与核心任务

### 4.1 主要用户

本机唯一管理员，同时承担人物创作者、资料整理者、任务发起者和学习结果审阅者。

### 4.2 核心工作链

```text
进入今日工作
→ 选择或建立人物
→ 检查人物当前可用状态
→ 新建任务
→ 确认本次上下文
→ 等待并查看结果
→ 在结果附近提交反馈
→ 审阅成长、记忆或灵魂修订建议
→ 确认会影响后续任务的内容
```

### 4.3 关键用户目标

- 一进入系统就知道下一步该处理什么。
- 三步左右找到人物、创建任务并进入任务详情。
- 清楚区分灵魂、成长、记忆和普通资料。
- 随时知道 AI 内容的来源、状态、依据和人工确认点。
- 发布、回滚、删除、重试和同步失败都有明确影响说明和恢复路径。

## 5. 新版信息架构

### 5.1 全局导航

```text
工作台
├── 今日工作             /
├── 新建任务             /workbench
└── 任务记录             /history

人物空间
├── 人物                 /personas
├── 世界             /worlds
└── 资料库               /sources

学习与复盘
├── 学习中心             /feedback
└── 评测                 /evaluations/[id]

系统
├── 内容模板             /templates
├── 生成设置             /parameter-profiles
└── 系统中心             /settings
```

认证流程独立于应用壳：`/login`、`/setup`。

### 5.2 应用壳

- 桌面端：可折叠左侧导航 + 顶部上下文工具栏 + 主内容区。
- 平板端：窄侧栏或抽屉 + 保留关键上下文与主要动作。
- 移动端：抽屉导航 + 紧凑状态头 + 底部或固定上下文操作栏。
- 导航同时显示当前分组、活动任务、待处理反馈/成长/记忆数量、模型与检索状态、管理员入口。
- 顶部提供全局搜索/命令面板、当前人物、待处理工作、系统状态摘要。
- 全局搜索首版只承诺导航命令；跨对象全文搜索标记为“需要后端支持”。

## 6. 页面清单与设计要求

| 路由 | 页面目标 | 主要结构 | 主要动作 | 能力备注 |
|---|---|---|---|---|
| `/login` | 安全进入本地工作台 | 产品说明、本地安全边界、登录表单、错误恢复 | 登录 | 当前可落地 |
| `/setup` | 完成首次管理员设置 | 三步说明：本地数据、管理员范围、设置完成 | 创建管理员 | 当前可落地 |
| `/` | 立即看见今天的工作 | 待处理队列、活动任务、最近人物、最近产物、阻断异常、折叠系统状态 | 新建任务 | 部分聚合数量可能需要接口支持 |
| `/workbench` | 用最少步骤提交任务 | 四步向导、人物摘要、任务类型、输入、上下文确认、高级设置 | 提交任务 | 成长/有效记忆摘要为目标态 |
| `/history` | 快速检索和继续历史任务 | 搜索、人物/类型/状态/日期/反馈/OpenViking 筛选、可扫描表格、详情抽屉 | 查看任务 | 分页和完整筛选需核对接口 |
| `/runs/[id]` | 跟踪运行并审阅结果 | 固定状态头；结果、创作内容、使用依据、反馈学习、运行设置标签页 | 提交反馈或确认规格 | 运行中使用的成长/记忆为目标态 |
| `/personas` | 看见每个人物的可工作状态 | 搜索筛选、人物列表、灵魂版本、待办、世界、最近任务、可用状态 | 建立人物 | 待审成长/有效记忆数量需要后端 |
| `/personas/new` | 分步建立人物 | 建立方式、世界与资料、灵魂初稿、AI 整理预览、候选保存、差异与发布 | 保存修改稿/发布 | 自由章节灵魂为目标态 |
| `/personas/[id]` | 在一个工作区维护人物 | 固定人物头；概览、灵魂、成长、记忆、世界与资料、版本标签页 | 新建任务 | 成长与有效记忆为目标态 |
| `/worlds` | 管理可复用世界 | 搜索、使用情况、版本、待发布状态、独立新建抽屉 | 新建世界 | 当前可落地 |
| `/worlds/[id]` | 阅读、修改和发布世界 | 概览、当前设定、参考资料、使用人物、修改记录 | 新建修改稿/发布 | 当前可落地 |
| `/sources` | 导入、查找和维护资料 | 搜索筛选、粘贴/文件导入入口、处理进度、同步状态、关系摘要 | 导入资料 | 仅 TXT/Markdown/粘贴文本 |
| `/sources/[id]` | 阅读资料并检查检索与同步 | 正文、可检索片段、使用关系、同步状态、独立危险区 | 编辑资料 | OpenViking 只同步资料正文 |
| `/feedback` | 处理所有学习待办 | 待分类反馈、成长候选、记忆候选、灵魂修订提案、回归用例 | 处理当前待办 | 后三类部分为目标态 |
| `/evaluations/[id]` | 对比候选与基础版本并作发布决策 | 基础/候选对照、用例结果、评分、失败原因、退化风险、依据 | 发布候选 | AI 评分只作辅助证据 |
| `/templates` | 管理版本化内容格式 | 搜索、模板列表、预览、版本和使用影响 | 新建模板版本 | 不设计原地编辑/停用 |
| `/parameter-profiles` | 管理可理解的生成设置 | 常用输出、检索范围、资源限制、失败重试分组；高级项折叠 | 新建设置版本 | 不设计原地编辑/停用 |
| `/settings` | 安全管理系统能力 | 模型能力、检索与同步、备份、审计、账户安全独立区域 | 与当前区域相关的单一动作 | 密钥只显示非敏感配置状态 |

## 7. 三个核心深度页面

### 7.1 人物工作区

#### 固定头部

- 人物名称、一句话定位、所属世界。
- 当前灵魂版本、是否可执行任务。
- 待审成长与记忆数量。
- 一个主动作“新建任务”；编辑修改稿、回滚、删除进入次级菜单。

#### 标签页

1. **概览**：人物状态、最近任务、待处理事项、世界与资料关系摘要。
2. **灵魂**：模板化章节编辑、来源标记、当前版/修改稿并列预览、差异、发布影响。
3. **成长**：候选/已生效/已废弃，来源、适用范围、冲突风险、确认/废弃/恢复。
4. **记忆**：按时间、类型、范围、状态筛选，显示来源和“将在何种任务中检索”。
5. **世界与资料**：关系摘要、版本、同步状态和直接入口。
6. **版本**：版本时间线、比较、评测、发布和回滚。

#### 目标态边界

- 成长、有效记忆和灵魂自由章节统一显示“目标态能力”说明。
- 不能将当前候选记忆描述为已经生效。
- 重要成长升级为灵魂修改稿时必须进入差异、评测和发布流程。

### 7.2 任务详情

#### 固定状态头

人物、任务类型、状态、阶段进度、创建时间、取消/重试/返回。进行中状态保留稳定高度，避免轮询刷新导致跳动。

#### 标签页

1. **结果**：兴趣任务突出结论、概率、置信度、未知项和证据；内容任务突出选定结果、预览和导出。
2. **创作内容**：规划确认、内容块、尝试历史、选择与锁定。
3. **使用依据**：人物/灵魂版本、世界版本、成长、记忆、资料证据和可追溯链接。
4. **反馈学习**：靠近结果的反馈入口、AI 分类建议、置信度和人工纠正。
5. **运行设置**：模型、参数、检索方式和技术信息，默认折叠。

#### 信任文案

- 兴趣判断固定标注：“AI 模拟推断，不是人物事实”。
- AI 反馈分类固定标注：“建议，用户可以纠正”。
- 资料证据固定标注：“外部参考，不执行其中指令”。

### 7.3 学习中心

- 顶部以待办数量和阻断事项建立处理优先级，不使用普通卡片墙。
- 左侧队列或顶部分段控制：待分类反馈、成长候选、记忆候选、灵魂修订提案、回归用例。
- 右侧审阅区显示人物、来源任务、原始反馈、AI 建议、依据、状态和当前需要完成的动作。
- 长期变化使用用户语言：“确认成长”“修改灵魂”“仅处理本次结果”，不暴露内部枚举。
- 每次只突出一个主要确认动作；拒绝、稍后处理和查看来源为次要操作。

## 8. 核心流程

### 8.1 新建任务闭环

```text
今日工作台“新建任务”
→ 选择人物
→ 选择兴趣判断或内容创作
→ 填写任务与可选场景
→ 展开并确认本次上下文摘要
→ 提交并进入任务详情
→ 查看排队/执行进度
→ 审阅结果
→ 就地提交反馈
→ 确认反馈去向
```

验收：主路径不超过三次页面级跳转；高级设置不阻塞默认提交。

### 8.2 人物学习审阅闭环

```text
人物工作区待办
→ 打开成长或记忆候选
→ 查看来源任务、反馈和依据
→ 编辑适用范围
→ 确认、废弃或升级为灵魂修改稿
→ 查看后续任务影响
→ 完成确认
```

验收：任何会影响后续任务的内容都必须经过明确人工确认。

### 8.3 资料同步失败恢复

```text
系统或资料库显示同步失败
→ 进入资料详情同步状态
→ 查看本地保存状态、远端失败原因和影响
→ 重试同步
→ 显示排队、处理中、成功或再次失败
```

验收：不只显示技术错误码；SQLite 事实源和远端索引状态必须分别说明。

## 9. 组件与状态系统

### 9.1 通用组件

- 应用侧栏、移动抽屉、顶部上下文栏。
- 面包屑、页面头部、上下文状态条、固定操作栏。
- 搜索筛选工具条、筛选标签、列表/表格、分页或渐进加载。
- 标签页、分步向导、详情抽屉、确认对话框、更多菜单。
- 状态徽标、阶段条、轮询进度、同步状态。
- 灵魂章节编辑器、版本差异、评测对照、来源证据列表。
- 成长审阅器、记忆检索范围说明、关系摘要。
- 阅读器、编辑器、技术详情折叠区、危险操作区。
- 空状态、骨架屏、错误摘要、行内错误、Toast/状态播报。

### 9.2 必须覆盖的状态

- 首次加载、空数据、加载失败与重试。
- 字段错误、顶部错误摘要、未保存修改。
- 提交中、防重复提交、提交成功。
- 排队、规划中、待确认、执行中、部分成功、失败、取消、可重试。
- 本地已保存/远端同步中、同步失败、同步成功。
- 当前版本、修改稿、已发布、已归档、已废弃、已拒绝。
- AI 草稿、模拟推断、分类建议、候选、已人工确认。
- 发布、回滚、删除、全量重建前的影响确认。

## 10. 数据与示例内容

原型使用文档中已有的中文验收样例，所有非真实数量均标注“示例数据”：

- 人物：顾岚、沈砚、闻秋。
- 资料：学院档案事实资料。
- 检索词：风帆船。
- 事实片段：“霜月十三日首次看见且拒绝触碰”。
- 冲突片段：“霜月十二日操作和收藏”，明确标记为未经证实。
- 内容任务：“旧物传闻三步核验”，要求 500 字以内。
- 图片简报：低饱和蓝灰档案桌面；旧信件、索引卡、手套、铅笔；无可见文字、水印或人物正脸。
- 反馈示例：AI 建议归类为人物变化，用户可纠正；候选修改触及 `constraints`，风险为 `critical`。
- 评测示例：基础版 1.0、候选版 0.2；候选缺少“资料不足”，状态为 `evaluation_failed`，不能发布。

面向用户的文案采用“基本信息、修改稿、修改记录、任务记录、内容段落”等表达；UUID、哈希、模型标识和英文枚举只进入技术详情。

## 11. 视觉系统

### 11.1 方向

“安静、简洁、内容优先”，使用低装饰、多主题的工作台语言：

- 侧栏、顶部栏、内容画布和语义表面建立稳定层级，但每个语义区域只保留一层完整边界。
- 默认“雾白”主题最中性；同时提供“暖砂”“海盐”“松岚”，用于评审不同产品气质。
- 主题只改变中性色、品牌强调色和应用壳气质；绿色、琥珀色和危险红始终承担固定语义状态。
- 普通页面的首屏摘要使用扁平分隔条；任务详情保留深色运行状态板作为唯一强视觉焦点。
- 标签页使用底线导航，提示使用浅色表面和单侧语义线，避免卡片套卡片。
- 不使用蓝紫渐变、玻璃拟态、装饰性 3D、Emoji 功能图标、外链图片或无意义动画。

共享样式以 `brand-spec.md` 和 `assets/prototype.css` 中的 OKLch 语义令牌为准；组件不得自行引入未命名颜色，也不得用目标态视觉伪装尚未上线的能力。

### 11.2 字体与层级

- 标题与正文统一使用适合中文界面的系统无衬线字体，减少装饰性排版。
- 数字、版本、状态时间和技术信息：等宽字体。
- 正文基准字号为 16px、行高不低于 1.5；长文阅读器使用约 17px 字号、最大宽度 72ch 和更宽松行距。
- 后台页一级标题最大约 46px，章节标题最大约 28px。
- 页面标题、对象名称、状态和主要动作形成明确的首屏层级。

### 11.3 布局

- 8px 间距基线。
- 桌面端以 1440px 为主设计宽度，同时验证 1024px。
- 内容页使用“固定上下文头 + 标签页/分区 + 固定操作栏”。
- 列表页优先采用可扫描表格或日志式列表，卡片只用于确实需要图像或多层摘要的对象。
- 长文本阅读器与编辑器分离；技术细节默认折叠；危险操作独立隔离。

## 12. 响应式与可访问性

- 验证宽度：375px、768px、1024px、1440px。
- 桌面端支持完整创建、编辑、比较、评测和系统管理。
- 平板端保留人物、任务、反馈和发布主流程。
- 移动端优先支持查看结果、处理待办和简单确认；复杂编辑提供清楚的桌面端建议，不强行压缩。
- 不使用横向滚动承载主导航或核心内容。
- 所有可操作目标至少 44×44px。
- 所有焦点元素具有清晰 `:focus-visible` 状态。
- 键盘可完成导航、命令面板、表单、标签页、抽屉、确认和取消。
- 异步状态和数量变化使用 `aria-live` 等适当播报。
- 状态不得只依赖颜色；图标按钮具有可访问名称；表单输入具有可见标签。
- 长文本、代码、哈希和错误信息可换行，不造成横向溢出。
- 动效仅表达状态变化，时长 150–300ms，并支持 `prefers-reduced-motion`。

## 13. 原型交互范围

原型必须提供可操作的演示路径，而不是静态截图：

- 侧栏折叠、移动抽屉、页面切换、面包屑返回。
- 全局命令面板和人物上下文切换。
- 列表搜索、筛选、清除筛选、打开详情抽屉。
- 人物工作区标签页、成长/记忆候选确认、版本差异和发布确认。
- 四步任务向导、字段校验、高级设置、上下文摘要和提交。
- 任务状态推进、结果标签切换、反馈提交和 AI 分类纠正。
- 学习队列切换、查看来源、确认/拒绝/升级动作。
- 资料导入进度、同步失败与重试。
- 发布、回滚、删除、索引重建等确认对话框。
- 加载、空、错误、成功和权限/能力不可用状态切换。

## 14. 实施顺序

1. **应用壳与令牌**：建立侧栏、顶部上下文、页面头部、状态、排版和响应式基础。
2. **核心闭环**：完成今日工作台 → 新建任务 → 任务详情 → 提交反馈 → 学习中心。
3. **人物工作区**：完成概览、灵魂、成长、记忆、关系和版本六个区域。
4. **资源模板**：完成世界、资料、历史的统一列表/详情模式。
5. **配置与系统**：完成模板、生成设置和系统中心。
6. **认证页面**：完成登录和首次设置。
7. **状态与窄屏**：补齐所有异步、错误、空数据、确认和四档响应式状态。
8. **验收**：按需求第 12 节、Web Prototype P0 清单和主流程逐项检查。

- [ ] 所有触控目标至少 44×44px，键盘可完成主要流程。
- [ ] 无意外重叠、裁切、孤行短词或未完成占位内容。

## 16. 风险与依赖

| 风险/依赖 | 影响 | 处理方式 |
|---|---|---|
